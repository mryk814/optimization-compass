# 教材記事の書き方（Teaching article playbook）

この文書は、formulation記事とmethod記事を「読者が手法や定式化を理解できる記事」にするための書き方です。
Claude、Codex、ChatGPTなど、どのAIや人が書く場合も同じ基準を使います。

見本は [`content/concepts/linear-least-squares.md`](../content/concepts/linear-least-squares.md) です。オーナーのレビューを何度も経て、「一つの記事にこれだけ書いてあればよい」と判断された水準です。
基準にするのは、オーナーが実際の画面で確認した版です。2026-10-03の版は、主図を30秒でつかむへ移し、静止図の幅を抑え、パネル名で図を呼ぶように直したものです。
method記事の見本は [`content/methods/adam.md`](../content/methods/adam.md) と [`content/methods/bayesian-optimization.md`](../content/methods/bayesian-optimization.md) です。

2026-10-03に、線形最小二乗だけを参考にして、次の5本を見本の候補として書き直しました。オーナーのレビューを経て、見本として確定するか直すかを決めます。見せ方がそれぞれ違うので、手法に応じた図の選び方の例として使えます。

| 記事 | 中心の見せ方 |
|---|---|
| [非線形最小二乗](../content/concepts/nonlinear-least-squares.md) | データの平面とパラメータの地形をつなぐ。地形の立体表示と、その場で作るお椀（Gauss–Newtonの一歩） |
| [Newton法](../content/methods/newton-method.md) | 当てた放物線の頂点へ跳ぶ様子と、正しい桁数が倍々に増える棒グラフ |
| [CMA-ES](../content/methods/cma-es.md) | 分布の楕円が谷の形を覚える再生と、大きさをそろえた楕円と谷の形の比較 |
| [非線形内点法](../content/methods/interior-point-nlp.md) | 障壁で縁が壁になる立体と、μを下げて中心パスをたどる様子 |
| [多目的最適化](../content/concepts/multiobjective-optimization.md) | 設計の空間と目的の空間をつなぎ、重み付き和が凹んだ前線の途中に届かないことを操作で見つける |

規則の役割分担は次のとおりです。この文書は「どう教えるか」を受け持ち、ほかの規則を置き換えません。

| 何を決めるか | 正の文書 |
|---|---|
| frontmatter、許可されるMarkdown、検証 | [`docs/content-authoring.md`](content-authoring.md) |
| 節の型（見出しの名前と順番） | `src/optimization_compass/content_skeletons.py`、[`docs/formulation-atlas.md`](formulation-atlas.md) |
| 文体と表記 | [`docs/article-style.md`](article-style.md) |
| 図の色と描き方 | [`docs/content-visual-language.md`](content-visual-language.md)、[`docs/explorables.md`](explorables.md) |
| 操作 → 変化 → 疑問 → 式の流れと、画面での検収基準 | [`docs/article-experience-pattern.md`](article-experience-pattern.md) |

リポジトリを読めないAI（ChatGPTなど）には、この文書を圧縮した [`docs/prompts/teaching-article.md`](prompts/teaching-article.md) を渡します。

## 1. 記事を読み終えた読者ができること

- **formulation記事**: 自分の課題がこの定式化かどうかを判断できます。小さな例を手で解けます。合わないときにどの記事へ進むかが分かります。
- **method記事**: 1回の反復で何が起きるかを、小さな例の数値で説明できます。コードを動かし、診断値から「続ける・止める・切り替える」を判断できます。

記事の長さはこの二つの結果で判断します。文字数や節の数は基準にしません。線形最小二乗の記事は、frontmatterを含めて約250行です。この量があっても、読者が上の判断に使わない段落があれば削ります。

## 2. 書く前に作るブリーフ

本文を書く前に、次のブリーフを埋めます。埋まらない項目があるうちは、本文を書き始めません。
PRの説明に貼ると、レビューする人が意図を確認できます。

```yaml
reader_question: 読者がこの記事を開くときの問い（例：ばらつく測定値から、上がる速さを一つの数で言いたい）
scene: 30秒でつかむで使う身近な場面（例：1時間おきの温度計の読み 1, 2, 2, 4）
running_example:        # 記事の最後まで使い続ける一つの小さな例
  data: 手で計算できる大きさ（2変数、4点、3反復など）
  answer: スクリプトで計算した答え（例：x = (0.9, 0.9)、二乗和 0.70）
  checkable_facts: 読者が検算できる中間量（例：Σr = 0、Σ t r = 0）
baseline: 同じ例で並べる比較相手（例：正規方程式とQR、同じηの勾配降下法、一様乱数）
misconceptions:         # 読者が実際にしそうな誤りを、例の数値で反証できるもの
  - 残差の大きい点が外れ値だと決めつける → 4点目を8にすると3点目の残差が最大になる
troubles_to_neighbors:  # 「こうなったら → この記事」
  - パラメータが指数の中に入る → 非線形最小二乗
visuals:                # §5 の水準と、各図が答える一つの問い
  - level: explorable
    question: データの平面の直線と、パラメータの平面のお椀はどう対応するか
    placement: 30秒でつかむの箇条書きの後（標準形の式より前）
    first_action: 画面のUI名で書く最初の操作（例：「傾き x₂」のつまみを動かす）
sources: [S054, S055]   # 事実の根拠。Qiita・Zennは不可
```

## 3. 一つの題材で教え切る

線形最小二乗の記事は、温度の4点という一つの題材を最初から最後まで使います。これがこの書き方の中心です。

- **30秒でつかむ**で場面として出し、**標準形を読む**の記号表に「温度の例では」の列を設けます。**小さな例**で解き、**つまずきやすい点**ではその数値を変えて誤りを示します。**数値計算**では同じ4点をコードで解きます。
- 新しい概念を導入するたびに、同じ題材の中で値を示します。題材を途中で取り替えると、読者は毎回データを読み直すことになります。
- 別の例が必要になったら（条件数の実験など）、補足の節に分けて「この節だけ別の例を使う」と分かるようにします。
- 例の数値は必ずスクリプトで計算します。推測で書きません。丸めた値を書き、読者が手で確かめられる中間量を一緒に示します。

### 例の範囲を、進行報告なしで示す

- 例の中の小見出しには、題材名を付けます。例：「4点の例・二乗和を切片と傾きの式にする」。読者は、見出しを見るだけで例の中にいると分かります。
- 式や静止図がどのデータに対応するかを、データについての文で示します。例：「以下の式と補助図は、この初期の4点に対応します。」静止図のcaptionにも「初期の4点：」のように条件を入れます。
- 操作図でデータを変えられるときは、元のデータへ戻すUIの名前を書きます。例：「『点と直線を最初に戻す』でこの4点に戻せます。」
- 「この節では〜を追います」「ここまでで〜は終わりです」「次は〜を説明します」のような進行報告は書きません。結果をまとめ直したいときは、操作図で見直す方法として書きます。例：「操作図で初期の4点に最小の直線を選ぶと、$y=0.9+0.9t$ と二乗和 $0.70$ を見直せます。」

## 4. 節ごとの書き方

### 30秒でつかむ

1. 身近な場面を2〜3文で描きます。数学の言葉は使いません。
2. その場面での違和感や迷いを書きます。例：「点は一直線に並びません」「近くを掘るか、未知の土地を試すか」。
3. 解決の考え方を一文で書きます。
4. 三つの箇条書きで役割を整理します。
   - formulation記事：**決めるもの / 良くしたいもの / 守ること**。該当しない項目は「特になし」と書きます。
   - method記事：**見るもの / 動かすもの / 前進の判断**。
5. 主図（explorable）があれば、ここに置きます。図の直前に、最初の操作を画面のUI名で一つ指示し、結果がどこに出るかを書きます。例：「まず『傾き x₂』のつまみを動かし、直線と橙の四角がどう変わるか見てください。四角の面積の合計は、図の下の『残差の二乗和』に出ます。」
6. 図の後に「確かめてほしいこと」を番号付きで3つ書き、最後に、観察から生まれる疑問を一つ置きます。例：「どうして底では二つの合計が0になるのでしょうか。」この疑問に、標準形や小さな例の式が答えます。

### 標準形を読む / 一手の意味

- 式の前に、式が何をするかを日本語で一文で書きます。例：「次の式は『パラメータを選んで、予測と観測のずれを長さの二乗で測って最小にする』を表します。」
- 式の後に記号表を置きます。列は「記号」「意味」「例では」の3つです。「例では」の列が、抽象的な式と題材をつなぎます。
- 読者が誤解しやすい語には、独立した小見出しを付けて定義します。例：「『線形』はパラメータについての線形」。そこで、当てはまる例と当てはまらない例を一つずつ示します。
- 「なぜこの形か」を説明する小見出しを置きます。例：「なぜ二乗するのか」。理由が複数あれば「一つ目は計算の理由、二つ目は統計の理由」のように分けます。それぞれの理由が成り立つ条件も書きます。
- method記事では、1回の反復の手順を番号付きで書き、どの手順が高い計算か（本物の関数を呼ぶか）を明記します。式の各項は「この式は〜と読みます」と言い換えます。状況ごとの振る舞いは表にまとめます（Adamの「同じ向きが続く / 符号が交互に変わる / ノイズが大きい」の表がその例です）。

### 小さな例

- 設定（データ、初期点、パラメータ、乱数を使うかどうか）を最初にまとめて書きます。
- 手で追える量（2〜3反復、4点など）を表で示します。表の後に、表をどう読むかを段落か「段階ごとの箇条書き」で書きます（BOの「活用 → 探索 → 再び活用」がその例です）。
- 主図を30秒でつかむに置いた場合は、ここで主図の観察を式と数値で確かめます。「直線を表す点」の図のように、パネル名で主図を指します。
- 主図を小さな例に置く場合（method記事で反復を追う図など）は、図の後に「確かめてほしいこと」を番号付きで3つ書きます。各項目には、操作をUI名で、起きること、その理由を書きます。数値で確かめられるものは数値も書きます。
- 長い数値の計算（$0\cdot0.1+1\cdot0.2+\dots$ など）は、文中の式にせず、独立した数式ブロックにします。スマホ幅では、文中の長い式が行からはみ出します。
- 比較相手を同じ例で並べます。そのうえで、比較から言えないことを一文で書きます。例：「これは、Adamがこの谷を速く解けるという意味ではありません。」順位付けはしません。

### つまずきやすい点

- 各項目は、**太字で読者がしてしまう行動**、例の数値での反例、代わりにすることの順で書きます。
- 線形最小二乗の「残差の大きい点を外れ値だと決めつける」が見本です。4点目を8にすると、最も大きい残差は動かしていない3点目に出ます。一般論ではなく、記事の例で誤りが起きる様子を見せます。
- 記事の例と関係のない一般的な注意は入れません。

### 課題から定式化する（formulation記事）

課題の言葉から式までを、番号付きの4段で書きます。何を推定するか、観測をどう予測するか、どのずれを減らすか、係数に条件があるかの4つです。最後に、「この条件が揃ったとき、この定式化になる」とまとめます。

### 困りごとから関連する問題へ / 困りごとから関連する手法へ

- 最初の箇条書きは「読者が気づく症状 → リンク」の形にします。例：「パラメータが指数・分母・三角関数の中に入る → 非線形最小二乗」。
- 次に、関係ごとに短い段落を書きます。この定式化（手法）から見て、より一般か、特殊か、緩和か、形が似ているだけか、とその条件を書きます。
- method記事は、`次に読む` の代わりにこの節を使えます（`content_skeletons.py` の `METHOD_TROUBLE_ROUTE`）。

### 数値計算の方法を選ぶ / Python

- コードは小さな例と同じ題材を解きます。`print` の行末に、実際の出力をコメントで書きます。
- コードの直後に、出力の各値が何を意味するかを書きます。例：「`rank` が2であることは、底が一点に決まることを表します。」
- 実装上の落とし穴は、実験で見せます。線形最小二乗の「正規方程式を直接解くと精度が落ちる」表（次数ごとの条件数と誤差）がその見本です。「精度が落ちる」と言うだけで終わらせません。

## 5. 視覚表現

記事144本のうち、図が一枚もない記事は67本です（2026-10-03時点、`uv run python scripts/visual_coverage_report.py`）。
視覚表現の水準を上げることは、記事を増やすことと同じくらい優先します。

### 5.1 水準

| 水準 | 読者ができること | 手段 |
|---|---|---|
| L0 | 読むだけ | 文章、表 |
| L1 | 見る | 静止SVG（`![...]`）。generatorで作り、数値は計算から取る |
| L2 | 条件を動かして、その場の計算で確かめる | explorable（`::: explorable <id>`） |
| L3 | 解説付きで再生し、動きの順番を追う | explorableの `beats`（guided scene）、録画 |
| L4 | 高さや空間配置を回して読む | 3D曲面（linked 3D view）、計算済みの3D scene（`#/theater/physical/...`） |

目標は次のとおりです。

- **すべての記事**：L1以上にします。中心となる仕組み（お椀、一歩、境界、頂点）を描いた図を最低1枚置きます。
- **method記事の主要手法と、学習経路に載る記事**：L2にします。可能ならL3の解説も付けます。
- **L4**：高さや空間配置を読むこと自体が問いになっているときだけ使います。3Dは2D図の代わりではなく、2D図に追加するものです。

### 5.2 よい図の型

見本の3記事に共通する型です。

- **二つの空間をつなぐ**：線形最小二乗では、「観測点」のパネルにデータと直線、「直線を表す点」のパネルにパラメータの平面のお椀を置き、パラメータの平面の1点がデータの直線1本に対応します。片方を動かすと、もう片方も動きます。最適化では「解く空間」と「結果を見る空間」が分かれていることが多いので、この型はほとんどの手法に使えます。
- **量を面積や長さにする**：残差の二乗を正方形の面積で見せると、二乗和が文字どおり「面積の合計」になります。抽象的な量を、目で比べられる形にします。
- **比較相手を同じ図で切り替える**：Adamの図では同じηの勾配降下法、BOの図では一様乱数や β の値の違いを、同じ図の中で切り替えて見せます。
- **読者に先に選ばせる**：BOの図では、読者が自分で井戸を選んでから、BOの提案と比べます。読者自身の判断を手法の言葉（予測平均、不確実性）に対応させます。
- **式の数値が動く**：更新式に今の値を代入した形を図と一緒に表示します（`LiveMath`）。
- **範囲を断る**：captionで、図から読み取れないことを一文で書きます。例：「教材用の計算で、実データでの性能は示しません。」
- **パネルに見出しを付ける**：explorableの各パネルに `ex-panel-title` の見出し（「観測点」「谷と軌跡」「座標ごとの比」など）を付けます。本文は、この見出しで図の部分を指します。
- **操作名は日本語**：スライダーやボタンの名前は「学習率 η」「切片 x₁」のように日本語にし、記号を添えます。手法の正式名（Momentum、Expected Improvement）はそのままにします。
- **小さくなる対象は、大きさをそろえて別に描く**：CMA-ESの分布の楕円は世代とともに小さくなり、地形の図では見えなくなります。大きさをそろえた楕円を、目標の形（谷の形）と重ねて別のパネルに描くと、形の変化を最後まで追えます。
- **3Dは2Dと並べる**：立体（`Surface3D`）は、同じ点を描いた等高線と並べるか、切り替えられるようにします。高さの切り方（線形か log1p か、どこで切るか）をcaptionで開示し、定義されない場所は描かずに（`domain`）、床の辺に軸の名前を書きます。浅い谷の差を見せたいときは線形、深く細い谷を見せたいときはlog1pを選びます。
- **判定文は今の一歩について書く**：再生の途中では、最終的な結果ではなく、次の一歩で何が起きるかを書きます。図の外へ出た点は、端に「いまは x=5.4（図の外）」のように示し、消えたように見せません。
- **乱数を使う手法は、図と本文で同じ乱数を使う**：CMA-ESのように乱数を使う手法は、図（TypeScript）と本文の数値（Python）に同じ乱数生成器（mulberry32とBox–Muller）を実装し、同じ種で同じ点が出ることをテストで確かめます。ライブラリの実行例は乱数が違うので、数値が一致しないことを本文で断ります。

### 5.3 図の置き場所

- **主図は、標準形の詳しい式より先に置きます。** formulation記事も、読者の判断を題材にするmethod記事（BOの探索と活用）も、`30秒でつかむ` の中に置きます。既定値から一つの操作で始められるようにし、式は観察の後で読ませます。
- **反復の流れそのものを追う図**（Adamの一歩、座標降下法の一掃引など）は、`小さな例` の設定の直後に置いてもかまいません。その場合も、手計算の表より前に置き、「操作 → 疑問 → 計算で確かめる」の順にします。
- 静止図は補助です。隣にある一つの式や説明だけを支え、それを説明する段落の直後に置きます。図の前に「何を見るか」を一文で書き、captionに固定した条件（「初期の4点：」など）を入れます。
- 1記事のexplorableは原則1つです。静止図は「仕組み」「途中の計算」「失敗の様子」のように、答える問いが違えば複数置けます。線形最小二乗は、静止図3枚とexplorable 1つです。

### 5.4 実際の画面を基準にする

読者が読むのはMarkdownではなく、描画された画面です。本文を書くときも、検収するときも、画面を基準にします。

**ページの枠が本文の外に出すもの。** 本文で同じことを繰り返さず、本文では枠にできないことを書きます。

| ページ | 本文の前に出るもの | 本文の後に出るもの |
|---|---|---|
| formulation（`#/formulations/PAxxx`） | 学習経路の帯（「この項の問い」）、題名、atlasの一文、標準形と性質のカード（決めるもの・目的の形・制約の形・凸性・得られる保証）、目次 | 定式化のコンパス（一般化・特殊化・書き換え・比較と、その条件）、ソルバー・手法（折りたたみ）、根拠、経路の「次の問い」 |
| method（`#/methods/M_xxx`） | 題名、読み方（折りたたみ：目的・読む順番・前提・次に進む）、目次 | 学習経路の「次に見る」、Method Theater / Trace、比較、実装、根拠 |
| explorable | 「見る問い」、解説付き再生のボタン、操作、2つのパネル、数値の入った式、読み取りの表と一文、caption、「この図の前提と、読み取れないこと」（折りたたみ） | |

- 学習経路の帯の「この項の問い」に、30秒でつかむが答えるようにします。
- 標準形のカードが性質を一覧にしているので、30秒でつかむでは性質を列挙せず、場面と役割（決めるもの・良くしたいもの・守ること）に絞ります。
- コンパスが関係の一覧を出すので、本文の関連の節は「困りごと → リンク」と、例を使った理由に絞ります。

**画面の幅で変わること。**

- PCでは、本文が42rem以下、主図が最大60remで表示されます。スマホ（375px）では、主図の2つのパネルが縦に積まれ、記事の幅は約353pxになります。
- そのため、図を「左・右・上・下」で呼びません。パネルの見出しやUIの名前で呼びます。アイコンだけのボタンは、名前とアイコンを両方書きます。例：「最初から」（⏮）、「1つ進む」（▶）。
- 図の中のラベルは、図の端で切れないように置きます。点の右に置いたラベルが、スマホ幅で図の外へ出ることがあります。

**静止図の文字の大きさ。** 静止SVGは表示幅に合わせて拡大・縮小されるので、図の中の文字の大きさは描いたときの値と変わります。

| 種類 | 置き場所と作り方 | 表示幅 | 図の中の文字 |
|---|---|---|---|
| 補助図 | `site/public/figures/`。`scripts/generate_lesson_figures.py` で記事のデータから計算して作る | PC 440px（1:1）、スマホ 約353px | 本文 16px、目盛り 15px、見出し 17px で描く。PCで15〜17px、スマホで12px以上になる |
| 実行結果の図 | `site/public/media/`。`scripts/generate_article_figures.py` で正準の実行記録から作る | PC 最大672px、スマホ 約353px | スマホで12px以上、PCで18px以下になるように描く |

- 新しい補助図は、`generate_lesson_figures.py` に関数を足して作ります。幅440で描き、`width` 属性も440にします。手で書いたSVGや、推測で置いた座標は使いません。
- 表示したときの文字の大きさは `uv run python scripts/visual_coverage_report.py --figure-text` で確かめます。2026-10-03時点で、実行結果の図34枚はスマホで6〜8pxになっていて、作り直しが必要です。幅800の図をそのまま縮めず、幅440前後で描き、横に並べていたパネルは縦に積みます。
- 文中の長い式、数値の入った式、横に広い表は、320pxの記事幅ではみ出します。数式ブロックに移すか、表の内部だけをスクロールさせます。

**検収のときに見る画面。** PC 1280px、スマホ375px、記事領域320pxの3つを、実際のブラウザで変更の前後に見ます。リポジトリを読めるエージェントは開発サーバー（`.claude/launch.json` の `atlas-dev`、または `npm --prefix site run dev`）で記事を開いて確かめます。
文字だけで理解できることを完成条件にしません。本文・主図・補助図・操作が、画面の上でひとまとまりに見えるかを確かめます。

### 5.5 アニメーションと3D

- アニメーションは、時間順の因果（反復が進む、候補が受理される、分岐する）を追うときに使います。初回の表示は終了状態にします。条件を変えたときだけ最初から再生します。reduced motionでは自動再生しません（[`docs/explorables.md`](explorables.md)）。
- 解説付き再生（beats）は、「どの順に何を見るか」を読者が自力で見つけにくいときに付けます。各beatのcaptionが計算について述べる内容は、テストで固定します。
- 3D曲面は、谷の細さ、鞍点、尾根のように、高さの形そのものが論点のときに使います。投影法（正射影）、高さの正規化（`log1p`など）、切り取りを必ずcaptionで開示し、同じフレームの2D等高線を隣に置きます（[`docs/linked-3d-views.md`](linked-3d-views.md)）。
- 物理的な3D scene（構造、ロボットアーム、ドローン）は、計算済みの結果を再生するものです。条件を変えて解き直すexplorableとは区別して書きます（[`docs/physical-scenes.md`](physical-scenes.md)）。

### 5.6 図がない記事の第一候補

次の表は、図がない主な記事について、最初に作る図の候補です。どれも小さな厳密モデルで計算できます。作る前に、§2のブリーフで問いを一つに絞ります。

| 記事 | 図が答える問い | 型 | 水準 |
|---|---|---|---|
| Newton法 | 接する放物線の底へ跳ぶと、なぜ二次収束するのか | 1次元の関数と二次モデルを重ねる。初期点を動かすと発散も見える | L2 |
| L-BFGS | 曲率の推定が、反復ごとに谷の形にどう近づくか | 等高線の上に、推定した二次モデルの楕円を重ねる | L2 |
| 非線形共役勾配法 | 前の方向を混ぜると、ジグザグがどう減るか | 勾配降下法と同じ谷で軌跡を切り替える | L2 |
| 信頼領域法の系統 | 半径の中で二次モデルを最小化し、実際との比で半径をどう変えるか | 円とモデルの等高線。比 ρ を表示する | L2〜L3 |
| 近接勾配法・FISTA | 勾配の一歩の後のsoft-thresholdで、係数がちょうど0になる様子 | 1次元の近接写像と2次元の軌跡 | L2 |
| 劣勾配法 | 尖った点で、劣勾配の向きが選べることと、一歩の大きさの扱い | 折れ線の関数と劣勾配の扇 | L2 |
| 拡張Lagrangian・ADMM | 罰則と乗数の更新で、制約の違反がどう減るか | 制約の線と軌跡、違反量の推移 | L2〜L3 |
| 非線形内点法・主双対バリア法 | 障壁を弱めると、中心パスに沿って境界へ近づく様子 | 可行領域と中心パス、μ のスライダー | L2 |
| SQP | 各反復で解く二次計画が、元の制約とどう違うか | 制約の線形化と二次モデルを重ねる | L2 |
| Pattern Search・COBYLA | 関数値だけで、図形やパターンがどう動くか | 2次元の単体・格子の更新の再生 | L3 |
| CMA-ES | 分布の楕円が、谷の向きと細さに合わせてどう伸びるか | サンプル点と楕円の再生。3D曲面との連動も候補 | L3 |
| 遺伝的アルゴリズム・Differential Evolution | 集団が世代ごとにどう動き、多様性がどう失われるか | 多峰関数の上の集団の再生 | L3 |
| Basin Hopping・Multi-start | 局所最適化を繰り返すと、どの谷を見つけるか | 1次元多峰関数で、跳躍と局所降下を交互に再生する | L3 |
| 多目的最適化・NSGA-III・MOEA/D | パレート前線と、重みやreference pointで選ばれる点 | 目的空間の散布図と、決定空間の対応 | L2 |
| 混合整数線形計画・ナップサック | LP緩和の解が整数でないとき、分枝や切除平面がどう効くか | 2変数の格子点と可行多角形 | L2〜L3 |

## 6. 日本語

文体の規則は [`article-style.md`](article-style.md) に従います。見本の3記事で特に効いている書き方は次のとおりです。

- 式の後に「この式は『〜』と読みます」と書き、式を日本語の文に戻します。
- 結果の数値の後に「〜と読めます」と書き、題材の言葉に戻します。例：「温度は1時間に約0.9度ずつ上がっている、と読めます。」
- 理由は「〜からです」「そのため」「その結果」で文をつなぎ、段落として一つの話にします。
- 読者への問いかけは、読者が実際に判断する場面だけで使います。例：BOの「すでに油が出た井戸の近くを掘りますか」。
- 書き終えたら `yomiyasu` スキル（Claude）または同等の推敲で、AIらしい言い回しを取り除きます。事実、数値、主張の強さは変えません。

## 8. AIごとの分担

|---|---|---|

| 検証 | `check_article.py`、`validate content` | リポジトリ側のエージェントが行う |

リポジトリを読めないAIが書いた原稿も、取り込む前に必ず数値を実行して確かめ、`check_article.py` を通します。
