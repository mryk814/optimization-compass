# ADR 0018: 動き・3D・動画を「1つの場面から投影する」教材メディアにする

- Status: proposed
- Date: 2026-10-01
- Related: ADR 0016, ADR 0017, [`docs/explorables.md`](../explorables.md), [`docs/content-visual-language.md`](../content-visual-language.md), [`docs/derived-media.md`](../derived-media.md)

## Context

Explorable（`::: explorable <id>`）で、2D SVG の図を「動かして、その場で計算し直す」仕組みができました。次に欲しいのは次の3つです。

1. **3D**: 目的関数の曲面、3変数の実行可能多面体、鞍点など、高さや奥行きそのものが意味を持つ対象。
2. **アニメーション**: 1回の更新で何が動き、何が保たれるかを、順番に見せる演出（今は「再生バー付きの軌跡」だけ）。
3. **動画**: 操作できない場所（README、スライド、SNS、オフライン、ページ冒頭の予告）で同じ内容を届ける手段。

これらを場当たり的に足すと、同じ図の「操作版」「3D版」「動画版」が別々のコードと別々の数値を持ち、どれが正しいのか分からなくなります。既存の `derived-media` は Trace から決定的に PNG/GIF/WebM を作れますが、Explorable とは別系統です。

## Decision

### 1. 原則: 場面（scene）が1つ、投影が複数

教材メディアの単位は **scene** です。scene は次の3つだけでできています。

| 部品 | 中身 | 置き場所 |
|---|---|---|
| model | 描画に依存しない厳密な計算（状態 = f(パラメータ, 時刻)） | `site/src/features/explorable/math/*.ts`（単体テスト必須） |
| beats | 時間の台本。「何を、どの順に、何秒で見せ、何と言うか」 | `resources/explorables.json` の `beats`（新設） |
| view | model の状態を絵にする関数（2D SVG または 3D） | `site/src/features/explorable/*.tsx` |

操作できる図、自動で進む解説、3D表示、動画、静止画サムネイルは、すべて **同じ scene の投影** です。動画のために別の数値やアニメーションを作りません。

- 「時刻 t の絵」は model と view の純粋関数にします。`requestAnimationFrame` の実時間に依存させません。これにより、ブラウザでの再生・コマ送り・動画書き出しが同じフレームを指します。
- 手作業で作る動画（After Effects 等で手打ちしたキーフレーム）は採用しません。数値の正しさをテストできないからです。

### 2. メディアの梯子: 問いに答える一番低い段を選ぶ

```text
文章・表 → 静的SVG → 2D explorable → 演出付き 2D（beats） → 3D explorable → 動画（投影）
```

- 上の段ほど作る・保つコストが高く、読者の注意も奪います。「その段でしか答えられない問い」があるときだけ上がります。
- **3D に上がる条件**: 3つ目の軸が教材上の意味（目的値の高さ、第3の決定変数、時間）を持つこと。見栄えのための奥行きは不可。3D 図は必ず 2D の対応表示（等高線・射影）と並べ、相互にハイライトを連動させます。
- **動画は段ではなく出口**です。どの段の scene からでも書き出せますが、記事本文の主役にはしません（本文では操作できる図を優先し、動画は予告・共有・オフライン用）。

### 3. 動きの文法（motion grammar）

動きは装飾ではなく、意味の担い手です。

- **時間 = 反復**: 反復・更新の進行は等速（linear）で見せます。ease は「カメラ移動」「注目の切り替え」など意味を持たない遷移だけに使います。
- **一度に1つ動かす**: 1 beat で動く主役は1つ。点が動く間は式の数値が、式が変わる間は点が止まります。
- **残像で因果を残す**: 前の状態は薄く残し（ghost）、何が変わったかを差分で読めるようにします。
- **長さの予算**: 1 beat は 0.4〜2 秒、1 scene の自動再生は 20 秒以内。それ以上は章に分けます。
- **色**: `atlas-geometric-v1` に従います（橙=候補・更新、青緑=実行可能・観測、赤=違反のみ、紺=構造線）。3D の陰影は形の読み取りに必要な最小限で、光沢・反射・被写界深度は使いません。
- **文字を3D空間に置かない**: ラベル・数式は画面座標の HTML/MathML に重ね、回転しても読める向きと大きさを保ちます。

### 4. 3D の規則

- **高さの加工は開示**: 縦方向の拡大・圧縮・対数化をしたら、図中と「固定している条件」の両方に書きます。
- **カメラ**: 初期視点は scene が決めた「答えが見える角度」です。自由回転は許しますが、視点プリセットと「戻す」ボタンを必ず付け、キーボード（矢印で回転、+/- でズーム）でも操作できます。
- **2D との連動**: 曲面上の点・軌跡は、隣の等高線図でも同じ色・同じ番号で示します。
- **代替**: WebGL が使えない、または `prefers-reduced-motion` のときは、静止した既定視点の画像と 2D 図を出し、内容は欠けないようにします。
- **性能**: 中位のスマホで 60fps を目標、最低 30fps。メッシュ解像度は scene 側で上限を持ちます。

### 5. 動画の規則

- **作り方**: scene を「録画モード」（`?record=1&t=<秒>` で時刻を外から与える）で開き、Playwright でフレームを撮り、ffmpeg で WebM（VP9）と MP4（H.264）にします。beats の文言から WebVTT 字幕と transcript を同時に生成します。
- **位置づけ**: 動画は派生物です。`derived-media` と同じく manifest に scene id、model/view のハッシュ、beats の版、字幕、出典、限界を記録します。ブラウザ描画は OS・GPU で数バイト単位の差が出るため、Trace 由来の pilot のような byte 同一性は求めず、**入力（scene と beats）のハッシュ一致**で鮮度を判定します。入力が変わったら再書き出しとレビューが必要です。
- **アクセシビリティ**: 自動再生はミュート・ループなしのプレビューに限ります。点滅（3回/秒超）は禁止。字幕と transcript を必ず付けます。
- **置き場所（まずは始めやすい形）**: 動画バイナリは git に commit しません。Pages のデプロイ job で録画・エンコードし、サイトと一緒に `media/scenes/<scene-id>/` として配信します（Pages job は既に Playwright を動かしているため、追加は ffmpeg だけ。音声は §5a のとおり手元で作ったものを使う）。上限は1本 3MB、合計 50MB。この形は後から release bundle（ADR 0014）や GitHub Releases へ移せるよう、ページは manifest 経由でだけ動画の URL を引きます。合計が上限に近づくか、デプロイ時間が問題になったら置き場所を見直します。

### 5a. ナレーション（TTS）

TTS の品質が実用水準になったため、合成音声のナレーションを試します。

- **台本は beats が唯一の源**: 各 beat に `narration_ja`（話す文）を持たせます。字幕（WebVTT）は話す文と同じ文言から作り、音声と字幕がずれないようにします。`caption_ja` は画面に出す短い要点で、話す文とは別です。
- **時間は長い方に合わせる**: beat の長さ = max(動きの長さ, 音声の長さ)。音声を先に生成し、その実測の長さでタイムラインを組みます。
- **音声は手元で生成して置く**: TTS は CI では動かしません（API キーも課金も CI に持ち込まない）。開発者が手元のスクリプトで生成し、Opus に変換して `media-src/narration/<scene-id>/<beat-hash>.opus` に commit します（20 秒で 100KB 前後）。隣の `narration.json` に beat ごとの (文、話者、style、モデル ID、生成日、入力ハッシュ) を記録します。CI は音声を作らず、手元で作った音声と録画を合成するだけです。
- **鮮度の検査**: `narration_ja` を変えたのに音声を作り直していなければ、入力ハッシュの不一致で validate が失敗します。TTS の出力は同じ入力でも bytes が揃わないため、音声そのものではなく入力で判定します。
- **初期の採用候補**: Gemini API の `gemini-3.8-flash-tts`（GA、日本語の pitch accent と漢字の読みの評価が高い）。比較対象は `gemini-3.8-flash-lite-tts`。話者は作り直せるように prebuilt voice を使い、Voice Design（1年で失効）と声の複製は使いません。話し方は `speech_metadata.style` で固定し、その文言も `narration.json` に残します。
- **合成音声であることを明示**: 動画の説明と transcript に「合成音声」と書きます。実在の人物の声を模した話者は使いません。
- **ライセンス**: 生成音声の再配布・商用利用が許されるモデル・話者だけを使います。採用前に利用規約を確認し、ADR か `docs/` に記録します。
- **ページ内の図では既定でオフ**: 記事内の explorable では、読者が押したときだけ読み上げます。動画では音声付きを既定にし、無音版の字幕だけでも内容が完結するようにします。
- **読み**: 数式・記号・英語の専門用語の読みは、`narration_ja` で読み方を書き下します（例: 「イータ」「ラムダ・マックス」）。読み辞書が必要になったら別に作ります。

### 6. ライブラリ

依存は「理由が書けるものだけ」入れます。現状の site は実行時依存が React と router だけで、この軽さは保ちます。

| 用途 | 採用 | 採らなかったもの と 理由 |
|---|---|---|
| 2D 図 | 手書き SVG + React（現状維持） | D3 一式: 必要なのは座標変換と等高線だけで、既に `svg.ts` / `contours.ts` がある |
| アニメーション時計 | 自前の `useTimeline` を beats 対応に拡張 | GSAP / Framer Motion: 実時間ベースで「時刻 t の純粋関数」にしにくく、録画と一致させづらい |
| 3D | **three.js を直接**（薄い自前 hook で React に載せる）。3D 図の chunk だけで読み込む | react-three-fiber: 宣言的で快適だが、図が小さく、録画時のフレーム制御を自分で持ちたい |
| ナレーション | Gemini `gemini-3.8-flash-tts`（手元で生成し、Opus で commit） | CI での都度生成: 鍵・課金・非決定性を CI に持ち込む |
| 数式 | MathML（現状維持） | KaTeX: 現状不要。MathML で足りない表現が出たら再評価 |
| 動画書き出し | Playwright（既に devDependency）+ ffmpeg（開発者環境・CI のツール） | Remotion: 企業利用にライセンス条件があり、scene と二重管理になる。Manim / Motion Canvas: 表現力は高いが、サイトの図と別実装になり「1つの場面」原則に反する |

- 3D の chunk 予算: gzip 後 200KB 以内、図が画面に入るまで読み込まない。

### 7. 作る前に決める brief

`content-visual-language.md` の brief を拡張し、`explorables.json` の各 entry に次を持たせます（3D・動画を使う場合は必須）。

```yaml
question: 図を見た直後に答えられる問い（1つ）
medium: svg-2d | three-3d
why_this_rung: なぜ一つ下の段では足りないか
beats:            # 自動再生・動画・字幕の共通台本
  - at: 0.0
    duration: 1.5
    focus: 主役（点・面・式のどれか1つ）
    caption_ja: この瞬間に読者に読んでほしいこと
camera: { preset: 名前, vertical_scale: 1.0 }  # 3D のみ
fixed_conditions: ...
not_implied: ...
```

beats を先に書いてレビューし（絵コンテ）、合意してから view を作ります。

### 8. 検証

- model: 解析解・既知値との一致（現状どおり）。
- 決定性: 同じパラメータと時刻 t から同じ状態が出ることを単体テストで固定。
- e2e: 既存の axe・375px 検査に加え、WebGL 無効時の代替表示、reduced motion 時に自動再生しないこと、キーボードでのカメラ操作。
- 予算: 3D chunk サイズをビルドで検査。

## Consequences

- 図を1つ作れば、操作・自動解説・動画・サムネイルが揃い、内容のずれが構造的に起きなくなる。
- beats という「台本」が registry に入るため、文章担当と実装担当が絵コンテで合意してから作れる。
- 「時刻 t の純粋関数」という制約で、物理シミュレーション風の逐次状態を持つ演出は書きにくくなる。必要なら model 側で事前計算した列を持つ。
- three.js 導入で 3D 図のページだけ読み込みが重くなる。chunk 分割と遅延読み込みで他ページへの影響はゼロにする。

## 段階的な導入

1. **beats と録画モード**: `useTimeline` を beats 対応にし、既存3図（`gradient-descent-valley` ほか）に beats を書く。録画スクリプトで最初の動画と字幕を作る。
1a. **TTS の試験**: `gradient-descent-valley` 1本で、`gemini-3.8-flash-tts` と `-lite` を、prebuilt voice 数種で比べる（日本語の自然さ、数式・英語用語の読み、生成コスト）。結果と選んだ話者・style を記録する。
2. **最初の 3D 図**: `gradient-descent-valley` の 3D 版（曲面 + 軌跡、隣に等高線）。3D に上がる条件を満たす最小の例として。
3. **3D が本命の図**: 鞍点と Newton 法、3変数 LP の多面体と頂点移動、KKT での勾配のつり合い。
4. **Theater の外枠**: 既存 Trace 再生を scene の枠（問い → 図 → 再生 → 読み取り）に載せ替え、同じ録画経路で動画化。

## 未決事項

- 動画の長期的な置き場所。まずは Pages のデプロイ時に生成して配信し、上限（合計 50MB）に近づいたら release bundle / GitHub Releases へ移すか決める。
- 話者と style（試験 1a の結果で決める）。
- Gemini API の利用規約で、生成音声を公開サイト・動画で再配布する条件を確認し、ここに記録する（公開前に必須）。
