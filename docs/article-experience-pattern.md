# 操作から式へつなぐ記事の見本

BO、線形最小二乗、分枝限定法の既存記事から、操作と観察を式へつなぐ型をまとめています。線形最小二乗と座標降下法で、この型を使った記事を読めます。
記事の固定節構造は `content-reading-principles.md`、文体は `.agents/skills/article-style/SKILL.md` のままです。
この型は節の中の読者体験と、図・本文の対応を決めます。全記事の一括改稿には使いません。

## 既存記事から残すもの

| 記事 | 具体的な強み | 見本へ取り込むもの |
|---|---|---|
| BO | 初めの3観測から自分で次の場所を選び、結果を得てから同じ観測でBOと比べる。選んだ理由は選択式かスキップ | 人の選択を学習の出発点にする。結果だけで採点せず、観測後に考え直せる。初手に自由記述を要求しない |
| 線形最小二乗 | 同じ4点を、残差の四角、二乗和、等高線、正規方程式で追える | 同じ変数・同じデータ・同じ色で、操作した対象と式をつなぐ。初期データの手計算と変更後の表示を区別する |
| 分枝限定法（現行main） | 小さな例の表で、解の発見と最適性の証明を区別できる | 一手の前後で、何が分かり、何がまだ分からないかを同じ値で示す |

## 一つの問いを追う共通パターン

1. **状況と問い**：具体例を一つ置き、何を決めたいかを述べます。
2. **最初の操作**：既定値を用意し、「このつまみを動かす」「次の場所を選ぶ」など一つの行動を示します。文章を書けなくても進めます。
3. **見える変化**：図の線・点・数値のうち、変わるものを操作の近くに示します。元へ戻す操作も用意します。
4. **対象への疑問**：「なぜ一点で両方のずれが釣り合うのか」など、見た変化から問いを置きます。製作者の進行説明に置き換えません。
5. **式で確かめる**：式の意味を日本語で述べ、図の変数との対応を示してから式を使います。具体値の代入で、観察の理由を追えるようにします。
6. **もう一度動かす**：式から予想できる別の条件を一つ試します。失敗や思った通りでない結果も、次に確かめる条件へつなぎます。
7. **使う判断**：得られた答えと保証の範囲を分け、診断値と切替先を示します。

書き手は、読者と同じ具体例を観察して説明する立場を保ちます。「検算しました」「ここまでで終わりです」「次は説明します」などの作業・進行報告は本文に入れません。
自由記述を使う場合も、操作と観測が済んだ後の任意の振り返りに限ります。

## 図の役割と配置

| 役割 | 大きさと位置 | 本文・caption |
|---|---|---|
| 主役の操作図 | PCでは最大60rem、本文の行長と独立。スマホでは1列へ戻す。軸・操作文字は縮めない | 直前に最初の操作と観察先。captionはパネル名、変化、読める範囲を示す |
| 補助の静的図 | `scripts/generate_lesson_figures.py` で幅440pxに描き、PCでは1:1（27.5remが上限）で主図より小さくする。狭い画面では収まる幅。文字の基準は [teaching-article-playbook.md](teaching-article-playbook.md) §5.4 | 隣接する式や説明の一つだけを支える。初期の4点など、固定した条件をcaptionへ入れる |
| 本文 | PCでは最大42rem。図の幅へ合わせて文章を長い行にしない | 図の「左・右」だけを参照しない。スマホの縦並びでも分かるパネル名を使う |
| 目次 | 操作図のある記事では上部の閉じた開閉領域。本文の横幅を占有しない | 開いて見出しを選べる。移動後は対象見出しへフォーカスする |

実装は記事に操作図があることから配置を決めます。個別の手法IDやルートで分岐しません。
操作図のない記事の既存配置は保持します。本文の見本は `concept.linear-least-squares` と `coordinate-descent` です。

### 視覚品質の判断

常設の説明や文字バッジを足してレイアウトを埋めません。まず主図・本文・補助図の優先順位、配置、余白を決めます。
操作の手がかりには既存の矢印や開閉マーカーを使い、操作名や数式の意味まで機械的にアイコンへ置き換えません。
補助的な説明は必要なtooltipやタップ時の開示へ送り、accessible nameを保持します。
動きは点と直線など、操作で変わった関係を示す目的に限り、reduced-motionでも同じ関係を確認できるようにします。
文字だけで理解できることを完成条件にせず、実画面で文字・図・余白・操作のまとまりを見ます。

## 検収基準

- [ ] 初めの操作をUI上の名前で指定できる。既定値で開始でき、必須の自由記述欄がない。
- [ ] 操作すると図と数値・式が対応して変わり、リセットでその図の既定値へ戻れる。
- [ ] 主図が標準形の詳しい式より先にあり、操作後の疑問が式の説明へつながる。
- [ ] PCで主図と補助図の幅が分かれ、本文は42rem以下。スマホでパネル名と本文の対応が保たれる。
- [ ] 目次を閉じた状態で本文を読め、開いた状態で見出しへ移動できる。
- [ ] PC 1280px、スマホ375pxの実ブラウザ画面を変更前後に見る。320pxの記事領域と文字200%相当でも本文・操作を失わず、横スクロールは表・長い式の内部だけに収まる。記事外の既存不具合は別記する。
- [ ] 本文と操作文字は16px以上、操作図の軸文字は13px以上。図のcaptionと本文が近く、同じデータと変数を指す。
- [ ] 常設説明や文字バッジで埋め合わせていない。既存の操作マーカー・余白・配置で優先順位が見え、必要な補助説明、accessible name、reduced-motionを保持している。
- [ ] 型・build・記事/ライセンス検証・関連テスト・ブラウザ操作/アクセシビリティを確認し、代替環境と未確認を分ける。
- [ ] source/ID/保証/数式/コード/推薦/リリース境界は保持する。生成物はexportからのみ更新する。

デスクトップChromiumのスマホ幅とタッチイベントによる代替は、Android実機の確認とは区別します。

## 同じ型を使う二つ目の見本

座標降下法 (`M_COORDINATE_DESCENT`, `coordinate-descent`) は、既存記事の二次関数と一座標更新式を操作図で追います。
線形最小二乗の「切片だけ／傾きだけを動かす」観察から、「一つの変数ずつ最小にしても、なぜもう一巡が必要になるのか」へ進めます。
勾配降下法の歩幅やBOの観測場所の選択とは異なる問いを、既存の手法IDと記事で扱います。

「最初から」へ戻り、「1つ進む」で点を動かします。一座標の傾きが0でも全体の勾配は残ることを見ます。
等高線の軌跡、一座標の曲線、目的値は同じ点を参照します。軸に沿う谷と斜めの谷を選び、変わった軌跡から結合項を含む更新式へ戻れます。
谷の角度と曲率比は詳しい設定にまとめ、一座標更新、一掃引、勾配による停止、更新回数の上限を区別します。

座標降下法の検収では、記事の初期点 `(4,3)` から `(−9,3)`、`(−9,−1)` と進み、目的値が `569 → 400 → 80` と変わることを確認します。
最小点 `(1,−2)` から開始した場合は0更新で停止し、リセットは同じ既定の例へ戻ります。
平面図と立体図の切替で現在点・目的値・勾配が変わらず、連続したクリックでも操作回数と更新が対応することを確認します。
