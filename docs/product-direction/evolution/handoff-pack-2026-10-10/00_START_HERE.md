# Optimization Compass — 発展準備・実装引継ぎパック

**2026-10-10 / 調査基準 main: `3099b8821a2317761dab8fb3eacebb20cfe0fbcd` / dataset: `0.18.20`**

## 今回の結論

Optimization Compassを「少数の完走できる事例」だけに絞らない。**広く引ける辞書、関係をたどれる地図、違いを体験できる教材、自分の問題へ接続できる入口**を、同じ知識から並行して育てる。

ただし、広さを測る分母は「世界の全最適化手法数」ではなく、版を持つ編集上の収録範囲とする。105という現行手法行数を、今回の160知識トピックの分子にはしない。手法・変種・戦略・共通部品の単位が違うためである。

## このパックの中身

- 160の知識トピック候補、80の問題構造トピック。既存項目を含む**照合用の初稿**であり、新規追加件数ではない。
- 24の分野横断ブリッジ、10の利用者仮説、16の体験パターン、24の判断規則候補。
- 研究・既存コードとの接続方針、媒体/ライブラリ比較、数値検算、依存関係付き課題票。
- 読み取り専用のリポジトリ監査ツール。これは未照合の分母を勝手に達成率へ変換しない。

最初に `AGENT_BRIEF.md`、次に `02_REPOSITORY_AUDIT.md`、`03_SCOPE_AND_COVERAGE.md`、`10_ROADMAP_AND_ACCEPTANCE.md` を読む。個別課題は `backlog/issues.json` と同名のMarkdown票にある。

## 境界

これは実装済み製品でも、承認済み新スキーマでもない。GitHubへのIssue登録、コード変更、PRのmerge、公開、外部サービス契約は行っていない。実装エージェントは作業先の `AGENTS.md` と最新HEADを優先する。

実際に確認したのは、接続GitHubでの主要ファイル・現行方針・生成レポート・PR状態、公開一次資料、およびこのパックの独立したtoy検算・ユーティリティ試験である。ブラウザ操作、全SQLite照合、リポジトリ全テストは未実施。コンテナからのcloneは名前解決で失敗したため、その部分を完了したとは記載しない。

## ローカルでの最初の操作

```bash
python tools/validate_package.py
python tools/verify_numeric_examples.py
python -m unittest discover -s tests -v
python tools/audit_repository.py --repo /path/to/optimization-compass --out /tmp/compass-audit.json
```

WindowsでもPython標準ライブラリのみで実行できる。`--out` は作業リポジトリの外を指定する。監査は既存DBをread-onlyで開き、生成物を更新しない。

## 成長の見方

「名前が載った」「前提を確認した」「記事を検算した」「適切な体験がある」「他分野へ転移できる」を分けて表示する。空欄があることは隠さず、まだ調べていないことと、意図的に扱わないことを区別する。

**最初の成果は、巨大な新基盤ではなく、照合された収録範囲と、既存の一例から複数の価値を生む体験である。**
