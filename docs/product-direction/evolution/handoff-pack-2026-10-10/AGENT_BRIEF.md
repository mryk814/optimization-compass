# ローカル実装エージェントへの指示

あなたはOptimization Compassの既存リポジトリで作業する。ユーザーの目的は、辞書としての広さと、難しい内容を伝える体験の両方を伸ばすこと。少数のケースだけへ縮小したり、手法数だけを増やしたりしない。

## 実装開始前

1. 作業先の `AGENTS.md` と未コミット変更を読む。mainの基準は本パック記載のSHAだが、最新状態を取得・照合し、既存作業を上書きしない。
2. PR297（記事品質台帳）・PR298（主単体法操作図）を再確認する。取得時点ではopen、PR298本文は297依存と記載。無断mergeせず、必要部分を重複実装しない。
3. `tools/audit_repository.py` を外部出力先で実行する。生成する一致候補は人手/意味レビュー前の候補であり、収録済み判定ではない。
4. 調査時の旧方針引用に注意する。現行は `learning-atlas.md`。古い `problem-first-atlas.md` の件数や動線を現在の正本にしない。

## 作業順

`backlog/issues.json` の依存関係に従う。最初の単位は OC-EVOL-001、002、003。その後、辞書拡張・関係・体験を小さな独立PRで並行させる。すべてを一括実装する大きなPRは禁止する。

各PRに、目的、既存との差、変更する正本、生成物、出典、検証コマンドと実行結果、未確認事項を残す。新しいcanonical IDやschema変更は既存手順で設計レビューする。本パックのTOPIC_/PROBLEM_等は企画用IDであり、DBの新規IDを予約していない。

## 必ず守ること

- 生成済みSQLite、site/public/data、release identityを直接編集しない。
- 推薦規則を独立したAIやフロント側の新しいランキングへ移さない。unknown/exclusion/evidenceを維持する。
- 160トピックを160個の新アルゴリズムとみなさない。alias・variant・strategy・primitiveを照合する。
- PRやADRの文面を実装済み・実測済みと読み替えない。既存のテストが通ることと教育効果があることも分ける。
- ライブラリを一覧から一括導入しない。現行sceneを使う一つのPoCで比較してから選ぶ。
- 任意コード/SQLの実行、外部URL追跡、ユーザー実験・制御への接続、課金、公開は別途許可が必要。
- 既存の `.agents/skills` 削除を取り消さない。本パックをAGENTS.mdへ丸ごと転記しない。

## 各コンテンツ追加の最小納品

既存項目との照合 → 一次資料 → 定義と必要条件 → 近縁手法との区別 → 小さな検算例 → 反例/失敗 → 関係1本以上 → 適切な入口 → 対応する検証。

動画を追加する場合は同じ計算状態を使う。文章・静止画・操作図・動画が異なる数値を持つ実装は不可。動画なしでも学習上の情報が欠けないこと。

作業前のSHA、変更ファイル、scope照合結果、PR297/298の扱い、最初の3課題の実装範囲、決裁が必要な事項を報告する。目標分母は初稿なので、変更提案と理由を残してよい。曖昧な任意事項で停止せず、範囲を限定した安全な作業から始める。
