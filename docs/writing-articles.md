# 記事と動く図の作り方

この文書は、記事を書く人（主にAI）に、何を目指すかと、このリポジトリ固有の決まりだけを伝えます。
文章や図の作り方の一般論は書きません。書き手の判断に任せます。
規則として縛るのは、数値・出典・生成物・リンク・数式の表示のように、機械で確かめられる正しさだけです（「機械で確かめること」）。

## 記事は何のためにあるか

読者は、最適化の定式化や手法を、自分の問題に使えるところまで理解したい人です。
記事は、一つの問いに一つの「わかった」を返します。その「わかった」は、文字より先に、目で見て起きるようにします。

- **定式化の記事**（`canonical_entity_type: problem`）：自分の課題がこの形かを見分けられる。小さな例を手で解ける。合わないとき、どの形へ移ればよいか分かる。
- **手法の記事**（`kind: method`）：1回の反復で何が起きるかを、例の数値で説明できる。コードを動かし、続ける・止める・切り替えるを判断できる。
- **概念の記事**：上の二つを読むときに引っかかる一つの考え方（凸性、変数の種類など）を、一つの図で腑に落とす。

長さは、この結果に届くかどうかで決めます。届かない短い記事は、図を足して育てるか、親の記事に統合します。届いた後の段落は削ります。

## 見本

- [線形最小二乗](../content/concepts/linear-least-squares.md)：オーナーが画面で何度も確かめた基準の記事です。
- [ベイズ最適化](../content/methods/bayesian-optimization.md)：読者に先に掘る場所を選ばせ、同じ観測から手法の提案を見せます。読者自身の判断が、予測平均と不確実性の言葉に変わります。
- [Adam](../content/methods/adam.md)：同じ谷で、同じ学習率の勾配降下法と切り替えて比べます。

真似るのは節の並びではなく、この3本がしていることです。

- 手で確かめられる小さな数（温度の読み 1, 2, 2, 4）を、最初の図から最後のPythonまで使い続ける。
- 一つの変化で性質を見せる（4点目を8に上げると、直線もお椀の底も動く）。
- 計算した意外さで誤解を崩す（最も大きい残差は、動かしていない3点目に出る）。
- 量を形にする（残差の二乗を正方形の面積にする）。
- 式は、見たものを説明するために出す。

この3本は、動く図を主役にする方針より前に書かれました。

動く図を主役にした lesson の見本は、次の3本です（2026-11-14 にオーナーが画面で承認）。新しい記事は、まずこの3本の形に合わせます。

- [線形計画](../content/concepts/linear-program.md)：決める・守る・良くするを、計画の点、在庫の範囲、等売上線として一つずつ出し、予想の段の後で、線が最後に角に触れるのを見せます。学習経路の最初の記事で、初めての読者の基準です。
- [動力学残差](../content/concepts/dynamics-defect.md)：費用0の初期推定が継ぎ目で水を湧かせていたことを、すき間の赤で見せ、閉じると費用が上がるという意外さで、残差を費用と別に読む理由を伝えます。薄い記事を育てた例です。
- [ハイパーパラメータ最適化](../content/concepts/hyperparameter-optimization.md)：同じ16回を格子とランダムで同じ時計で競わせ、予想の段の後に、点数の差が新しいデータでほぼ消えるのを見せます。詰め込みすぎた記事を一つの「わかった」に絞った例です。

## 動く図を主役にする

記事の中心は、その記事の「わかった」を起こす動く図（explorable）です。文章は、図で見たことに名前を付け、式で確かめ、使い方へつなぐ役です。
動きが意味を運ばない（静止した一枚で見える）なら、静止図で十分です。

- **一つの図は一つの問いに答えます。** 問いは読者の言葉で書きます（「一方向ずつ最小にしているのに、斜めの谷では何度も往復するのはなぜか」）。
- **見るだけで分かり、触って確かめられるようにします。** 解説付き再生（beats）は、字幕つきの短い動画として、見るだけで要点が伝わるようにします。終わると、同じ図がそのまま読者の操作に渡ります。
- **時間で起きることを動かします。** 反復が進む、候補が受理・棄却される、集合が縮む、境界に当たる。反復は等速で進め、一度に動く主役は一つにし、前の状態を薄く残して何が変わったかを見せます。
- **量を形にします。** 二乗を面積に、勾配を矢印の長さに、双対価格を傾きにします。数字の表より先に、形で比べられるようにします。
- **二つの空間をつなぎます。** 最適化では「選ぶ空間」と「結果を見る空間」が分かれていることが多く、片方を動かすともう片方が動く図がよく効きます。
- **比べるときは、一つの要因だけが違う二つの実行を、同じ時計で並べます。** 固定した要因と変えた要因が、画面で見て分かるようにします。
- **判断が主題なら、読者に先に予想させます。** 決め手の場面の前で止め、読者が選んでから、計算した答えを見せます。
- **式の数値を動かします。** 更新式に今の値を代入した形を、図と一緒に出します（`LiveMath`）。
- **3Dは、高さや奥行きそのものが論点のときだけ使います。** 同じ点を描いた2Dの等高線と並べます。
- 図を読むのに指示（「紺の短い線を数えてください」）が要るなら、図の方を直します。
- 初めて開いたときに何も押さなくても読める状態にし、reduced motion では終了状態を出します。スマホでは図が縦に積まれるので、本文は図の部分を「左・右」ではなくパネルの見出しで呼びます。
- 色は `atlas-geometric-v1` です。構造線は紺、可行・観測は青緑、候補・更新は橙、赤は違反だけに使います。色だけに意味を預けず、文字も添えます。

静止図（SVG）は補助です。一つの式や一つの説明の隣に置き、その一点だけを支えます。

### Lesson で書く

記事の前半は、動く図を一つ据えた lesson（`:::: lesson <図のid>`）で書きます。文章を短い段（`::: step`）に分け、段ごとに図の設定と動き（定数、`a..b` の掃引、`a..b@r` の速度）を書きます。PCでは図が右に固定され、読み進めると段が切り替わって図が動きます。スマホでは図の下の帯で段を送ります。「自動で見る」で字幕つきの短い動画のように通しで再生でき、最後の段の後は同じ図が読者の操作に渡ります。書き方の細部は [`explorables.md`](explorables.md) の「Lesson」にあります。

- 一つの段は一つの気づきです。最初の一文（太字）がその段の字幕になり、続けて2文ほどで、見えたものに名前を付けます。段の文章が言う数値・印・名前は、その段の終わりの図にそのまま見えているようにします。
- 判断や意外さが主題の場面の前には、予想の段（`predict`）を一つ置きます。答えは次の段の図で見せます。
- 段の間、図は一画面に収めます（PC 1280×800、スマホ 375×812 で図と帯が一緒に見える）。表や長い式は、自由に動かす状態だけに出します。
- 図は記事の数値を出す計算そのものです。Pythonで作った例は fixture にし、図の試験で段の文章の数値を固定します。
## 記事の形

- 前半は「見て分かる」部分です。場面、動く図、図で見たことの説明、それを式にしたもの。読者はここで「わかった」に届きます。
- 後半は、あとで引くための部分です。標準形と記号、つまずきやすい点、関連する問題や手法、数値計算とPython、診断値。後半で前半の図の話を繰り返しません。
- 節の見出しは記事ごとに決めます。言うことのない節は作りません。
- `summary`（frontmatter）は、カード・検索・ページの説明に出る1〜2文です。本文の書き出しとは別に書きます。書き出しは、定義ではなく場面や図から始めてかまいません。

## 文章

- 日本語の です・ます で書きます。英語は、手法の正式名（BFGS、Nelder–Mead）、API、コード、式、出典の題名に残します。日本語の文に普通の英単語を混ぜません（検査あり）。ソルバー、勾配、制約、局所解など、定着した日本語を使います。
- 式の前に、その式が何をするかを一文で言います。結果の数値の後に、例の言葉へ戻します（「温度は1時間に約0.9度ずつ上がっている、と読めます」）。
- 図の前提と、図から読み取れないことは、その図の `meta.json` の `fixed_conditions` と `not_implied` に書きます。図の枠が一か所に出すので、caption と本文では繰り返しません。本文で限界に触れるのは、読者が実際に言い過ぎそうな箇所で一度だけにします。

このリポジトリで繰り返した失敗です。読者の理解に効かないので書きません。

- 進行報告と作業報告（「この節では〜を追います」「検算しました」）。
- 型を埋めるための節や欄（「守ること: 特になし」だけの欄、例と関係のない一般的な注意）。
- 出力の貼り付け（`2.500000`、20行のログ）と、本文で使わない数値の列挙。
- 図のcaptionごとに付けた、定型の断り書き。
- 数値を読ませるだけの表を、図の代わりに置くこと。

## 作る順番

1. **選ぶ。** `uv run python scripts/article_inventory.py` で、学習経路に載っているのに動く図がない記事などを見ます。記事がない定式化は `uv run python scripts/formulation_backlog.py` で見ます。オーナーが承認した記事（`data/seeds/owner_approvals.json`）は、オーナーに断らずに書き直しません。
2. **絵コンテを先に作る。** 読者の問い、通して使う一つの例、「わかった」の瞬間、解説付き再生の流れ（何が、どの順に動き、各場面で何に気づいてほしいか）を短く書きます。PRの説明に貼ると、レビューする人が意図を確かめられます。
3. **数値を一つの計算から出す。** 例の数値は、静止図のモジュールか、動く図の計算で出し、テストで固定します。本文の数値は、その出力から写します。機械精度に近い値（$10^{-11}$ の残差、$10^{18}$ の条件数）は数値ライブラリの実装で末尾が変わるので、桁の大きさで書きます。
4. **動く図を作る。** 図の `meta.json` に `params` を宣言し、lesson の段と自由な操作の両方で動くようにします。
5. **図のまわりに文章を書く。** 前半を lesson の段に、後半を引くための部分に書きます。
6. **描画した画面で見る。** `npm --prefix site run shots -- <content-id>` で、PC 1280px、スマホ 375px、記事幅 320px の画面と、lesson の各段の終わり（PCとスマホ）を一枚にまとめて見ます。本文・図・操作がまとまって見え、横にはみ出さないかを確かめます。オーナーはMarkdownではなく画面で記事を読みます。
7. **別のエージェントに読ませる。** 書いた本人とは別の目で、本文と画面の食い違い（ボタンの名前、図にない印、数値）を探し、`uv run python scripts/run_article_code.py <md>` で本文のPythonを実行し直してもらいます。二回目の読みでも本物の誤りが見つかってきました。

## 機械で確かめること

規則として守るのはここだけです。どれもコマンドで確かめられます。

| 何を | どこで |
|---|---|
| frontmatter と Markdown の形、未知の出典・記事ID、壊れた内部リンク、表示できない数式、日本語への英単語の混入 | `uv run python scripts/check_article.py <md…>`（生成物を作らずに確かめられるので、並行して書くときに使う）、`uv run optimization-compass validate content` |
| 本文のPythonの出力と、本文に書いた値 | `uv run python scripts/run_article_code.py <md…>` |
| 静止図が計算と一致していること | `uv run python scripts/generate_lesson_figures.py --check` と、その図のテスト |
| 動く図の計算 | 各図のフォルダにある計算のテスト |
| 公開データ | `uv run optimization-compass ready content <content-id>`（既存の entity の記事）、または `uv run optimization-compass export-site-data --output site/public/data` |

内容の正しさの原則（出典は公式ドキュメント・原論文・標準で、Qiita と Zenn は使わない。小さな例から一般の優劣を言わない。ライブラリの既定値を推奨として示さない。離散化した結果から連続モデルの保証を言わない）は、[`AGENTS.md`](../AGENTS.md) の「不変条件」にあります。

## ファイルの置き場所

一つの記事を作るとき、ほかの記事の作業と同じファイルを編集しないで済むようにしてあります。並行して何本も書くときは、1記事を1ブランチにし、生成物（`site/public/data`）は統合した後に作り直します。

| 作るもの | 置き場所 |
|---|---|
| 記事 | `content/concepts/<slug>.md`、`content/methods/<slug>.md`。frontmatter は [`content-authoring.md`](content-authoring.md) |
| 静止図 | `scripts/lesson_figures/<記事>.py` に `FIGURES` を置く。出力は `site/public/figures/`。テストは `tests/lesson_figures/` |
| 動く図 | `site/src/features/explorable/figures/<id>/`（[`explorables.md`](explorables.md)） |

## リポジトリを読めないAIに頼むとき

この文書の「記事は何のためにあるか」から「文章」までと、見本の記事1本を渡し、絵コンテ、Markdown、本文の数値をすべて出すPythonを書いてもらいます。
受け取ったら、リポジトリ側でPythonを実行して数値を確かめ、動く図を作り、`check_article.py` を通してから取り込みます。
