# 教材記事を書くためのプロンプト（リポジトリを読めないAI向け）

ChatGPTなど、リポジトリを読めないAIに記事の下書きを頼むときに使います。
下の「入力」を埋め、`---- ここから ----` から `---- ここまで ----` までをそのまま貼ります。
内容は [`docs/teaching-article-playbook.md`](../teaching-article-playbook.md) を一つのプロンプトに収めたものです。基準を変えるときは、先にplaybookを直してから、このファイルを合わせます。

## 入力として用意するもの

| 入力 | 取り出し方 |
|---|---|
| 記事の種類（formulation / method）と content_id | 書く記事の対象 |
| frontmatterのひな形 | 最も近い既存記事のfrontmatterをコピーし、値を書き換える |
| 使ってよい source ID と出典名 | `site/public/data/sources.json` |
| リンクしてよい記事のルートと題名 | `site/public/data/content.json`（`#/learn/<id>`、`#/formulations/PAxxx`） |
| 見本記事の全文 | `content/concepts/linear-least-squares.md`（method記事なら `content/methods/adam.md` も） |

見本記事の全文を一緒に貼ると、文体と密度がいちばん揃います。

## 受け取った後にすること

1. 出力の「検算用Python」を実行し、本文の数値と一致するか確かめます（`uv run --no-project --with numpy --with scipy python check.py`）。
2. 記事を `content/` に置き、`uv run python scripts/check_article.py <file>` を通します。
3. 図のブリーフは、リポジトリを読めるエージェント（Claude Code、Codex）に渡して実装させます。

# 書き方の基準

## 一つの題材で教え切る

- 手で計算できる小さな例を一つ決めます（2変数、4点、2〜3反復など）。その例を「30秒でつかむ」から最後のコードまで使い続けます。
- 30秒でつかむでは、例を身近な場面として出します（温度計の読み、井戸を掘る場所、細長い谷など）。
- 例の数値は推測で書きません。必ず「検算用Python」で計算し、丸めた値を書きます。読者が手で確かめられる中間量も示します。
- 例の中の小見出しには「4点の例・〜」のように題材名を付けます。式や静止図がどのデータに対応するかは、「以下の式と補助図は、この初期の4点に対応します」のように、データについての文で示します。
- 「この節では〜を追います」「ここまでで〜は終わりです」「次は〜を説明します」のような進行報告は書きません。

## 節の型（見出しの名前と順番を変えない）

formulation記事の `##` 見出しは次の順にします。

1. 30秒でつかむ
2. 標準形を読む
3. 小さな例
4. つまずきやすい点
5. 課題から定式化する
6. 困りごとから関連する問題へ
7. 数値計算の方法を選ぶ

method記事の `##` 見出しは次の順にします。型の節の間に `## コラム: …` を置いてもかまいません。

1. 30秒でつかむ
2. 一手の意味
3. 小さな例
4. 向く条件・避ける条件
5. Python
6. 診断値
7. 失敗・切替の兆候
8. 困りごとから関連する手法へ

frontmatterの直後の第1段落は、frontmatterの `summary` と一字一句同じにします。

## 節ごとの中身

- **30秒でつかむ**: 身近な場面を2〜3文で書き、その場面での違和感や迷いを書きます。次に、解決の考え方を一文で書きます。続けて三つの箇条書きを置きます。formulation記事は「決めるもの / 良くしたいもの / 守ること」、method記事は「見るもの / 動かすもの / 前進の判断」です。該当しない項目は「特になし」と書きます。性質の一覧（凸性、保証など）は画面のカードに出るので、ここでは書きません。
  主図（explorable）はここに置きます。図の直前に、最初の操作をUIの名前で一つ指示し（「まず『傾き x₂』のつまみを動かし…」）、結果が画面のどこに出るかを書きます。図の後に「確かめてほしいこと」を番号付きで3つ書き、最後に観察から生まれる疑問を一つ置きます。この疑問に、後の節の式が答えます。
- **標準形を読む / 一手の意味**: 式の前に、式が何をするかを一文で書きます。式の後には「記号 | 意味 | 例では」の3列の表を置きます。誤解しやすい語には小見出しを付けて定義し、当てはまる例と当てはまらない例を一つずつ示します。「なぜこの形か」の小見出しも置き、理由とその理由が成り立つ条件を書きます。method記事では、1回の反復を番号付きの手順にし、どの手順が高い計算かを明記します。状況ごとの振る舞いは表にします。
- **小さな例**: 設定を最初にまとめ、数反復分を表で示します。表の後に、表をどう読むかを書きます。30秒でつかむの主図で見たことを、ここで式と数値で確かめます。比較相手（別の手法、乱数など）を同じ例で並べ、比較から言えないことを一文で書きます。長い数値の計算は、文中ではなく `$$` の数式ブロックに書きます。
- **つまずきやすい点**: 各項目を「**読者がしてしまう行動**: 例の数値で示す反例。代わりにすること。」の形で書きます。記事の例と関係のない一般的な注意は書きません。
- **課題から定式化する**: 「何を推定（決定）するか / どう予測するか / どのずれを減らすか / 条件があるか」の番号付き4段で、課題の言葉から式までを導きます。
- **困りごとから関連する問題へ（手法へ）**: 最初に「読者が気づく症状 → [記事名](ルート)」の箇条書きを書きます。続けて、関連する記事ごとに、より一般か、特殊か、緩和か、形が似ているだけか、とその条件を短い段落で書きます。リンクは入力で渡したルートだけを使います。
- **数値計算の方法を選ぶ / Python**: コードは小さな例と同じ題材を解きます。`print` の行末には、実際の出力をコメントで書きます。コードの直後に、出力の各値の意味を書きます。実装上の落とし穴は、実験の表で示します。

## 日本語

- です・ます調で書きます。一文で一つのことを言い、文と文は「だから」「そのため」「その結果」などでつなぎます。
- 式の後に「この式は『〜』と読みます」、結果の後に「〜と読めます」と書き、題材の言葉に戻します。
- 英語の正式用語は、初出で一度だけ併記します。例：正規方程式（normal equations）。手法名、API名、数式、コードは原表記のままにします。
- 次の書き方はしません：絵文字、文末のコロン、過剰な太字、「〜することができます」、「本稿では」、書き手の作業報告（「確かめました」）、計算出力をそのまま貼った桁（`2.500000`）、各節を注意書きで締めること。
- 保証や性能を、根拠より強く言いません。手法の順位付けや、ライブラリの既定値を一般的な推奨として書くこともしません。
- 根拠が必要な事実には、入力で渡した出典だけを使います。渡された出典で裏付けられない事実は書かず、末尾の「要確認」に挙げます。

## 図

図は次の水準で計画します。実装はしません。

- L1 静止SVG: 中心となる仕組みを描いた図。すべての記事に最低1枚置きます。
- L2 explorable: 読者が条件を動かし、その場の計算で結果を確かめる図。主要な手法には1つ置きます。
- L3 解説付き再生: 反復の順番を、captionを付けて再生する図。
- L4 3D: 高さや空間配置を読むこと自体が論点のときだけ使います。2D図に追加するもので、2D図の代わりにはしません。

よい図の型は次のとおりです。

- 二つの空間をつなぎ、片方を動かすともう片方も動くようにします（データの平面とパラメータの平面など）。
- 抽象的な量を、面積や長さで見せます。
- 比較相手を同じ図で切り替えます。
- 読者に先に選ばせてから、手法の選択と比べます。
- 図から読み取れないことを、captionで一文で書きます。

置き場所は次のように決めます。主図は、標準形の詳しい式より先、「30秒でつかむ」の中に置きます。反復の流れそのものを追う図だけは、「小さな例」の設定の直後（手計算の表より前）に置いてもかまいません。静止図は補助として、支える式や説明の直後に置きます。

記事は画面で読まれます。次の点を守ります。

- 図を「左・右・上・下」で呼びません。スマホでは2つのパネルが縦に積まれるからです。パネルの見出しやUIの名前で呼びます。
- アイコンだけのボタンは、名前とアイコンを両方書きます。例：「最初から」（⏮）、「1つ進む」（▶）。
- 図の操作名は日本語で書きます（「学習率 η」「切片 x₁」）。手法の正式名はそのままにします。
- 静止図のcaptionには、固定した条件（「初期の4点：」など）を入れます。図の中の文字は、表示したときに本文より大きくならないようにします。
- 画面の枠が標準形の性質の一覧と、関連する定式化の一覧（条件つき）を出します。本文ではそれを繰り返さず、例を使った理由と「困りごと → リンク」に絞ります。

本文では、静止図は `![具体的なalt](./figures/<名前>.svg "caption")`、explorableは次の形で置き場所を示します。

```
::: explorable <kebab-case-id>
何を動かすと何が見えるか、何が読み取れないかを一段落で書く。
:::
```

# 出力

次の4つを、この順に出力します。

1. **ブリーフ**（YAML）: reader_question、scene、running_example（data、answer、checkable_facts）、baseline、misconceptions、troubles_to_neighbors、visuals（level、question、placement、first_action、panel_names、must_show、must_not_imply）、sources。
2. **記事**: frontmatterから始まるMarkdown全文。数式は `$...$` と `$$` で書きます。
3. **検算用Python**: 本文に出てくる数値をすべて計算して表示するスクリプト。numpyとscipyだけを使い、乱数を使う場合はseedを固定します。
4. **要確認**: 出典で裏付けられなかった点と、確信のない点の箇条書き。なければ「なし」と書きます。
