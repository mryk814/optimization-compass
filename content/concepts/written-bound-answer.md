ソルバーの答えが自分で書いた下限や上限に着いたら、その答えを決めたのはツールではなく、その境界の値です。境界での傾きは、境界を1だけ動かしたときに費用がどれだけ変わるかを表します。本当の制約が開いた範囲なら最小は存在せず、どこに境界を書くかが答えになります。

## 30秒でつかむ

[ソルバーが目的関数を呼ぶ点と回数](#/learn/concept.solver-evaluation-points)と同じ、鋼の熱処理の例を使います。温度 $T$（K）と炭素の量 $c$ をツールに渡すと、費用 $F$ が返ります。ツールは $c\le 0$ を受け付けないので、その記事では炭素の下限を $c\ge10^{-5}$ と書きました。

L-BFGS-Bの答えは $(T,c)=(1247.73,\ 10^{-5})$ で、費用は $F=0.2387$ です。炭素の量は、書いた下限にちょうど着いています。そこで、下限だけを変えて同じ条件で解き直しました。

| 炭素の下限 | 答えの $T$ | 答えの $c$ | 費用 $F$ |
|---|---|---|---|
| $10^{-6}$ | 1247.7 | $10^{-6}$ | 0.1944 |
| $10^{-5}$ | 1247.7 | $10^{-5}$ | 0.2387 |
| $10^{-4}$ | 1247.8 | $10^{-4}$ | 0.6823 |

温度はほとんど変わらないのに、費用は下限につれて3倍以上も変わります。どの答えも、炭素の量は下限そのものです。

- **決めるもの**: 温度 $T$ と炭素の量 $c$
- **良くしたいもの**: ツールが返す費用 $F$
- **守ること**: $900\le T\le1600$、$c_{\min}\le c\le0.01$。$c_{\min}$ は自分で書いた値

この答えを決めているのは、ツールの中の式でしょうか。それとも、自分で書いた $c_{\min}$ でしょうか。

## 書いた制約と本当の制約

例には、炭素の量についての制約が三つあります。

| 制約 | 誰が知っているか | 例では |
|---|---|---|
| 書いた制約 | ソルバー。点を選ぶときに使う | `bounds` の $c\ge c_{\min}$ |
| ツールのエラー | ツールだけ。ソルバーは呼んでみるまで分からない | $c\le0$ でエラーになる |
| 本当の要求 | 書かなければ誰も知らない | 実際に作れる最小の炭素量 |

ツールのエラーが表す範囲 $c>0$ は、端の0を含まない開いた範囲です。費用は炭素を減らすほど下がるので、$c$ を0に近づけると、費用は0.1895に近づきます。ところが $c=0$ はツールが拒むので、0.1895にはどの点でも届きません。この範囲には最小の点がありません。

そのため、$c_{\min}$ をどこに書くかで、答えが決まります。下限を書いたことで、最小の点のない問題が、最小の点のある問題に変わりました。その代わり、答えの $c$ はツールの式ではなく、書いた値から来ています。

![炭素の量 c（0〜0.00011）を横軸に、その c で温度を最適にしたときの費用 F を描いた図。F はほぼ直線で、傾きは約4927。下限1e−5の答えはF=0.2387、下限1e−4の答えはF=0.6823。c=0はツールがエラーになるので白い丸で描かれ、Fは0.1895に近づくが届かない。](./figures/written-bound-price.svg "炭素の量ごとに温度を最適にしたときの費用：下限を動かすと、答えはこの線に沿って動く。教材用のツールの式で、実際の鋼の費用は示さない")

## 小さな例・境界での傾きは下限の値段

### 鋼の例・答えの点の傾き

L-BFGS-Bは、答えの点での勾配を `res.jac` に返します。下限 $10^{-5}$ の答えでは、次の値です。

$$
\left(\frac{\partial F}{\partial T},\ \frac{\partial F}{\partial c}\right)=(-0.000005,\ 4927)
$$

$T$ の成分はほぼ0で、温度は範囲の内側で最小になっています。$c$ の成分4927は0から遠い値です。この値は「$c$ を減らせば、費用はまだ下がる」と読みます。$c$ を減らす向きは下限でふさがれているので、ソルバーはそこで止まりました。

下限に着いた変数の最小では、その変数の傾きは0以上になります。傾きが正なら、境界がなければもっと減らせたことを表します。L-BFGS-Bの停止の条件も、境界の外を向く成分を除いた勾配（射影勾配）が小さいことです。

### 鋼の例・4927の内訳

炭素の量を増やすと、炭素の費用 $5000c$ が増えます。一方で硬さ $y$ が上がり、目標の1.05に近づくので、硬さのずれの費用は減ります。

$$
\frac{\partial F}{\partial c}=\underbrace{2\,(y-1.05)\,\frac{\partial y}{\partial c}}_{\text{硬さの項}}+\underbrace{5000}_{\text{炭素の費用}}
$$

答えの点では $y=0.6158$、$\partial y/\partial c=83.8$ で、硬さの項は $-72.8$ です。$5000-72.8\approx4927$ になります。炭素の費用が硬さの得を大きく上回るので、炭素は減らせるだけ減らすのが得です。

### 鋼の例・下限を動かしたときの見積もり

この傾きは、下限を少し動かしたときの費用の変化を表します。下限を $10^{-5}$ から $c_{\min}$ に動かすと、費用は次のように見積もれます。

$$
F(c_{\min})\approx0.2387+4927\,(c_{\min}-10^{-5})
$$

| 新しい下限 | 見積もり | 解き直した値 |
|---|---|---|
| $10^{-6}$ | 0.1944 | 0.1944 |
| $10^{-4}$ | 0.6822 | 0.6823 |

見積もりは、解き直さなくても、表の小数第3位まで合っています。下限に着いた変数の傾きは、その下限の値段として報告できます。

## つまずきやすい点

- **収束した点を、ツールが選んだ答えだと読む**: 下限 $10^{-5}$ の答え $c=10^{-5}$ は、自分で書いた値そのものです。下限を $10^{-4}$ にすれば $c=10^{-4}$ が答えになり、費用は0.6823です。答えの変数が範囲の端に着いていないかを、まず確かめてください。
- **下限を0に近づけるほど良い答えになると考える**: 下限を $10^{-12}$ にすれば、費用は0.1895に近づきます。ただし、0.1895に届く点はありません。炭素の量が $10^{-12}$ の鋼を作れるかは、ツールもソルバーも知りません。下限は、作れる最小の炭素量のような本当の要求から決めます。
- **`res.jac` の大きな値を、収束していない印だと読む**: 答えの `res.jac` は $(−0.000005,\ 4927)$ で、$c$ の成分が大きく見えます。それでも `success` は `True` です。下限に着いた変数の傾きは正のままで構いません。収束を見るときは、範囲の内側にある変数の成分（例では $T$）を見ます。

## 本当の制約を書く

答えが書いた境界に着いたら、次の順に確かめます。

1. **どの変数が境界に着いたか**: 例では $c$ が下限に着き、$T$ は内側です。
2. **その境界はどこから来たか**: 例の $10^{-5}$ は、ツールのエラーを避けるために置いた値でした。作れる最小の炭素量のような本当の要求があるなら、その値を下限に書きます。
3. **境界の値段はいくらか**: `res.jac` の成分から、下限を動かしたときの費用の変化を見積もります。例では、下限を $10^{-5}$ 上げるごとに、費用は約 $0.049$ 増えます。
4. **境界が本当は費用なのか**: 炭素を減らすほど工程の費用が増えるなら、その費用は下限ではなく目的の式に入れます。そうすれば、答えの $c$ は書いた値ではなく、費用の釣り合いから決まります。

答えを報告するときは、境界に着いた変数と、その値段を一緒に書きます。例なら「炭素は下限 $10^{-5}$ に着いた。下限を $10^{-5}$ 下げるごとに、費用は約0.049下がる」と書きます。

## Python

次のコードは、下限だけを変えて解き直し、境界での傾きから見積もった費用と比べます。`# →` の行は、SciPy 1.18.1で実行したときの出力です。

```python
from scipy.optimize import minimize


def hardness(T, c):
    # 平衡計算の代わり: y**3 + (T/1000)*y = 1 + 200*c を二分法で解く
    lo, hi = 0.0, 2.0
    while hi - lo > 1e-13:
        mid = 0.5 * (lo + hi)
        if mid**3 + T / 1000 * mid - 1 - 200 * c > 0:
            hi = mid
        else:
            lo = mid
    return 0.5 * (lo + hi)


def tool(x):
    T, c = x
    if c <= 0:
        raise ValueError("炭素量が範囲外")
    y = hardness(T, c)
    return (y - 1.05) ** 2 + 0.5 * ((T - 1250) / 100) ** 2 + 5000 * c


x0 = [1200.0, 0.0005]

# 1. 炭素の下限だけを変えて、同じ条件で解く
for c_min in [1e-6, 1e-5, 1e-4]:
    res = minimize(tool, x0, method="L-BFGS-B", bounds=[(900, 1600), (c_min, 0.01)])
    T, c = res.x
    print(f"下限 {c_min:g}: T={T:.1f}, c={c:g}, F={res.fun:.4f}, dF/dc={res.jac[1]:.0f}")
# → 下限 1e-06: T=1247.7, c=1e-06, F=0.1944, dF/dc=4927
# → 下限 1e-05: T=1247.7, c=1e-05, F=0.2387, dF/dc=4927
# → 下限 0.0001: T=1247.8, c=0.0001, F=0.6823, dF/dc=4929

# 2. 境界での傾き（下限の値段）から、下限を動かしたときの F を見積もる
base = minimize(tool, x0, method="L-BFGS-B", bounds=[(900, 1600), (1e-5, 0.01)])
price = base.jac[1]
for c_min in [1e-6, 1e-4]:
    print(f"下限 {c_min:g} の見積もり: F={base.fun + price * (c_min - 1e-5):.4f}")
# → 下限 1e-06 の見積もり: F=0.1944
# → 下限 0.0001 の見積もり: F=0.6822
```

1の出力では、どの下限でも $c$ が下限と同じ値です。`res.jac` の $c$ の成分 `dF/dc` は約4927で、下限によってほとんど変わりません。$T$ は小数第1位で表示しています。L-BFGS-Bは傾きが十分小さくなった所で止まるので、その先の桁は計算機によって変わることがあります。2の出力は、下限 $10^{-5}$ での傾きだけを使った見積もりで、1の解き直した費用と小数第3位まで合います。

## 出典と再現条件

上下限に着いた最小で勾配の成分が0以上になる条件は、Nocedal・Wrightの教科書『Numerical Optimization』（S056）に基づきます。乗数が、制約を動かしたときの目的の変化を表すことも同じ教科書にあります。L-BFGS-Bの射影勾配による停止はByrdらの論文（S065）に、`minimize` の `bounds` と `jac` はSciPyの公式文書（S002）に基づきます。
