モデル予測制御（MPC）は、現在の状態から有限の先までの操作量を最適化し、最初の一手だけを実行して、次の周期でまた解き直す定式化です。線形のモデル、二次の費用、線形の制約なら、毎周期の問題は凸QPです。ただし、その問題が解けたことは、次の周期でも解けることや、連続時間で制約を守ることを保証しません。

## 30秒でつかむ

レール上の台車を、位置3の静止状態から、位置0で止めたいとします。位置0には壁があり、越えてはいけません。台車を押す力は $-1$ から $1$ までです。制御は1歩ごとに、位置と速度を測り、先の5歩ぶんの力を計画し、そのうち最初の力だけを加えます。次の1歩で、測り直して計画を立て直します。

計画を1回だけ立てて最後まで実行すれば、手間は一度で済みます。ところが実際の台車は、モデルどおりには動きません。ここでは、台車が力に対して、モデルの1.3倍強く反応するとします。計画だけを信じると、気づかないまま壁を越えます。

- **決めるもの**: 今から5歩ぶんの力 $u_0,\dots,u_4$（実行するのは $u_0$ だけで、残りは次の周期の初期の見積もりになります）
- **良くしたいもの**: 位置と速度のずれ、および力の大きさの重みつき和
- **守ること**: 台車の動きの式、力の範囲 $|u|\le1$、壁の手前にいること $p\ge0$、そして今測った状態から始めること

次の図は、同じ初期状態から、3通りの動かし方で位置を12歩ぶん追ったものです。壁は位置0で、紺の太線です。

1. 橙の細線は、モデルの上での計画です。位置は $3,\ 2.5,\ 1.23,\ 0.19,\ 0$ と進み、4歩目に壁の位置0へ着きます。
2. 灰の線は、同じ12個の力を、解き直さずに実機へ加えた結果です。3歩目に位置が $-0.66$ になって壁を越え、12歩後は $-0.90$ に止まります。
3. 緑の線は、毎回5歩先まで解き直した結果です。位置の最小は $0.019$ で、壁を越えません。12歩後は $0.023$ です。

毎回解き直す問題は、毎回同じ形をしているのでしょうか。標準形と小さな例の式で確かめられます。

## 標準形を読む

次の式が表すのは「現在の状態 $\hat x(t)$ から、動きの式に従って $N$ 歩先まで進む操作量の列を選び、状態と操作の重みつき二乗和を最小にする」です。

$$
\min_{u_0,\dots,u_{N-1}}\ \sum_{k=0}^{N-1}\bigl(x_k^\top Qx_k+u_k^\top Ru_k\bigr)+x_N^\top Px_N
\quad\text{s.t.}\quad x_{k+1}=Ax_k+Bu_k,\ \ x_0=\hat x(t),\ \ u_k\in\mathcal U,\ \ x_k\in\mathcal X
$$

記号は次の意味です。

| 記号 | 意味 | 台車の例では |
|---|---|---|
| $N$ | 予測区間の長さ（先を見る歩数） | $5$ |
| $x_k=(p_k,v_k)$ | $k$ 歩先の予測状態 | 位置と速度 |
| $u_k$ | $k$ 歩先の操作量 | 台車を押す力 |
| $A,\ B$ | 動きの式の行列 | $A=\begin{pmatrix}1&1\\0&1\end{pmatrix}$、$B=\begin{pmatrix}0.5\\1\end{pmatrix}$（刻み1） |
| $Q,\ R$ | 状態と操作の重み | $Q=\mathrm{diag}(1,\ 0.1)$、$R=0.1$ |
| $P$ | 終端コストの行列 | 無限区間の制約なしの問題から決める（後述） |
| $\hat x(t)$ | 時刻 $t$ に測った状態。周期ごとに変わる | 最初は $(3,\ 0)$ |
| $\mathcal U,\ \mathcal X$ | 操作量と状態の制約の集合 | $\lvert u\rvert\le1$、$p\ge0$ |

式の和には、定数の $x_0^\top Qx_0$ を含めていません。以下の数値でも、この項は除いています。

### 毎周期の問題は凸QP

$A$、$B$ が決まった行列で、$Q$、$R$、$P$ が半正定値（$R$ は正定値）、制約が線形の不等式なら、この問題は凸QPです。台車の例では、変数は予測状態 $x_1,\dots,x_5$（10個）と力 $u_0,\dots,u_4$（5個）の15個です。制約は、動きの式 10本、力の範囲 5本、壁 5本です。

動きの式で $x_k$ を $u$ で書き直すと、変数は $u$ だけになります。このとき、$x_0$ は目的の線形項と制約の右辺にだけ入り、二次の項の行列と制約の行列は周期をまたいで変わりません。毎周期変わるのは、最初の1本の式 $x_1-Bu_0=Ax_0$ の右辺だけです。この「構造が同じで、データだけが少し変わる」性質が、解き直しの費用を抑える手がかりになります。

### 先頭の一手だけを実行する

1周期の手順は、次のとおりです。

1. 状態 $\hat x(t)$ を測る。
2. $x_0=\hat x(t)$ として、$N$ 歩先までのQPを解く。
3. 解のうち $u_0$ だけを実機へ加える。
4. 次の周期で、新しい $\hat x(t+1)$ から1へ戻る。

計画の残りを捨てるのは、予測が外れるからです。実機の状態は、モデルが予想した $x_1$ とずれます。測り直した状態から計画を取り直せば、ずれが次の力へ反映されます。

### 終端コスト $P$ の役目

$N$ 歩より先の費用は、このQPには入りません。そこで、最後の状態に $x_N^\top Px_N$ を足して、先の費用の代わりにします。$P$ を、制約が効かないときの無限区間の最適な費用（離散時間のRiccati方程式の解）にすれば、制約が効かない限り、$N$ 歩のQPの最初の力は $N$ によらず $u_0=-Kx_0$ になります。台車の例では $K=(0.8947,\ 1.3673)$ で、$x_0=(3,\ 0)$ のとき $u_0=-2.684$ です。

ただし、この例では力の範囲と壁が効くので、$P$ は先の費用の近似にとどまります。$P$ を決めても、先の周期でQPが解けることまでは決まりません。

### 離散化した問題の保証は、連続時間へ持ち越せない

台車の式は、1歩の間、力を一定に保つ設定で、連続時間の台車を厳密に離散化したものです。それでも、壁の制約 $p_k\ge0$ は、歩の区切りの時刻だけで確かめています。区切りの間の位置は、QPの制約に入っていません。連続時間の安全性を言うには、区切りの間の軌道も別に計算して確かめます。この例での数値は、つまずきやすい点で示します。

## 小さな例

台車の例を、初期状態 $(p,\ v)=(3,\ 0)$、予測区間 $N=5$ で解きます。以下の表と式は、この設定に対応します。コードは、状態と力を並べた15個の変数のQPを、ソルバー OSQP（S012）で解きます。許容誤差などの設定は、この例のために決めた値で、推奨値ではありません。

### 台車の例・1回のQPを解く

```python
import numpy as np
import osqp
import scipy.linalg as sl
from scipy import sparse

A = np.array([[1.0, 1.0], [0.0, 1.0]])  # 状態 (位置 p, 速度 v)、刻みは1
B = np.array([[0.5], [1.0]])
Q, R = np.diag([1.0, 0.1]), 0.1
P = sl.solve_discrete_are(A, B, Q, np.array([[R]]))  # 終端コストの行列
K = (B.T @ P @ A / (R + (B.T @ P @ B)[0, 0]))[0]  # 制約なしの無限区間の利得
print(P.round(3).tolist(), K.round(4))
# [[1.528, 0.354], [0.354, 0.414]] [0.8947 1.3673]


def build(N, umax=1.0, pmin=0.0):
    """z = (x_1..x_N, u_0..u_{N-1}) を変数とする凸QP。x_0 は l, u の先頭2行にだけ入る。"""
    blocks = [Q] * (N - 1) + [P] + [np.array([[R]])] * N
    H = 2 * sparse.block_diag([sparse.csc_matrix(b) for b in blocks], format="csc")
    D = sparse.lil_matrix((2 * N, 3 * N))  # x_{k+1} - A x_k - B u_k = 0
    for k in range(N):
        D[2 * k : 2 * k + 2, 2 * k : 2 * k + 2] = np.eye(2)
        if k:
            D[2 * k : 2 * k + 2, 2 * k - 2 : 2 * k] = -A
        D[2 * k : 2 * k + 2, 2 * N + k] = -B[:, 0]
    lo = np.r_[np.zeros(2 * N), np.full(2 * N, -np.inf), np.full(N, -umax)]
    hi = np.r_[np.zeros(2 * N), np.full(2 * N, np.inf), np.full(N, umax)]
    lo[2 * N : 4 * N : 2] = pmin  # 壁: 位置 p_k >= pmin
    return H, sparse.vstack([D, sparse.eye(3 * N)], format="csc"), lo, hi


class MPC:
    def __init__(self, N, **kw):
        self.N = N
        self.H, C, self.lo, self.hi = build(N, **kw)
        self.solver = osqp.OSQP()
        self.solver.setup(P=sparse.triu(self.H, format="csc"), q=np.zeros(3 * N), A=C,
                          l=self.lo, u=self.hi, verbose=False, eps_abs=1e-7, eps_rel=1e-7,
                          polish=False, check_termination=1)

    def solve(self, x, z0=None):
        lo, hi = self.lo.copy(), self.hi.copy()
        lo[:2] = hi[:2] = A @ x  # 先頭の式 x_1 - B u_0 = A x_0 の右辺だけが状態で変わる
        self.solver.update(l=lo, u=hi)
        z0 = np.zeros(3 * self.N) if z0 is None else z0
        self.solver.warm_start(x=z0, y=np.zeros(5 * self.N))
        return self.solver.solve()


x0 = np.array([3.0, 0.0])
mpc = MPC(5)
r = mpc.solve(x0)
u, xs = r.x[10:], r.x[:10].reshape(5, 2)
print(r.info.status, r.info.iter, u.round(3))
# solved 82 [-1.    -0.542  1.     0.71  -0.229]
print(xs.round(3).tolist())
# [[2.5, -1.0], [1.229, -1.542], [0.187, -0.542], [-0.0, 0.168], [0.053, -0.062]]
print(round(r.x @ mpc.H @ r.x / 2, 3), (-K @ x0).round(3))
# 8.454 -2.684
print(MPC(3, umax=1e6, pmin=-1e9).solve(x0).x[6].round(3))
# -2.684
```

`r.x` は15個の変数、`r.info.iter` はOSQPの反復回数です。得られた計画を表にします。

| 歩 $k$ | 力 $u_{k-1}$ | 位置 $p_k$ | 速度 $v_k$ |
|---:|---:|---:|---:|
| 1 | $-1$ | $2.5$ | $-1$ |
| 2 | $-0.542$ | $1.229$ | $-1.542$ |
| 3 | $1$ | $0.187$ | $-0.542$ |
| 4 | $0.71$ | $0$ | $0.168$ |
| 5 | $-0.229$ | $0.053$ | $-0.062$ |

最初の力 $u_0=-1$ と3つ目の力 $u_2=1$ は、力の範囲の端に当たっています。4歩目の位置 $p_4=0$ は、壁に当たっています。この3か所で制約が効いているのが、この計画の特徴です。

手で確かめられる量が二つあります。一つ目は、1歩目の状態です。$p_1=3+0\cdot1+0.5\cdot(-1)=2.5$、$v_1=0+(-1)=-1$ なので、表の1行目と一致します。二つ目は、制約を外したときの最初の力です。$u_0=-Kx_0=-0.8947\cdot3=-2.684$ で、力の範囲の $-1$ より大きく外れます。そのため、この計画は上限の力で押し出します。コードの最後の行は、力の範囲と壁を外した $N=3$ のQPでも、最初の力が同じ $-2.684$ になることを示しています。

### 台車の例・最初の一手だけを使って解き直す

次のコードは、1周期ごとにQPを解き、$u_0$ だけを台車へ加えます。台車は、モデルのとおりに動くとします。

```python
def shifted(z, N, x):
    """前回の力を1つ前へずらし、今の状態から動きの式で状態を並べ直す。"""
    un = np.r_[z[2 * N + 1 :], z[-1]]
    xs, xx = [], x.copy()
    for k in range(N):
        xx = A @ xx + B[:, 0] * un[k]
        xs.append(xx)
    return np.r_[np.ravel(xs), un]


def receding(N, steps, plant_B=B, warm=False, **kw):
    mpc, x, z, log = MPC(N, **kw), x0.copy(), None, []
    for t in range(steps):
        r = mpc.solve(x, shifted(z, N, x) if warm and z is not None else None)
        if r.info.status != "solved":
            return {"failed_at": t, "x": x, "log": log}
        z = r.x
        log.append((t, x.copy(), z[2 * N], r.info.iter))
        x = A @ x + plant_B[:, 0] * z[2 * N]  # 先頭の力だけを台車へ
    cost = sum(xt @ Q @ xt + R * ut**2 for _, xt, ut, _ in log)
    return {"cost": cost, "log": log, "x_end": x}


out = receding(5, 8)
for t, x, ut, it in out["log"][:5]:
    print(t, x.round(3), round(ut, 3))  # 周期、状態、加えた力
print(round(out["cost"], 3), out["x_end"].round(3))
# 0 [3. 0.] -1.0
# 1 [ 2.5 -1. ] -0.542
# 2 [ 1.229 -1.542] 1.0
# 3 [ 0.187 -0.542] 0.71
# 4 [0.    0.168] -0.229
# 17.454 [ 0. -0.]
```

台車がモデルどおりに動くので、解き直しで得た力 $-1,\ -0.542,\ 1,\ 0.71,\ -0.229$ は、最初の計画の力と一致します。6周期目以降の力は $0.039,\ 0.023,\ 0$ と小さくなり、8歩で $(0,\ 0)$ に着きます。8歩ぶんの費用（$x^\top Qx+Ru^2$ の合計）は $17.454$ です。

### 台車の例・予測区間の長さを変える

同じ初期状態で、予測区間 $N$ を1から6まで変え、12歩の解き直しを実行します。

```python
for N in range(1, 7):
    o = receding(N, 12)
    print(N, 3 * N, f"t={o['failed_at']} {o['x'].round(3)}" if "failed_at" in o else round(o["cost"], 3))
# 1 3 t=2 [ 1.065 -1.87 ]
# 2 6 t=2 [ 1.193 -1.615]
# 3 9 17.454
# 4 12 17.454
# 5 15 17.454
# 6 18 17.454
```

| 予測区間 $N$ | 変数の数 | 12歩の結果 |
|---:|---:|---|
| 1 | 3 | 3周期目（$t=2$）でQPが実行不可能になる |
| 2 | 6 | 3周期目（$t=2$）でQPが実行不可能になる |
| 3 | 9 | 費用 $17.454$ |
| 4 | 12 | 費用 $17.454$ |
| 5 | 15 | 費用 $17.454$ |
| 6 | 18 | 費用 $17.454$ |

$N=1,\ 2$ では、最初の2周期のQPは解けるのに、3周期目に解がなくなります。そのときの状態は、$N=1$ で $(1.065,\ -1.87)$ です。壁までの距離は $1.065$ なのに、速度が $-1.87$ もあります。最大の力 $+1$ で押し戻しても、$1.065-1.87+0.5=-0.305$ と、1歩で壁を越えます。短い予測区間は、壁が近づくまで減速を始めません。$N=3$ 以上では、12歩の費用が同じです。この例では、区間を延ばしても、費用は下がりません。

比較は、1つの初期状態と1組の重みでの結果です。$N$ の大小で、手法の優劣や、実時間での性能は読み取れません。

### 台車の例・ウォームスタートの反復回数

QPを解く前に、前回の解を1歩ずらして初期値にするのがウォームスタートです。8周期の反復回数を、毎回ゼロから始める場合と比べます。

```python
cold, warm = receding(5, 8), receding(5, 8, warm=True)
print([it for *_, it in cold["log"]], sum(it for *_, it in cold["log"]))  # ゼロから
# [82, 47, 71, 50, 43, 42, 40, 31] 406
print([it for *_, it in warm["log"]], sum(it for *_, it in warm["log"]))  # ウォームスタート
# [82, 33, 65, 47, 26, 24, 35, 14] 326
print(max(np.abs(a[1] - b[1]).max() for a, b in zip(cold["log"], warm["log"])))
# 7.194430149404241e-07
```

| 周期 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 合計 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| ゼロから始める | 82 | 47 | 71 | 50 | 43 | 42 | 40 | 31 | 406 |
| ウォームスタート | 82 | 33 | 65 | 47 | 26 | 24 | 35 | 14 | 326 |

0周期目は、前回の解がないので同じ回数です。1周期目以降は、ウォームスタートのほうが、どの周期も反復が少なくなりました。2通りの状態の列は、最大で $7\times10^{-7}$ しか違わず、許容誤差の範囲で同じ軌道です。この回数は、許容誤差 $10^{-7}$ と、OSQPのこのバージョンでの値です。ソルバーの速さの比較にはなりません。

## つまずきやすい点

- **QPが解けたので、次の周期も解けると考える**: 前の節の $N=2$ は、最初の2周期でQPが解けました。ところが3周期目の状態は $(1.193,\ -1.615)$ です。最大の力で押し戻しても、位置は $0.078$、$-0.037$ と進み、2歩目に壁を越えます。この周期のQPは実行不可能で、台車に加える力が出ません。$N=3$ にすれば、同じ設定で12周期とも解けます。壁を罰則つきの柔らかい制約にすれば解は出ますが、壁を守る約束は弱まります。短い予測区間と状態の制約を組み合わせるなら、実行不可能になった周期の動作を、先に決めておきます。
- **歩の区切りで制約を守れたので、連続時間でも守れたと考える**: $N=5$ の解き直しは、12歩とも $p_k\ge0$ を満たします。区切りの時刻での位置の最小は $0$ です。ところが、4周期目（$t=3$）は状態 $(0.187,\ -0.542)$ で、力 $0.71$ を1歩の間加え続けます。その間の位置は、0.76歩目に $-0.0198$ まで下がります。区切りの時刻だけを見ていると、この越え方に気づけません。壁を $0.03$ 手前（$p\ge0.03$）にずらして解き直すと、区切りの間も位置は $0$ を下回りません（小数第4位まで）。費用は $17.454$ から $17.482$ に増えます。この余裕の量は、この例の1回の計算で決めた値で、一般の目安ではありません。
- **計画をそのまま最後まで実行すれば十分だと考える**: 台車がモデルの1.3倍強く反応するとします。$N=12$ の計画を解き直さずに実行すると、12歩後の位置は $-0.90$ で、壁を $0.90$ 越えます。毎回5歩先まで解き直すと、位置の最小は $0.019$、12歩後は $(0.023,\ -0.115)$ です。ただし、解き直しは壁を越えない保証ではありません。予測は実機より小さい力のモデルで立てます。壁のすぐ手前では、予測と実際の差が、そのまま壁を越える一歩になりえます。この例では越えなかった、という結果です。
- **ウォームスタートの回数を、MPCやソルバーの速さと読む**: 上の表で、8周期の合計は406回から326回に減りました。ただし、許容誤差を $10^{-7}$ にそろえ、この1つの初期状態から8周期を追った回数です。1周期目は、前回の解がないので減りません。目標が急に変わる周期や、有効な制約が入れ替わる周期では、ずらした解がかえって悪い初期値になることがあります。この例では、そうした周期を確かめていません。

## 課題から定式化する

「台車を壁の手前で止めたい」という課題だけでは、まだこの型とは決まりません。次の4つを順に確かめます。

1. **何を測り、何を決めるか**: 位置と速度 $x=(p,\ v)$ を測り、力 $u$ を決めます。測れない状態があるなら、状態の推定が別に必要です。
2. **動きをどう予測するか**: 力 $u$ から次の状態を出す式 $x_{k+1}=Ax_k+Bu_k$ を用意します。台車は、刻み1で厳密に離散化した $A$、$B$ です。モデルが非線形なら、次の節の別の型になります。
3. **どのずれを減らすか**: 位置と速度のずれ $x^\top Qx$、力の大きさ $Ru^2$、先の費用の近似 $x_N^\top Px_N$ の和にします。
4. **何を守り、何が毎周期変わるか**: 力の範囲 $|u|\le1$ と壁 $p\ge0$ が制約です。毎周期変わるのは、測った状態 $\hat x(t)$ だけです。

線形のモデル、二次の費用、線形の制約が揃い、状態の測定ごとに解き直すとき、この記事の型になります。

## 困りごとから関連する問題へ

実際の課題で、次の症状が出たら、対応する記事へ進めます。

- 動きの式が非線形で、毎周期の問題が凸でなくなる → [最適制御](#/formulations/PA042)と、[multiple shooting](#/learn/multiple-shooting)、[SQP](#/learn/sqp)
- 毎周期、同じ形の問題を、データだけ変えて解く費用が気になる → [反復パラメトリック最適化](#/formulations/PA053)
- 毎周期のQPそのものを、行列が変わらない形で解きたい → [凸二次計画](#/formulations/PA018)
- 解き直しの期限、ウォームスタートが効かない周期、実行できなかったときの動作を整理したい → [移動予測区間](#/learn/concept.receding-horizon)
- 100Hzで解く固定教材（状態1次元、4歩）で、周期ごとの反復とdeadlineを見たい → [100Hzで反復MPCの二次計画問題を解く事例](#/gallery/EC025)

### MPCと関連する問題の関係

- [反復パラメトリック最適化](#/formulations/PA053): MPCは、その特別な場合です。目的と制約の形は周期をまたいで同じで、測った状態 $\hat x(t)$ だけがパラメータとして変わります。台車の例では、$A$、$B$、$Q$、$R$、$P$ と制約の行列は固定で、変わるのは先頭の式の右辺 $Ax_0$ だけでした。
- [凸二次計画](#/formulations/PA018): モデルが線形で、費用が二次で、制約が線形なら、毎周期の問題は凸QPに書き直せます。台車の例が、その形です。モデルが非線形になる、費用が二次でなくなる、制約が非線形になると、凸QPではなくなります。
- [最適制御](#/formulations/PA042): 形が似ていますが、使い方が違います。最適制御は、時間全体の操作の計画を連続時間も含めて立てる問題で、MPCは、有限区間の計画を測定のたびに解き直す運用です。台車の灰の線は、12歩ぶんの計画を1回だけ立てて実行した場合にあたり、緑の線がMPCです。

## 数値計算の方法を選ぶ

どの方法も、使う情報と得られる保証が違います。毎周期の問題が凸QPかどうか、周期の期限、状態の次元で分けて考えます。

| 系統 | 使う情報 | 向く条件・避ける条件 |
|---|---|---|
| [ADMM型のQPソルバー](#/learn/admm-qp)（OSQPなど） | QPの行列と、前回の解 | 疎な凸QPで、行列が周期をまたいで変わらないときに、行列の分解を使い回せます。反復の途中で止めた解は、許容誤差の範囲でしか制約を満たしません |
| [有効集合法のQP](#/learn/active-set-qp) | QPの行列、有効な制約の候補 | 小規模で、有効な制約が周期間で安定しているときに、前回の候補から始められます。有効な制約が入れ替わる周期では、反復が増えることがあります |
| [内点法（バリア法）](#/learn/barrier-lp-qp) | QPの行列 | 精度の高い解が要るときに向きます。ウォームスタートが効きにくい方法です |
| [SQP](#/learn/sqp)、[multiple shooting](#/learn/multiple-shooting)、[iLQR/DDP](#/learn/ilqr-ddp) | 非線形モデルと、その微分 | モデルが非線形なときに使います。得られるのは局所解で、acados（S043、S076）のようなMPC向けのソフトウェアは、この系統の周期ごとの計算を速くするためのものです |

OSQPの設定値（許容誤差、`check_termination` など）は、使うソルバーの既定やこの例の選び方であり、MPC一般での推奨値ではありません。選ぶときは、毎周期の期限、QPの大きさ、行列が変わるかどうかを確かめます。

次のコードは、小さな例の計画を、別の方法で確かめ、つまずきやすい点の数値を出します。

```python
from scipy.optimize import minimize

# 別の解法（SLSQP）で、同じ最初の計画の目的値と力を確かめる
def states(uu):
    x, out = x0.copy(), []
    for k in range(5):
        x = A @ x + B[:, 0] * uu[k]
        out.append(x.copy())
    return out

def cost(uu):
    xs_ = states(uu)
    return sum(x @ Q @ x for x in xs_[:4]) + xs_[4] @ P @ xs_[4] + R * uu @ uu

cons = [{"type": "ineq", "fun": lambda uu, k=k: states(uu)[k][0]} for k in range(5)]
s = minimize(cost, np.zeros(5), method="SLSQP", bounds=[(-1, 1)] * 5, constraints=cons,
             options={"ftol": 1e-12, "maxiter": 200})
print(round(s.fun, 3), s.x.round(3))
# 8.454 [-1.    -0.542  1.     0.71  -0.229]
# 動きの式の残差
res = max(np.abs(xs[0] - (A @ x0 + B[:, 0] * u[0])).max(),
          *[np.abs(xs[k] - (A @ xs[k - 1] + B[:, 0] * u[k])).max() for k in range(1, 5)])
print(f"{res:.0e}")  # 1e-10

# 壁をなくすと、位置は壁を越える（費用は少し下がる）
free = receding(5, 12, pmin=-1e9)
print(round(free["cost"], 3), min(x[0] for _, x, _, _ in free["log"]).round(3))
# 17.403 -0.151


def min_position(o):
    """各周期の1歩の間（力は一定）の位置の最小。"""
    best = 0.0
    for _, x, ut, _ in o["log"]:
        tau = np.linspace(0, 1, 10001)
        best = min(best, (x[0] + x[1] * tau + 0.5 * ut * tau**2).min())
    return best


for pm in (0.0, 0.03):
    o = receding(5, 12, pmin=pm)
    lowest = round(min(x[0] for _, x, _, _ in o["log"]), 4)
    print(pm, round(o["cost"], 3), lowest, round(min_position(o), 4))  # 壁, 費用, 区切りの最小, 間の最小
# 0.0 17.454 -0.0 -0.0198
# 0.03 17.482 0.03 0.0

# 実機の入力の効きがモデルの1.3倍
plant = 1.3 * B
plan = MPC(12).solve(x0).x  # 12歩の計画を1回だけ立てて実行
x = x0.copy()
for k in range(12):
    x = A @ x + plant[:, 0] * plan[24 + k]
print(x.round(3))  # [-0.9 -0. ]
rm = receding(5, 12, plant_B=plant)
print(rm["x_end"].round(3), min(x[0] for _, x, _, _ in rm["log"]).round(3))
# [ 0.023 -0.115] 0.019
```

最初のSLSQPの行は、OSQPと同じ目的値 $8.454$ と同じ力を返します。2つの方法の一致は、この問題が凸で、局所解が大域解でもあることと整合します。動きの式の残差が $10^{-10}$ 程度なので、予測した状態は、モデルの式を満たします。壁をなくした行は、台車が壁を $0.151$ 越える代わりに、費用が $17.454$ から $17.403$ に下がることを示します。壁を守る代償は、$0.051$ の費用です。

`min_position` は、歩の区切りの間の位置を細かく調べます。壁を $p\ge0$ のままにすると最小が $-0.0198$ になり、$p\ge0.03$ にすると $0$ を下回りません。最後の3行は、図の灰の線の終点 $-0.9$ と、緑の線の最小 $0.019$、終点 $(0.023,\ -0.115)$ を再現します。
