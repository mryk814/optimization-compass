非常に高価な低次元評価は、1回の評価に時間や費用がかかり、試せる回数が数十回ほどしかない最小化の定式化です。式も勾配も見えないため、これまでの観測から次に試す点を選ぶ手順そのものが主題になります。

## 30秒でつかむ

レーザー加工の出力・速度・焦点位置を決める場面を考えます。
条件を1つ試すごとに試作が必要で、結果の品質は測定するまで分かりません。試作は12回までしかできません。

このとき、加工条件を数式で書くことはできません。試作の結果として、品質の悪さを表す数値が1つ返ってくるだけです。
どの条件を次に試すかで、限られた12回の価値が決まります。

- **決めるもの**: 次に試す連続値の設定（出力、速度、焦点位置など）
- **良くしたいもの**: 試作の後にだけ分かる品質損失 $F(x)$
- **守ること**: 各設定の上下限と、試作回数の予算

## 標準形を読む

この型は、箱の中の1点を選び、評価が高価なブラックボックスの値を最小にする問題です。

$$
\min_{x\in[\ell,u]}\; F(x),\quad \text{1回の評価が高価},\; n \text{ は小さい}
$$

| 記号 | 意味 |
|---|---|
| $x$ | 決める設定のベクトル。$n$ 個の連続値 |
| $[\ell,u]$ | 設定ごとの下限と上限。装置や安全の範囲 |
| $F(x)$ | 評価。$x$ を渡すと値だけが返る。式も勾配も使えない |
| $n$ | 設定の数。数個から十数個までの小さい値 |

式に書かれない条件が、この型の本体です。評価の回数 $N$ が、数十回ほどに限られています。
勾配を数値微分で求めようとすると、1回の勾配だけで $n$ 回の追加評価が要ります。予算がすぐ尽きるので、この方法は選べません。

この型では、評価の記録を残すことが手法の一部になります。1回ごとに、入力 $x$ と値と費用と成否を台帳へ書きます。書き方は[評価費と予算](#/learn/concept.evaluation-cost)にあります。

ライブラリによって、最小化を標準にするものと、最大化を標準にするものがあります。品質損失と品質スコアのどちらを渡しているかを、符号も含めて確かめます。

## 小さな例

公開事例『高価な製造実験から工程条件を探す』の教材と同じ、1次元の関数を使います。

$$
F(x)=0.16(x-1.7)^2+0.45\sin(2.2x)+0.12\sin(5.3x),\qquad x\in[-3,3]
$$

実際の工程では、この式は見えません。ここでは答え合わせのために、式を関数として持っています。
密な格子で調べると、最小は $x\approx2.079$、値は $-0.5427$ です。

評価を10回まで、と決めます。次の3通りで、10回の評価が終わったときの最良値を比べます。

| 選び方 | 10回後の最良値 |
|---|---:|
| 等間隔に10点 | $-0.3703$ |
| 一様乱数で10点（2000回くり返した中央値） | $-0.4375$ |
| ガウス過程で次の点を選ぶ | $-0.5378$ |

最後の方法は、最初の3回を $x=-3,\,0,\,3$ で評価します。その後は、これまでの観測から予測と不確実性を作り、下側信頼限界が最小の点を次に評価します。

### 読み取り: 評価の履歴を読む

10回の評価は次のとおりです。

| 回 | $x$ | $F(x)$ | それまでの最良値 |
|---:|---:|---:|---:|
| 1 | $-3.00$ | $3.4171$ | $3.4171$ |
| 2 | $0.00$ | $0.4624$ | $0.4624$ |
| 3 | $3.00$ | $0.3877$ | $0.3877$ |
| 4 | $2.12$ | $-0.5378$ | $-0.5378$ |
| 5 | $1.30$ | $0.2191$ | $-0.5378$ |
| 6 | $-1.11$ | $1.0204$ | $-0.5378$ |
| 7 | $2.46$ | $-0.1974$ | $-0.5378$ |
| 8 | $0.60$ | $0.6249$ | $-0.5378$ |
| 9 | $1.83$ | $-0.3779$ | $-0.5378$ |
| 10 | $-1.86$ | $2.4443$ | $-0.5378$ |

最良値は4回目で決まり、正解の $-0.5427$ に近い値です。5回目以降に最良値は更新されていません。
それでも、これらの評価に意味がないわけではありません。まだ測っていない場所に、もっと良い点がないかを確かめています。ただし、確かめた結果としても、大域的に最小だという証明にはなりません。

予算を15回に増やすと、方法の差は縮みます。等間隔は $-0.5309$ で、乱数の中央値は $-0.4941$ です。ガウス過程は $-0.5427$ です。
この数値は、1つの1次元の関数と、指定したカーネルの幅と信頼限界の係数に対する結果です。方法の一般的な優劣を示すものではありません。

### 事例との対応

公開事例には、次の3件があります。

- 『少ない試作でレーザー加工条件を絞る』：試作は12回まで
- 『少ない実験で配合条件を絞る』：実験は12回まで
- 『高価な製造実験から工程条件を探す』：試作は10回まで

いずれも、実際は複数の設定が並ぶ問題を、教材では1次元の代理変数に縮めています。実問題の設定数は $n>1$ で、答え合わせの式もありません。
『低／高評価精度シミュレータを予算内で使い分ける』は、精度の違う評価を使い分ける発展形で、評価ごとの費用が異なります。

## 見分け方

次の兆候があれば、この型を疑います。

- 1回の実験や計算に、数分から数日かかる
- 試せる回数が、数十回ほどに限られている
- 評価の中身が見えず、値だけが返る。勾配は得られない
- 設定の数が、数個から十数個までである

別の型へ向かう兆候もあります。

- 評価が安く、数万回試せる → 集団を使う探索や局所探索が選べます。導入は[微分なし最適化](#/learn/concept.derivative-free)
- 設定の数が数十以上に増える → [高次元のブラックボックス（PA015）](#/formulations/PA015)
- 同じ点を測っても値がばらつく → [ノイズを含むブラックボックス（PA013）](#/formulations/PA013)
- 評価が失敗したり、NaN を返したりする → [失敗・NaNを伴うシミュレーション（PA016）](#/formulations/PA016)
- 手法の設定（学習率など）を調整する → [ハイパーパラメータ最適化（PA039）](#/formulations/PA039)
- 評価が安価で、勾配も得られる → 滑らかな最適化の型（[PA006](#/formulations/PA006)）

## 近い定式化

- **高次元ブラックボックス（PA015）**: 評価が高価でも、低次元なら代理モデルが観測から形を学べます。設定の数が増えると、代理モデルを作ること自体が難しくなります。
- **ハイパーパラメータ最適化（PA039）**: 検証損失を高価なブラックボックスとして扱えば、この型で書けます。条件が付きます。探索空間が連続で低次元であること、1回の学習が高価なことです。カテゴリや条件付きの設定が中心なら、別の手法が候補になります。
- **失敗・NaNを伴うシミュレーション（PA016）とノイズを含む評価（PA013）**: 高価な評価に、失敗やばらつきが加わった型です。値がないことと、悪い値が返ることを区別します。

## 解き方の系統

- **代理モデルを使う逐次法（ベイズ最適化）**: 観測から予測と不確実性を作り、次の点を選びます。評価の回数が少ない問題に向きます。得られるのは「有望な候補」であり、大域最適の証明ではありません。詳しくは[ベイズ最適化](#/learn/bayesian-optimization)にあります。
- **高次元への拡張（TuRBO、SAASBO）**: 設定の数が増えたときの拡張です。TuRBO は探索領域を絞り、SAASBO は少数の設定だけが効くと仮定します。[高次元の局所ベイズ最適化](#/learn/turbo-saasbo)にあります。
- **箱を分割する方法（DIRECT）**: 探索する箱を細かく分けていき、評価点の並びが乱数によらず決まります。低次元で、目的関数が決定的なときに向きます。[DIRECT](#/learn/direct-global)にあります。
- **集団を使う方法（CMA-ES、差分進化）**: 1世代で複数の点を評価します。評価が高価で予算が数十回だと、世代を重ねる余地が小さくなります。この型では、代理モデルや箱の分割を先に検討します。
- **基準線**: 等間隔と一様乱数は、必ず並べます。[Random Search](#/learn/random-search)が、どの程度まで良い値を出すかが分かります。

次のコードは、上の3通りの選び方と、DIRECT の結果を並べます。`scipy.optimize.direct` は SciPy 1.9 以降にあります。

```python
import numpy as np
from scipy.optimize import direct


def f(x):
    """1回が高価な評価を、閉じた式で代用した教材用の目的関数"""
    x = np.asarray(x, dtype=float)
    return 0.16 * (x - 1.7) ** 2 + 0.45 * np.sin(2.2 * x) + 0.12 * np.sin(5.3 * x)


lo, hi = -3.0, 3.0

# 答え合わせ用。実際の問題では、これほど評価できない
dense = np.linspace(lo, hi, 60001)
print("answer key:", round(dense[f(dense).argmin()], 3), round(f(dense).min(), 4))


def rbf(a, b, length=0.6):
    return np.exp(-0.5 * (a[:, None] - b[None, :]) ** 2 / length**2)


def gp_lcb(budget):
    """Gaussian process と下側信頼限界で、次の1点を選びながら budget 回評価する"""
    xs = np.array([lo, 0.0, hi])  # 最初の3回
    ys = f(xs)
    candidates = np.linspace(lo, hi, 601)
    while len(xs) < budget:
        z = (ys - ys.mean()) / ys.std()  # 平均0・分散1に直す
        kernel = rbf(xs, xs) + 1e-6 * np.eye(len(xs))
        cross = rbf(candidates, xs)
        mean = cross @ np.linalg.solve(kernel, z)
        var = 1.0 - np.sum(cross * np.linalg.solve(kernel, cross.T).T, axis=1)
        lcb = mean - 2.0 * np.sqrt(np.maximum(var, 1e-12))
        x_next = candidates[lcb.argmin()]
        xs, ys = np.append(xs, x_next), np.append(ys, f(x_next))
    return xs, ys


rng = np.random.default_rng(0)
for budget in (10, 15):
    grid = f(np.linspace(lo, hi, budget)).min()
    rand = np.median([f(rng.uniform(lo, hi, budget)).min() for _ in range(2000)])
    best = gp_lcb(budget)[1].min()
    print(f"budget {budget}: grid={grid:.4f} random(median)={rand:.4f} gp-lcb={best:.4f}")

xs, ys = gp_lcb(10)
for k, (x, y) in enumerate(zip(xs, ys), start=1):
    print(f"eval {k:2d}: x={x:5.2f} F={y:7.4f} best-so-far={ys[:k].min():7.4f}")

# scipy の DIRECT。maxfun は評価回数の厳密な上限ではない
calls = []


def counted(x):
    calls.append(x[0])
    return float(f(x[0]))


result = direct(counted, [(lo, hi)], maxfun=10)
print(f"DIRECT: maxfun=10, used={len(calls)}, best={result.fun:.4f} at x={result.x[0]:.3f}")
```

budget 15: grid=-0.5309 random(median)=-0.4941 gp-lcb=-0.5427
eval  1: x=-3.00 F= 3.4171 best-so-far= 3.4171
eval  2: x= 0.00 F= 0.4624 best-so-far= 0.4624
eval  3: x= 3.00 F= 0.3877 best-so-far= 0.3877
eval  4: x= 2.12 F=-0.5378 best-so-far=-0.5378
eval  5: x= 1.30 F= 0.2191 best-so-far=-0.5378

最後の行に注目します。`maxfun=10` を指定しても、DIRECT は15回の評価を使いました。予算が厳しい問題では、この差を見過ごせません。
DIRECT の15回と、上の表の10回は予算が違うので、値を横に並べて優劣を決めることはできません。

## つまずきやすい点

- **最良値を最適と読む**: 実際の問題には答え合わせがありません。10回後の最良値が $-0.5378$ でも、それが最小だと知る方法はありません。未探索の領域と不確実性を、台帳と一緒に報告します。
- **失敗した評価を大きな値で置き換える**: 落ちた試作に「悪い値」を入れると、代理モデルがその周辺を必要以上に避けます。値は欠測のまま、成否と消費した予算だけを記録します。
- **予算を守れない手法がある**: 上のDIRECTのように、指定した回数を超えて評価した例があります。予算は、評価を呼ぶ側で数えて止めます。
- **設定の尺度がそろっていない**: 温度が200〜400、速度が0.1〜0.5のように尺度が違うと、全方向に同じ幅を使うカーネルは片方に偏ります。各設定を0から1へそろえてから渡します。
- **基準線がない**: 「ベイズ最適化が良かった」という判断には、同じ予算の等間隔と乱数の結果が要ります。上の例でも、予算15では等間隔が乱数の中央値を上回りました。
- **初期点の影響を確かめない**: 最初の3点を $(-2,0,2)$ に変えると、10回後の最良値は $-0.5246$ になりました。$(-1.5,0.5,2.5)$ では $-0.5416$ です。初期点を変えて再実行し、ばらつきを見ます。
