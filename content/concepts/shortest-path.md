最短路問題は、点と向きのある道でできた網で、始点から終点までの経路を一本選びます。通る道の重み（時間や費用）の合計を最小にする定式化です。重みがすべて非負ならDijkstra法で解け、負の重みがあっても負閉路がなければBellman–Ford法で解けます。供給が1単位で容量のない最小費用流としても書けます。

## 30秒でつかむ

配送の拠点Sから客先Tへ、バンが向かいます。途中に交差点A・B・Cがあり、一方通行の道が7本あります。道ごとの所要時間（分）は次のとおりです。

| 道 | 所要時間 |
|---|---:|
| S→A | 2 |
| S→B | 4 |
| S→T | 12 |
| A→B | 5 |
| A→T | 6 |
| B→C | 1 |
| C→T | 2 |

経路の選び方は一つではありません。道の数が最も少ないのはSからTへの直行ですが、12分かかります。最初の道が最も速いのはS→Aの2分ですが、その先でどれだけかかるかは、たどってみないと分かりません。

- **決めるもの**: 7本の道のうち、どれを通るか。SからTまで一続きになる経路を一本選ぶ
- **良くしたいもの**: 通る道の所要時間の合計
- **守ること**: Sから出てTに着くこと。途中の点では、入った道の次に出る道があること

次の図は、同じ7本の道で3通りの選び方を比べたものです。まず道路網の図で、太い橙の道をSからたどり、各点の下の「d=」の値を読んでください。続いて、図の「道の数が最少」「次の道が最安」「合計が最小」の3行で、各行の分数を比べてください。

![拠点Sから客先Tへ向かう一方通行の7本の道の図。S→A 2・S→B 4・S→T 12・A→B 5・A→T 6・B→C 1・C→T 2（分）。各点のdはSからの最短時間で、Aが2・Bが4・Cが5・Tが7。道の数が最少の選び方はS→Tで12分、次の道が最安の選び方はS→A→B→C→Tで10分、合計が最小の選び方はS→B→C→Tで7分。](./figures/shortest-path-routes.svg "拠点Sから客先Tへ：辺の数字は所要時間（分）、dはSからの最短時間。時間は教材用の値で、実際の道路網や手法の速さは表さない")

1. 「道の数が最少」では、S→Tの1本で済みます。ただし所要時間は12分で、4通りの経路のうち最長です。
2. 「次の道が最安」では、Sで最も速いS→A（2分）を選び、Aで最も速いA→B（5分。A→Tは6分）を選び、B→C→Tへ進みます。合計は $2+5+1+2=10$ 分です。
3. 「合計が最小」のS→B→C→Tでは、最初の道S→Bが4分で、S→Aより2分遅くなります。それでも合計は $4+1+2=7$ 分で、10分より3分短くなります。
4. 太い道の上では、dが道の時間ぶんだけ増えます。Bの4にB→Cの1を足すとCの5、さらにC→Tの2を足すとTの7です。Aのdは2ですが、Aを通る経路はTまで最短にならないので、太い道に入っていません。

一本ずつ選ぶ方法では7分に届かず、各点のdを使うと7分が出てきました。dは何を表し、どう求めるのでしょうか。

## 標準形を読む

次の式は「始点から終点までの経路を選び、通る道の重みの合計を最小にする」を表します。

$$
\min_{P:\,s\to t}\; \sum_{(i,j)\in P} c_{ij}
$$

この式は「点 $s$ から点 $t$ へ着く経路 $P$ のうち、$P$ が通る道 $(i,j)$ の重み $c_{ij}$ を足した値が最小のもの」と読みます。

| 記号 | 意味 | 例では |
|---|---|---|
| $s,\,t$ | 始点と終点 | 拠点Sと客先T |
| $c_{ij}$ | 道 $(i,j)$ の重み（時間・費用・距離） | 所要時間。S→Bは4、B→Cは1 |
| $P$ | $s$ から $t$ への経路（決めるもの） | 最適ではS→B→C→T |
| $d_i$ | $s$ から点 $i$ までの最短の合計 | $d_A=2$、$d_B=4$、$d_C=5$、$d_T=7$ |

### 点ごとの最短値で、経路の合計を段階に分ける

経路は選び方が組み合わせで増えますが、点ごとの最短値 $d_i$ を使うと、一つの式に分けられます。

$$
d_j=\min_{(i,j)\in E}\bigl(d_i+c_{ij}\bigr),\qquad d_s=0
$$

この式は「点 $j$ に着く最短の合計は、$j$ に入る道ごとに『手前の点の最短値＋その道の重み』を計算した最小値」と読みます。この式が成り立つのは、始点から行ける範囲に負閉路がない網です。負閉路とは、重みの合計が負になる閉路です。負閉路があると、周回するたびに合計が減り、最短値が決まりません。

最適性の条件も同じ形です。どの道 $(i,j)$ でも $d_i+c_{ij}\ge d_j$ が成り立ち、最短路の上の道では等号になります。右辺との差を、この記事では道の余裕と呼びます。余裕が0の道だけをたどると、最短路が見つかります。

### 容量のない最小費用流としての形

同じ問題を、道ごとに流す量 $x_{ij}\ge0$ を選ぶ形でも書けます。始点から1単位を出し、終点で1単位を受け取り、途中の点では入る量と出る量を等しくします。

$$
\min_{x\ge0}\; \sum_{(i,j)} c_{ij}x_{ij} \quad \text{s.t.} \quad \sum_{j} x_{ij}-\sum_{j} x_{ji}=b_i,\quad b_s=1,\; b_t=-1,\; b_i=0\;(i\ne s,t)
$$

[ネットワークフロー（PA028）](#/formulations/PA028)で、供給を1単位にし、容量の上限を外した場合です。この形の係数行列は、PA028と同じ性質を持ちます。そのため、整数条件を付けなくても、$x_{ij}$ は0か1で返ります。

### ソルバーごとの書き方の違い

グラフ専用のライブラリは、道の一覧と始点・終点を受け取り、経路を返します。一般の線形計画ソルバーには、上の保存則を等式制約の行列として自分で組み立てます。どちらも同じ問題で、例の答えは7分です。

## 小さな例

設定は「30秒でつかむ」の表のとおりです。始点はS、終点はTで、乱数は使いません。

### 7本の道の例・点ごとに最短値を求める

どの道もSからTへ向かう向きにしか走っていないので、S・A・B・C・Tの順に、各点の $d$ を一度ずつ求めれば足ります。点ごとに、入る道から候補を作り、最小のものを選びます。

| 点 | 入る道ごとの候補 | $d$ | 最短の入り道 |
|---|---|---:|---|
| S | 始点 | 0 | なし |
| A | S→A: $0+2$ | 2 | S→A |
| B | S→B: $0+4=4$、A→B: $2+5=7$ | 4 | S→B |
| C | B→C: $4+1$ | 5 | B→C |
| T | S→T: $0+12=12$、A→T: $2+6=8$、C→T: $5+2=7$ | 7 | C→T |

Tから最短の入り道をさかのぼると、T←C←B←Sで、経路はS→B→C→Tです。Aまでの最短値は2ですが、Aの先のA→BとA→Tはどちらも他の候補に負けます。そのため、Aは最短路に入りません。経路は全部で4通りあり、合計は7・8・10・12分です。

### 7本の道の例・Dijkstra法で解く

Dijkstra法は、暫定値が最小の点を一つ取り出して確定し、その点から出る道で隣の暫定値を更新します。更新するのは、新しい値が小さいときだけです。

| 順 | 確定する点 | $d$ | 更新 |
|---:|---|---:|---|
| 1 | S | 0 | A=2、B=4、T=12 |
| 2 | A | 2 | Bは $2+5=7$ で4より大きいので据え置き。T=8 |
| 3 | B | 4 | C=5 |
| 4 | C | 5 | T=7 |
| 5 | T | 7 | 終了 |

確定した順はS・A・B・C・Tで、各点の値は上の表と一致します。順2でTの暫定値は12から8に、順4で8から7に下がりました。確定するまで暫定値であることが、この表から読めます。確定した値が後から変わらないのは、重みがすべて非負のときです。この条件が外れる例は「つまずきやすい点」で示します。

### 読み取り: 各道の余裕

最短値 $d$ を使って、道ごとの余裕 $d_i+c_{ij}-d_j$ を計算します。

| 道 | $d_i+c_{ij}-d_j$ | 読み方 |
|---|---:|---|
| S→A | $0+2-2=0$ | 最短値を与える道 |
| S→B | $0+4-4=0$ | 最短値を与える道 |
| S→T | $0+12-7=5$ | 直行は最短より5分長い |
| A→B | $2+5-4=3$ | Aを経由すると3分長い |
| A→T | $2+6-7=1$ | Aから直接着くと1分長い |
| B→C | $4+1-5=0$ | 最短値を与える道 |
| C→T | $5+2-7=0$ | 最短値を与える道 |

余裕はすべて0以上です。余裕が0の道は、S→A・S→B・B→C・C→Tの4本です。Sからこの4本だけをたどると、S→Aの先では進めず、S→B→C→Tだけが終点に届きます。Aは余裕0の道が1本入るだけで、出る道が両方とも余裕が正だからです。

## 見分け方

次の言葉が課題に出てきたら、この型を疑います。

- 地点を結ぶ道の中から、最短・最安・最速の一本を選ぶ
- 道ごとに時間・距離・費用が決まっていて、経路の合計で比べる
- 経路の途中で選べるのは、次にどの道へ進むかだけ

別の型へ進む兆候は、困りごとから探せます。

- 道に容量があり、複数の荷物を同時に流す → [ネットワークフロー（PA028）](#/formulations/PA028)。複数の荷物が同じ道を取り合うなら、一本の最短路だけでは足りません
- 顧客を1軒ずつ回って戻る順番を決めたい → [配送経路問題（PA031）](#/formulations/PA031)
- 人と仕事を1対1で組み合わせたい → [割当・matching（PA030）](#/formulations/PA030)
- 通れる道の本数や時間窓のような条件が経路全体に付く → [混合整数線形計画（PA023）](#/formulations/PA023)。状態を増やす方法は、「つまずきやすい点」の最後の項目で示します
- 道の重みに負の値がある → 解き方の系統の表で、使える方法の条件を確かめます

## 近い定式化

- **ネットワークフロー（PA028）の特別な場合です**: 供給が1単位で、容量の上限がなければ、最小費用流は最短路になります。分かれ目は、容量のある道に複数単位を流すかどうかです。最短路は1単位を一本の経路で運ぶので、道が混み合うことを式に入れる必要がありません。容量付きの最小費用流の解き方は、PA028の記事で読めます。
- **配送経路問題（PA031）とは別の型です**: 一本の最短路は、道の重みから多項式時間で解ける形です。複数の顧客を1回ずつ回る巡回路は、最短路を並べても解けず、訪問順と割当を同時に決めます。例で、客先Tのほかに通るべき地点が増えると、最短値の表だけでは答えが決まらなくなります。
- **整数計画（PA023）の形でも書けます**: 経路上の道を0-1の変数で選ぶ形にして、道の本数や時間窓の条件を足せます。ただし、条件を足すと、係数行列の整数の答えが出る性質が失われることがあります。

## 解き方の系統

次の表は、条件に合う方法を探すためのものです。速さの順位ではなく、使える条件の違いを示します。

| 系統 | 進み方 | 成り立つ条件 | 例での様子 |
|---|---|---|---|
| [Dijkstra法](#/learn/dijkstra-astar) | 暫定値が最小の点を確定し、隣を更新する | 重みがすべて非負 | S、A、B、C、Tの順に確定する |
| Bellman–Ford法 | 全部の道を、更新がなくなるまで繰り返し見直す | 負の重みも可。始点から行ける負閉路がないこと（あれば検出できる） | 道を表の順に見ると、1巡目で全点が決まり、2巡目は更新がない |
| 閉路のない網の一巡 | 点を前から後ろへの順に並べ、$d$ を一度ずつ求める | 網に閉路がない（負の重みも可） | S、A、B、C、Tの順に5点を一度ずつ見る |
| [動的計画法](#/learn/dynamic-programming)の見方 | $d_j$ の式を、状態を増やして解く | 状態の数が数え上げられる | 「つまずきやすい点」で、点と使った本数を状態にする |
| 線形計画 | 流れの形で等式制約にして解く | 供給が1単位、容量の上限なし | SciPyの `linprog`（HiGHS）が、整数条件なしで0か1の流量を返す |

次のコードは、例の経路を数え上げ、3通りの方法で解きます。解く方法はDijkstra法・Bellman–Ford法・`linprog` です。重みや道を変えた場合も計算します。

```python
import heapq

from scipy.optimize import linprog

nodes = ["S", "A", "B", "C", "T"]
# (始点, 終点): 所要時間（分）。道は一方通行
minutes = {
    ("S", "A"): 2,
    ("S", "B"): 4,
    ("S", "T"): 12,
    ("A", "B"): 5,
    ("A", "T"): 6,
    ("B", "C"): 1,
    ("C", "T"): 2,
}


def routes(node="S", seen=("S",)):
    """Sから同じ点を通らずにTへ着く経路を、すべて数え上げる"""
    if node == "T":
        return [seen]
    found = []
    for tail, head in minutes:
        if tail == node and head not in seen:
            found += routes(head, seen + (head,))
    return found


def total(route, arcs=minutes):
    return sum(arcs[edge] for edge in zip(route, route[1:]))


for route in sorted(routes(), key=total):
    print("→".join(route), total(route))
# S→B→C→T 7
# S→A→T 8
# S→A→B→C→T 10
# S→T 12

# 各点で、いま一番安い道を選び続ける（確定した後は戻らない）
here, greedy = "S", ["S"]
while here != "T":
    here = min((v for u, v in minutes if u == here), key=lambda v: minutes[greedy[-1], v])
    greedy.append(here)
print("→".join(greedy), total(greedy))  # S→A→B→C→T 10


def dijkstra(arcs):
    """暫定距離が最小の点を確定し、そこから出る道で隣の暫定距離を更新する"""
    dist, queue, done = {"S": 0}, [(0, "S")], []
    while queue:
        d, node = heapq.heappop(queue)
        if node in done:
            continue
        done.append(node)  # この時点で d を最終値として扱う
        for (tail, head), weight in arcs.items():
            if tail == node and head not in done and d + weight < dist.get(head, 10**9):
                dist[head] = d + weight
                heapq.heappush(queue, (dist[head], head))
    return {n: dist[n] for n in done}, done


dist, order = dijkstra(minutes)
print(order, dist)  # ['S', 'A', 'B', 'C', 'T'] {'S': 0, 'A': 2, 'B': 4, 'C': 5, 'T': 7}

# 最適性の条件: どの道でも d(始点)+時間-d(終点) >= 0。最短路の道では 0
slack = {f"{u}→{v}": dist[u] + w - dist[v] for (u, v), w in minutes.items()}
print(slack)  # {'S→A': 0, 'S→B': 0, 'S→T': 5, 'A→B': 3, 'A→T': 1, 'B→C': 0, 'C→T': 0}


def bellman_ford(arcs):
    """全部の道を n 回まで見直す。n 回目にも更新があれば負閉路"""
    dist = {n: float("inf") for n in nodes}
    dist["S"] = 0
    for _ in range(len(nodes)):
        changed = False
        for (tail, head), weight in arcs.items():
            if dist[tail] + weight < dist[head]:
                dist[head], changed = dist[tail] + weight, True
        if not changed:
            return dist
    return "negative cycle"


def flow_form(arcs):
    """1単位をSからTへ流す線形計画（容量の上限なし）"""
    keys = list(arcs)
    supply = {"S": 1, "A": 0, "B": 0, "C": 0, "T": -1}
    rows = [[(u == n) - (v == n) for u, v in keys] for n in nodes]
    return linprog(
        [arcs[k] for k in keys],
        A_eq=rows,
        b_eq=[supply[n] for n in nodes],
        bounds=(0, None),
        method="highs",
    )


res = flow_form(minutes)
print(res.fun, [round(f) for f in res.x])  # 7.0 [0, 1, 0, 0, 0, 1, 1]

# 負の時間: S→Aを5分、A→Bを-3分にする
neg = {**minutes, ("S", "A"): 5, ("A", "B"): -3}
print(dijkstra(neg))  # ({'S': 0, 'B': 4, 'A': 5, 'C': 5, 'T': 7}, ['S', 'B', 'A', 'C', 'T'])
print(bellman_ford(neg)["T"], flow_form(neg).fun)  # 5 5.0

# 負閉路: C→Aを-7分で足す（A→B→C→Aの合計は 5+1-7=-1）
loop = {**minutes, ("C", "A"): -7}
print(bellman_ford(loop), flow_form(loop).status)  # negative cycle 3


def with_road_limit(limit):
    """通れる道を limit 本までにする。状態は（点, 使った本数）"""
    best = {"S": 0}
    for _ in range(limit):
        step = dict(best)
        for (tail, head), weight in minutes.items():
            if tail in best and best[tail] + weight < step.get(head, 10**9):
                step[head] = best[tail] + weight
        best = step
    return best["T"]


print([with_road_limit(k) for k in (1, 2, 3)])  # [12, 8, 7]
```

最初の出力は、4通りの経路と合計です。7分のS→B→C→Tが唯一の最短路で、「次の道が最安」の規則が選ぶ10分の経路との差が3分です。`dijkstra` の確定順と値は、小さな例の表と一致します。`slack` は、道ごとの余裕で、0の道がS→A・S→B・B→C・C→Tの4本です。

`flow_form` の出力7.0は、費用の最小値です。流量の並びは `minutes` の順で、S→B・B→C・C→Tの3本だけが1です。整数条件を付けていないのに、0か1の流量が返ります。`status` は、`linprog` が返す終了の種類で、3は「非有界」です。次の節の負閉路の例で、この3が現れます。

## つまずきやすい点

- **各点で最も速い道を選び続ける**: 例では、Sで最安のS→A（2分）を選び、Aで最安のA→B（5分）を選びます。すると、S→A→B→C→Tの10分になります。最短の7分より3分長く、最初の道を一つ変えるだけで差が出ます。一歩先の値で決めず、dで比べます。
- **道の数が最少の経路を最短だと考える**: 例で道の数が最少のS→Tは12分で、4通りの経路のうち最長です。重みは道の数ではなく、道ごとの値の合計です。道の数を数えたいなら、すべての重みを1にして解き直します。
- **負の重みがあっても、Dijkstra法で確定した値が使える**: S→Aを5分、A→Bを-3分に変えます。Dijkstra法は、Sの次にBを確定し、Tを7分と返します。ところが、S→A→B→C→Tは $5-3+1+2=5$ 分です。Bはいったん4で確定した後に、Aを経由して2になる道があり、確定した値が下がります。Bellman–Ford法と `linprog` は、どちらも5を返します。負の重みがあるときは、Dijkstra法を使わないでください。
- **負閉路があっても、答えが一つ決まる**: C→Aを-7分で足すと、A→B→C→Aの合計が $5+1-7=-1$ になります。一周するたびに1分減るので、最短の時間は決まりません。Bellman–Ford法は、道を見直す5回目にも更新があり、負閉路を報告します。`linprog` の状態は3（非有界）です。容量のない形では、周回の流量にも上限がないからです。容量のある最小費用流なら、周回の流量が容量で抑えられるので、この問題は起きません。負の重みを含むデータなら、解く前に負閉路の有無を確かめます。
- **点ごとの最短値だけで、経路全体の条件も扱える**: 通る道を2本までにすると、答えは変わります。点ごとの $d$ をそのまま使うと、最短路S→B→C→Tは道が3本なので、条件を破ります。条件を守る最短は、S→A→Tの8分です。状態を（点, 使った本数）に増やすと、道を1本・2本・3本まで許した最短値が12・8・7分と求まります。本数のような経路全体の条件は、状態を増やすか、[混合整数線形計画（PA023）](#/formulations/PA023)で解きます。

## 出典と再現条件

最短路の標準形と最適性の条件は、Ahuja・Magnanti・Orlinの教科書『Network Flows』（S144）に基づきます。条件とは、どの道でも $d_i+c_{ij}\ge d_j$ が成り立つことです。Dijkstra法が使える非負の重みという条件と、負閉路の扱いも、同じ教科書（S144）にあります。閉路のない網で一巡して解く方法も同様です。同じ教科書に、最短路と最小費用流・線形計画との関係、整数の答えが出る性質もあります。最短路の動的計画法による定式化は、Bellmanの論文（S140）に基づきます。問題型としての位置づけは、NEOS Guideの問題型の解説（S054）に基づきます。`linprog` と HiGHS の使い方は、SciPyの公式文書（S004）とHiGHSの公式文書（S016）に基づきます。

例の数値は、SciPy 1.18.1 の `linprog`（`method="highs"`）と、上のコードで再現できます。Bellman–Ford法の「n回目にも更新があれば負閉路」は、点の数を $n$ として、始点から行ける負閉路の検出に使う標準の結果です。時間は教材用の値で、実際の道路網の規模や、手法ごとの速さは示しません。
