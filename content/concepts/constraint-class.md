制約分類は、解として許される領域をどの式・論理・シミュレーションで定めるかを表し、可行性の扱いとソルバー選択を左右します。

## 目的値が良くても、可行でなければ候補解ではない

最小化問題では目的`f(x)`を小さくしたくなりますが、`x`が許容領域に入っていることは別の条件です。たとえば温度を下げるほど目的が改善しても、装置の下限温度を破れば実行できません。制約はこの「実行できる範囲」を定義します。

一般には、上下限／等式／不等式を次のように書きます。

$$
\min_x f(x)\quad \text{subject to}\quad l \le x \le u,\; g(x) \le 0,\; h(x) = 0.
$$

式の形だけでなく、制約を評価できる情報も重要です。

1. `g(x)`の値を候補ごとに計算できるか
2. ヤコビアンを滑らかに計算できるか
3. ブール論理として判定するか
4. シミュレーションが失敗した後で初めて違反が分かるか

この違いが、使える手法と診断値を変えます。

## よくある分類と診断値

| 分類 | 例 | 解法側で読む量 |
| --- | --- | --- |
| 上下限 | 温度、濃度、設計範囲 | 各変数の下限・上限、有効な上下限制約 |
| 線形制約 | 予算、質量保存、容量 | 余裕量、双対、線形緩和の界 |
| 滑らかな非線形制約 | 応力、反応速度、幾何条件 | 制約値、ヤコビアン、KKT残差 |
| 等式・動力学 | 収支、状態方程式、ODE | 残差、初期・終端条件、積分誤差 |
| 組合せ・論理制約 | 排他、順序、資源割当 | 定義域の縮小、矛盾、暫定最良解 / 最適性ギャップ |
| 暗黙の制約・評価失敗 | シミュレータ異常終了、実験失敗 | 失敗率、再試行規則、保守的な判定 |

「制約なし」も有用な分類ですが、単にまだ制約を聞いていない状態とは区別します。不明な制約は`unknown`であり、制約なしと仮定してよい根拠にはなりません。

## 制約の形をソルバーへ渡せるか

上下限や単体のように射影が安価なら、[Projected Gradient](#/learn/projected-gradient)を検討できます。
これは、一歩進んでから許容集合へ戻す方法です。

滑らかな一般制約と微分がある場合は、[制約付き非線形最適化](#/learn/family.constrained-nlp)へ進みます。
SQP／内点法／拡張Lagrange法などが候補です。

排他／台数上限／工程順序は、論理や整数として表す制約です。
連続微分可能な不等式へ無理に直さず、[離散・組合せ最適化](#/learn/family.discrete-structure)として扱う方が自然な場合があります。

罰則を目的へ足す方法は、制約違反を無視してよいという意味ではありません。係数を大きくするほど数値条件が悪くなることがあり、有限の罰則では違反が残る場合もあります。目的値と最大違反量を別々に記録します。

## 可行性の確認を仕様にする

最適化の完了条件を`success`フラグだけにしないで、問題に応じた可行性判定を書き下します。

- 不等式は最大違反量と許容誤差
- 等式は残差のノルムと単位に応じた許容誤差
- 動力学はメッシュ上の残差だけでなく、必要なら区間内の制約確認
- 論理・整数制約は丸め後ではなく、最終候補の割当で判定
- シミュレーション失敗は大きな目的値へ黙って置換せず、失敗として件数・条件・扱いを記録

非凸問題で小さいKKT残差が得られても、大域最適性の証明にはなりません。また、離散化されたモデルの可行性を、そのまま連続系・実機の安全性として読まないようにします。

::: note
制約は「ソルバーへ渡す入力」である前に、解を採用してよいかを決める仕様です。
式／単位／許容誤差／判定時点を一緒に保存すると、再現と切替がしやすくなります。
:::
