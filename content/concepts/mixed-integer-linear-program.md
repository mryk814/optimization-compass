混合整数線形計画は、線形計画の一部の変数に「整数であること」を加えた定式化です。この一条件で凸性が失われるため、緩和で得た界と見つけた解の差（gap）を詰めながら最適性を証明します。

## 30秒でつかむ

トラックを2.4台買うことはできません。倉庫を半分だけ開くこともできません。
現実の決定には、個数・台数や、する・しないのような飛び飛びの値がよく現れます。
線形計画に「この変数は整数」という条件を足した定式化が、混合整数線形計画（mixed-integer linear program, MILP）です。

- **決めるもの**: 連続の量と、整数や0-1の決定の組み合わせ
- **良くしたいもの**: 線形計画と同じく、量に比例する費用の合計
- **守ること**: 線形の制約と、一部の変数の整数条件

整数条件は一行で書けますが、問題の性質を大きく変えます。
可行な点が飛び飛びになり、「近くの点より良ければ全体でも最良」という凸の性質が成り立たなくなります。

## 標準形を読む

$$
\min_{x}\; c^\top x \quad \text{s.t.}\quad Ax\le b,\quad x_j\in\mathbb{Z}\;\;(j\in I)
$$

添字の集合 $I$ に入る変数だけが整数です。$I$ が空なら線形計画、全部なら純粋整数計画です。
0-1変数（binary）は、整数変数に $0\le x_j\le 1$ を足したものです。

0-1変数を使うと、論理的な条件を線形の式で書けます。これがMILPの表現力の源です。

| 表したいこと | 書き方 |
|---|---|
| 作るなら固定費 $f$ がかかる | $x\le M y,\; y\in\{0,1\}$、目的に $f\,y$ を足す |
| AかBのどちらか一つだけ選ぶ | $y_A+y_B=1$ |
| Aを選ぶならBも選ぶ | $y_A\le y_B$ |

$M$ は「$x$ が取り得る十分大きな上限」です。big-M と呼ばれ、値の選び方が解きやすさを左右します。

## 小さな例

次の問題を考えます。

$$
\max\; 5x_1+4x_2 \quad \text{s.t.}\quad 6x_1+4x_2\le 24,\;\; x_1+2x_2\le 6,\;\; x_1,x_2\in\mathbb{Z}_{\ge 0}
$$

整数条件を外した線形計画（LP緩和）の答えは $(3,\,1.5)$ で、目的値は $21$ です。
これを丸めてみます。$(3,2)$ は2本目の制約を破ります。$(3,1)$ は実行可能ですが、目的値は $19$ です。

整数の最適解は $(4,0)$ で、目的値は $20$ です。LP緩和の答えから離れた場所にあります。
丸めでは最適解に届かず、制約を破ることさえある点が、MILPを別の定式化として扱う理由です。

### 界と gap で進み具合を測る

LP緩和の値 $21$ は、どの整数解もこれを超えられないという上界です。
見つけた整数解の値（incumbent）が $20$ なら、最適値は $20$ と $21$ の間にあります。
この差を相対的に表したものが gap で、ここでは $(21-20)/20=5\%$ です。

分枝限定法は、$x_2\le 1$ と $x_2\ge 2$ のように変数の範囲を分けて緩和を解き直し、上界を下げていきます。
この例では、最初の緩和を含めて5個の緩和問題を解くと上界が $20$ まで下がり、gap が0になって最適性が証明されます。
時間切れで止めた場合も、gap を見れば「最適値からどれだけ離れている可能性があるか」が分かります。

## 見分け方

次の兆候があれば、MILPを考えます。

- 買う・買わない、開く・閉じる、割り当てる・割り当てないの決定がある
- 固定費、最小ロット、台数の上限がある
- 「どちらか一方」「Aならば B」のような論理条件がある

一方で、次の兆候があれば別の型が合うかもしれません。

- 変数がすべて0-1で、条件の多くが論理式 → SAT・制約programming
- 時間の区間の重なりや順序が主役 → 制約programming型scheduling
- 構造がネットワークの流れそのもの → ネットワークフロー。LPのまま整数解が得られる

## 近い定式化

- **線形計画**: 整数条件のないMILPで、MILPの緩和でもあります。MILP ソルバー（solver）の内部では、線形計画が何千回も解かれます。
- **knapsack**: 制約が1本の0-1整数計画です。動的計画法でも解けます。
- **混合整数二次計画**: 目的に凸な二次項を足した形です。
- **SAT・scheduling**: MILPで書き直せますが、専用の方法の方が自然で速いことがよくあります。

## 解き方の系統

- **分枝限定法（branch-and-bound）**: 緩和で上界（最小化なら下界）を求め、変数の範囲を分けて探索木を作ります。改善できないと分かった枝は切ります。
- **branch-and-cut**: 分枝に加えて、整数解を切り落とさずに緩和を締める制約（cut）を足します。現在の商用・OSSのMILP ソルバーの標準です。
- **CP-SAT**: 論理伝播とSAT由来の学習を組み合わせます。純粋な整数・論理・schedulingの問題で強い方法です。
- **ヒューリスティクス**: 良い整数解を早く見つけます。ソルバーの内部でも使われますが、単独では最適性を証明しません。

次の例は、上の問題を `scipy.optimize.milp`（内部はHiGHS）で解きます。

```python
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

result = milp(
    c=-np.array([5, 4]),  # 最大化を最小化に直す
    constraints=LinearConstraint([[6, 4], [1, 2]], ub=[24, 6]),
    integrality=[1, 1],  # 1 は整数変数
    bounds=Bounds(0, np.inf),
)
print(result.status, result.x, -result.fun)  # 0 [4. 0.] 20.0
```

## つまずきやすい点

- **big-M が大きすぎる**: $M$ を大きく取るほど緩和が緩くなり、上界が下がりません。数値誤差の原因にもなります。取り得る値の上限を、根拠のある最小の値にします。
- **対称性**: 同じ性能のトラックが10台あると、入れ替えただけの同じ解が大量に生まれ、探索木が膨らみます。順序を付ける制約で対称性を崩します。
- **時間切れの解を最適と読む**: 停止理由と gap を必ず記録します。gap が残っていれば、それは「実行可能な良い解」であって最適解の証明ではありません。
- **LP解の丸め**: 例で見たとおり、丸めは実行可能性も最適性も保証しません。
