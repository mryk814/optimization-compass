ツールがエラーを出す範囲と、本当にありうる値の範囲は同じではありません。ツールは、ありえない値でも黙って計算し、ありうる値で失敗することもあります。失敗した点に大きな値を返すと、その値の選び方で答えが変わります。ありうる値は自分で制約として書き、その中ではツールが必ず値を返すように直します。

## 30秒でつかむ

[ソルバーが目的関数を呼ぶ点と回数](#/learn/concept.solver-evaluation-points)と同じ、タンクの水位の例を使います。ツールは、流出口の面積 $a$（m²）と流入量 $q$（m³/s）を受け取って水位の式を解き、31回の記録とのずれの二乗和を返します。30分のうちにタンクが空になると、ツールはエラーを出します。

計算が途中で止まらないように、エラーのときは大きな値を返すことにしました。初期点 $a=q=0.0001$ から `minimize(f, x0)` の既定（BFGS）で解きます。エラーのときに返す値だけを変えて、4回解き直しました。

| エラーのときに返す値 | 止まった点の $a$ | 止まった点の $q$ | 二乗和 |
|---|---|---|---|
| 10 | $0.000401$ | $0.000500$ | $0.000503$ |
| 100 | $-0.0000112$ | $-0.000588$ | $0.923$ |
| 1000 | $0.000401$ | $0.000501$ | $0.000503$ |
| 1000000 | $0.000401$ | $0.000501$ | $0.000503$ |

100のときだけ、止まった点は $a$ も $q$ も負でした。面積が負の流出口も、水を汲み出す流入もありえません。それでも、ツールはこの点でエラーを出さず、二乗和0.923を返しています。4回とも結果の `success` は `False` で、記録に合う点で止まった回も含めて、BFGS は終了の条件を満たせていません。

- **決めるもの**: 流出口の面積 $a$ と流入量 $q$
- **良くしたいもの**: 計算した水位と記録のずれの二乗和
- **守ること**: $a\ge0$、$q\ge0$。ただし、例のツールはこの条件を知らず、タンクが空になったときだけエラーを出します

ツールのエラーは、どの点を拒み、どの点を通していたのでしょうか。

## 書いた制約、ツールのエラー、本当の要求

例には、点を拒む仕組みが三つあります。

| 仕組み | 誰が知っているか | 例では |
|---|---|---|
| 本当の要求 | 書かなければ自分だけ | $a\ge0$、$q\ge0$ |
| ツールのエラー | ツールだけ。呼んでみるまで分からない | 30分のうちにタンクが空になる $(a,q)$ |
| 書いた制約 | ソルバー。点を選ぶときに使う | `bounds` に書いた下限と上限 |

次の図は、$a$ と $q$ の平面に、本当の要求とツールのエラーを重ねたものです。

![流出口の面積 a と流入量 q（どちらも×10⁻⁴）の平面。緑の「ありうる値」は a≥0、q≥0。赤の「ツールが失敗」は、30分のうちにタンクが空になる範囲で、q≤0 の側に曲線で区切られる。q=0 の線の上でも、a が0.000251より大きい部分は赤い太線で、失敗する。どちらでもない白い範囲は「計算できるがありえない」。白抜きの丸は fmin の13回目と14回目の点で、q が負なのに計算された。×は fmin の15回目と、下限0の Nelder–Mead の15回目で、ツールが失敗した。◆は、失敗した点に100を返した BFGS の答えで、赤の範囲の境目のすぐ外にある。●は記録に合う答え。](./figures/written-constraint-plane.svg "初期点 a=q=0.0001、SciPy 1.18.1 で渡された点と、水位の式から計算した境目。教材用のタンクで、実際の設備の値は示さない")

「ありうる値」と「ツールが失敗」の二つの範囲は、ぴったり補い合ってはいません。どちらにも入らない「計算できるがありえない」範囲があり、「ありうる値」の端にも失敗する部分があります。

- $q>0$ なら、水位の式の上ではタンクは空になりません。水位は、最初の1 mと、流入と流出がつり合う高さ $(q/a)^2/(2g)$ の低い方より下がらないからです。ただし、ツールは式を数値で解くので、つり合う高さがごく低い点では失敗します。たとえば $(a,q)=(0.01,\ 0.000001)$ では、つり合う高さは $5\times10^{-10}$ m で、ツールはエラーを出しました。図の赤の範囲は、式から計算したもので、この数値の失敗は描いていません。
- $q<0$ でも、30分のうちに空にならなければ、ツールは値を返します。白抜きの丸は、`fmin` の13回目 $(0.000192,\ -0.0000144)$ と14回目 $(0.000220,\ -0.0000356)$ です。どちらもエラーにならずに計算されました。
- $q=0$ は、流入の弁を閉じた状態で、ありうる値です。それでも $a$ が $0.000251$ より大きいと、タンクは30分のうちに空になり、ツールは失敗します。図の $q=0$ の線のうち、赤の太線の部分です。

$q=0$ では、満水の1 mから空になるまでの時間 $T$（秒）が次の式で決まります。

$$
T = \frac{2}{a\sqrt{2g}}
$$

この式は「流出口が広いほど、早く空になる」と読みます。$T=1800$ になる $a$ が $0.000251$ です。赤の範囲の境目の曲線は、$q$ が負の側で、30分ちょうどで空になる $(a,q)$ を結んだものです。

## 小さな例・失敗に返した値が答えを動かす

### タンクの例・100を返したときに止まった点は境目のすぐ外

100を返したときに止まった点 $(a,q)=(-0.0000112,\ -0.000588)$ は、図の◆です。毎秒0.588 Lを汲み出し、流出口からは水位に応じて水が入る、という意味の点です。水位の式を解き直すと、30分後の水位は0.85 mmで、空になるのは約1801.5秒後です。30分を、1.5秒の差で持ちこたえています。

この点で、二乗和の勾配は次の値です。

$$
\frac{\partial F}{\partial a}=-24600,\qquad \frac{\partial F}{\partial q}=6340
$$

勾配の逆向きに進めば、二乗和はまだ下がります。ところが、その向きに長さ $10^{-6}$ だけ進むと、タンクは約1791秒で空になります。そこでツールは失敗します。計算できる範囲だけを見ると、二乗和は境目に向かって下がり続けます。そして境目の向こうでは、100が返ります。目的関数は境目で0.92から100へ跳ぶので、BFGS はその手前から進めなくなり、`success` が `False` のまま止まりました。

### タンクの例・返す値の大小と止まった点

10と1000では記録に合う答えに着き、その間の100では着きませんでした。返す値を大きくするほど安全、小さくするほど安全、という並びにはなっていません。どの値で境目の手前に止まるかは、途中の点が境目の近くをどう通ったかで決まり、前もっては分かりません。

返す値を1e10にすると、止まる点は計算機によって変わりました。計算機の違いは、NumPy が使う行列計算の部品（OpenBLAS）を切り替えて試しました。部品は SkylakeX・Haswell・Sandybridge・Prescott・Nehalem の5通りです。Haswell 以外の4通りで $q$ が負の点で止まり、その点も実行ごとに違いました。

## つまずきやすい点

- **失敗した点に大きな値を返して、そのまま解く**: 返す値が10と1000なら記録に合う答えに着き、100なら $a$ も $q$ も負の点で止まりました。どの実行も `success` は `False` です。返す値はツールにも記録にもない数なのに、それが答えを決めています。失敗が起きない範囲を制約に書き、ありうる点ではツールが値を返すように直してください。
- **ツールが値を返したら、ありうる点だと考える**: 100を返したときに止まった点は、$a$ も $q$ も負です。それでもツールは二乗和0.923を返しました。`fmin` の13回目と14回目も、負の $q$ をエラーなしで計算しています。ツールが拒むのは、計算が続けられない点だけです。ありうる値の条件は、自分で書いてソルバーに渡してください。
- **ツールが失敗する点は、ありえない点だと考える**: $q=0$ は弁を閉じた状態で、ありうる値です。それでも $a>0.000251$ ならツールは失敗します。失敗を避けるために下限を $q\ge0.00001$ にすると、流入のない場合を答えの候補から外すことになります。弁を閉じていた日の記録なら、答えの $q=0$ が下限の外に出ます。

## 本当の制約を書く

答えがありえない点に着いたり、ありうる点でツールが失敗したりしたら、次の順に直します。

1. **本当の要求を、上下限として書く**: 例では $a\ge0$、$q\ge0$ です。上限は、十分に広い流出口と流入として0.01を置きます。上下限を受け取る L-BFGS-B は、評価する点をこの範囲の中に保ちます。
2. **ありうる点では、ツールが値を返すように直す**: 弁を閉じたタンクは空になったら空のままで、流出口から水は出ません。そこで、水位の式の流出の項では、水位を $\max(h,0)$ に置き換えます。空のタンクを「エラー」ではなく「水位0の状態」として扱うわけです。こうすると $a\ge0$ かつ $q\ge0$ のどの点でも、ツールは二乗和を返します。
3. **同じ上下限で解き直す**: [前の記事](#/learn/concept.solver-evaluation-points)では、上下限 $0\le a,q\le0.01$ の L-BFGS-B が4回目に角 $(0.01,\ 0)$ を渡しました。そこでツールが失敗しています。直したツールでは、角の二乗和は5.44です。タンクは約45秒で空になり、そのあとは水位0のままだからです。L-BFGS-B は反復9回・評価60回で $(0.000401,\ 0.000501)$ に着き、`success` は `True` でした。
4. **状態で表せない失敗は、値に置き換えずに記録する**: 内側の計算が収束しない場合や時間切れのように、物理の状態では書けない失敗もあります。その記録の仕方は、[失敗・NaNを伴うシミュレーション](#/formulations/PA016)で扱います。

[ソルバーが目的関数を呼ぶ点と回数](#/learn/concept.solver-evaluation-points)で使った上下限 $0.00001\le a,q\le0.001$ も、ツールの失敗を防ぎます。$q\ge0.00001$ なら、$a\le0.001$ でもつり合う高さは $5\times10^{-6}$ m あり、ツールは値を返しました。ただし、この上下限は本当の要求より狭く、流入のない場合を外しています。

## Python

次のコードは、失敗した点に返す値を変えて解き、そのあと空のタンクを状態として扱うツールで解き直します。`# →` の行は、SciPy 1.18.1 で実行したときの出力です。タンクが空になる点では、`sqrt` の警告（`RuntimeWarning`）も出ます。

```python
import numpy as np
from scipy.integrate import solve_ivp
from scipy.optimize import minimize

G, AREA, H0 = 9.81, 1.0, 1.0  # 重力加速度、タンクの断面積 1 m²、最初の水位 1 m
t = np.arange(0, 1801, 60.0)  # 30分間、1分おきに31回測る


def simulate(a, q, rtol=1e-3, empty=False):
    # empty=True なら、水位が0のタンクからは水が出ない（空を状態として扱う）
    def rhs(_, h):
        level = max(h[0], 0.0) if empty else h[0]
        return [(q - a * np.sqrt(2 * G * level)) / AREA]

    return solve_ivp(rhs, (0, t[-1]), [H0], t_eval=t, rtol=rtol, method="Radau")


# 教材用の記録：a=0.0004、q=0.0005 の水位に、測定のばらつきを足したもの
rng = np.random.default_rng(0)
observed = simulate(4e-4, 5e-4, rtol=1e-10).y[0] + rng.normal(0, 0.005, t.size)


def tool(x):
    sol = simulate(*x)
    if sol.status != 0 or not np.all(np.isfinite(sol.y)):
        raise ValueError("タンクが空になり、水位を計算できない")
    return float(np.sum((sol.y[0] - observed) ** 2))


def penalized(big):
    # ツールが失敗した点では、二乗和の代わりに big を返す
    def f(x):
        try:
            return tool(x)
        except ValueError:
            return big

    return f


x0 = [1e-4, 1e-4]

# 1. 失敗した点に返す値だけを変えて、minimize の既定（BFGS）で解く
for big in [10, 100, 1000, 1e6]:
    res = minimize(penalized(big), x0)
    a, q = res.x
    print(f"失敗を {big:g} に: a={a:.3g}, q={q:.3g}, 二乗和={res.fun:.3g}, success={res.success}")
# → 失敗を 10 に: a=0.000401, q=0.0005, 二乗和=0.000503, success=False
# → 失敗を 100 に: a=-1.12e-05, q=-0.000588, 二乗和=0.923, success=False
# → 失敗を 1000 に: a=0.000401, q=0.000501, 二乗和=0.000503, success=False
# → 失敗を 1e+06 に: a=0.000401, q=0.000501, 二乗和=0.000503, success=False

# 2. 100 のときの答えで、水位の式を解き直す
a, q = minimize(penalized(100), x0).x
level = simulate(a, q).y[0]
print(f"30分後の水位 {level[-1] * 1000:.2f} mm")
# → 30分後の水位 0.85 mm


# 3. 空のタンクを状態として扱うツールで、a と q の下限を0にして解く
def tool_empty(x):
    sol = simulate(*x, empty=True)
    return float(np.sum((sol.y[0] - observed) ** 2))


print(f"(0.01, 0) の二乗和 {tool_empty([0.01, 0.0]):.3g}")
# → (0.01, 0) の二乗和 5.44
box = [(0, 0.01), (0, 0.01)]
res = minimize(tool_empty, x0, method="L-BFGS-B", bounds=box)
a, q = res.x
print(f"反復 {res.nit} 回, 評価 {res.nfev} 回, a={a:.3g}, q={q:.3g}, 二乗和={res.fun:.3g}")
# → 反復 9 回, 評価 60 回, a=0.000401, q=0.000501, 二乗和=0.000503
```

1の出力の $q=0.0005$ は、$0.0005004$ を3桁で表示したものです。どの行も `success=False` で、`res.message` は4回とも、精度が足りずに終了の条件を確かめられなかったことを表す `Desired error not necessarily achieved due to precision loss.` でした。2の出力の0.85 mmは、100を返したときに止まった点が、ありえない点でもツールに計算されたことを示します。3の出力の5.44は、元のツールが失敗した角でも、直したツールが値を返すことを示します。

`tool_empty` には `try` も大きな値もありません。上下限 $0\le a,q\le0.01$ の中で、元のツールが失敗した $(0.01,\ 0.000001)$ を含む49点の格子を試すと、どの点でも二乗和を返しました。この例では、上下限を守る L-BFGS-B と組み合わせれば、失敗の扱いを考える必要がなくなります。

## 次に読む

上下限を受け取る手法の一つの反復は、[L-BFGS-B法](#/learn/lbfgsb)で確かめられます。上下限を受け取らない手法の直線探索は、[BFGS法](#/learn/bfgs)にあります。ツールの中で微分方程式を解くことが、目的関数の値と傾きをどう変えるかは、[内側の計算が作る目的関数のずれと段差](#/learn/concept.inner-solver-error)へ進みます。

## 出典と再現条件

BFGS と直線探索は、Nocedal・Wright の教科書『Numerical Optimization』（S056）に基づきます。L-BFGS-B が反復の点を上下限の中に保つことは Byrd らの論文（S065）に基づきます。差分の点も上下限の中に取ることは、SciPy 1.18.1 の実装の性質です。`minimize` の `bounds` と `success` は、SciPy の公式文書（S002）に基づきます。

例の数値は、SciPy 1.18.1 と NumPy 2.5.3 で上のコードを実行して得た値です。返す値が10から1000000までの4通りの止まった点は、OpenBLAS の部品を上の5通りに切り替えても変わりませんでした。評価の回数は部品によって変わるので、表には載せていません。返す値を1e10にしたときの結果は、部品によって変わります。図の境目の曲線は、水位の式から空になるまでの時間を式で計算して描きました。タンクの数値は教材用で、実際の設備の値は示しません。
