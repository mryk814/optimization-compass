ハイパーパラメータ最適化（HPO）は、学習の前に人が決める設定を、学習と検証の評価を繰り返して選ぶ定式化です。設定の例は、次数、木の深さ、正則化の強さです。評価1回が高価で、同じ設定でも値が変わり、勾配も得られません。選ぶ過程で検証の点数が甘くなるため、最後の点数は選択に使っていないデータで測ります。

## 30秒でつかむ

30点の散布データに、多項式の曲線を当てはめます。決める設定は2つです。多項式の次数 $d$（整数、2から15）と、係数が大きくなりすぎないようにする罰則の強さ $\lambda$（$10^{-6}$ から $10$）です。設定を決めるたびに、曲線を学習し、学習に使っていない点で誤差を測ります。この例では1回が数ミリ秒ですが、実際のモデルなら数時間かかるものとみなし、試せるのは16回までとします。

16回の使い方は、すぐに2つ思いつきます。次数と $\lambda$ をそれぞれ4つ選んで4×4の格子で試す方法と、探索範囲から16組をでたらめに引く方法です。評価の回数は同じです。

- **決めるもの**: 次数 $d$（整数）と $\log_{10}\lambda$（連続）の2つの設定
- **良くしたいもの**: 5分割の交差検証で測った二乗誤差（小さいほどよい）
- **守ること**: 探索範囲の上下限と、評価16回の予算。最後の点数は、設定の選択に使っていないデータで測る

次の図は、同じ16回を格子とランダムに使ったときの、設定の位置です。背景の灰色は、次数と $\log_{10}\lambda$ の各区画の中心で測った交差検証誤差で、濃いほど誤差が大きくなります。緑の丸が評価した設定、橙の輪が16点のうちの最良です。まず格子のパネルで、紺の短い線が何本あるかを数え、ランダムのパネルの本数と見比べてください。

## 標準形を読む

次の式が表すのは「設定 $\theta$ を探索範囲 $\Theta$ から選び、その設定で学習した結果の検証損失を最小にする」です。

$$
\min_{\theta\in\Theta}\ \mathcal L_{\text{val}}\bigl(w^{*}(\theta)\bigr),\qquad
w^{*}(\theta)\in\arg\min_{w}\ \mathcal L_{\text{train}}(w;\theta)
$$

定式化の辞書では、設定を $\lambda$ と書きます。この記事ではリッジ回帰の罰則の強さが $\lambda$ なので、設定全体を $\theta=(d,\lambda)$ と書きます。

| 記号 | 意味 | 例では |
|---|---|---|
| $\theta$ | 学習の前に決める設定（ハイパーパラメータ） | 次数 $d$ と罰則の強さ $\lambda$ |
| $\Theta$ | 探索範囲。整数、対数目盛り、条件付きの設定を含むことがある | $d\in\{2,\dots,15\}$、$\log_{10}\lambda\in[-6,1]$ |
| $w^{*}(\theta)$ | 設定 $\theta$ で学習した結果 | 学習に使う24点で求めた多項式の係数 |
| $\mathcal L_{\text{train}}$ | 学習の目的。設定ごとに形が変わる | 二乗誤差の和に $n\lambda\lVert w\rVert^2$ を足したもの |
| $\mathcal L_{\text{val}}$ | 検証損失。学習に使っていないデータで測る | 5分割の交差検証の平均二乗誤差 |
| 評価1回 | 学習してから検証する1組の計算 | 係数を求める計算が5回 |

内側の式（学習）が1回解けることが、外側の式（設定の選択）の「目的関数を1回測る」ことにあたります。外側から見ると、$\mathcal L_{\text{val}}(w^{*}(\theta))$ は $\theta$ を入れると数が返る関数です。その中身である学習は、見えない箱として扱います。

### 評価1回は、学習してから検証すること

交差検証は、30点を6点ずつの5組 $F_1,\dots,F_5$ に分けます。1組を検証用に取り分け、残りの24点で学習します。5回の誤差を平均したものが評価値です。

$$
\mathrm{CV}(\theta)=\frac15\sum_{k=1}^{5}\frac{1}{|F_k|}\sum_{i\in F_k}\bigl(y_i-\hat f_{-k}(x_i;\theta)\bigr)^2
$$

この式は「$k$ 番目の組を除いて学習した曲線 $\hat f_{-k}$ が、除いた組の点をどれだけ外すかを測り、5組で平均する」と読みます。例の内側の問題は、リッジ回帰の正規方程式 $(A^\top A+n\lambda I)^{-1}A^\top y$ で解けます。ここで $A$ は、各点の Legendre 多項式の値を並べた行列です。ニューラルネットなら、この内側が反復計算になり、評価1回が数時間になります。

評価値は、分割（と、実際の学習では初期値や乱数）で決まります。同じ設定でも、分割を変えると値が変わります。小さな例で確かめます。

### 標準形が持つ探索空間の癖

$\Theta$ は、ただの箱ではありません。この例にも、次の癖があります。

- **整数**: 次数は整数です。3.6 も 4.4 も、学習に渡す前に整数へ丸める必要があります。
- **対数目盛り**: $\lambda$ は桁で効きます。$10^{-6}$ と $10^{-5}$ の差は小さく、$0.1$ と $1$ の差は大きいので、$\log_{10}\lambda$ で動かします。
- **条件付き**: 罰則なし（最小二乗）と罰則あり（リッジ）を選べるとき、罰則なしを選ぶと $\lambda$ は使われません。ある設定が、別の設定の値によって意味を持つ構造です。
- **評価の事情**: 勾配は一般に得られず、値は測り方でばらつきます。$\lambda$ だけなら微分できる場合もありますが、次数のような整数には使えません。

これらは、探し方を選ぶ前に、まず探索空間を正しく書くための条件です。

## 小さな例

データは、$[-1,1]$ の一様乱数 $x$ を30点引き、$y=\sin 3x+0.5x$ に標準偏差 $0.4$ の正規ノイズを足したものです。乱数は標準ライブラリの `random`（種1）です。新しい点での二乗誤差は、真の曲線を使っても、ノイズの分散 $0.4^2=0.16$ 前後を下回りません。以下の表と式は、すべてこの30点と、評価16回の予算に対応します。

### 30点の例・評価1回を測る

次のコードは、リッジ回帰と5分割の交差検証を実装し、いくつかの設定で評価値を測ります。1回の評価（`cv_mse`）が、外側の最適化から見た目的関数です。

```python
import math
import random
import statistics as st

import numpy as np
from numpy.polynomial import legendre

N, SIGMA = 30, 0.4
LOG_LAM = (-6.0, 1.0)  # 探索範囲: log10 λ
DEGREES = list(range(2, 16))  # 探索範囲: 次数は整数 2..15


def make_data(seed, n=N):
    rng = random.Random(seed)
    x = [rng.uniform(-1, 1) for _ in range(n)]
    y = [math.sin(3 * v) + 0.5 * v + SIGMA * rng.gauss(0, 1) for v in x]
    return np.array(x), np.array(y)


def fit(x, y, degree, lam):
    """Legendre基底の ridge 回帰。lam=0 は最小ノルムの最小二乗。"""
    a = legendre.legvander(x, degree)
    if lam == 0:
        return np.linalg.lstsq(a, y, rcond=None)[0]
    return np.linalg.solve(a.T @ a + len(x) * lam * np.eye(degree + 1), a.T @ y)


def predict(w, x):
    return legendre.legvander(x, len(w) - 1) @ w


def cv_mse(x, y, degree, lam, k=5, split_seed=0):
    """目的関数: k分割交差検証の平均二乗誤差。split_seed が分割を決める。"""
    order = list(range(len(x)))
    random.Random(split_seed).shuffle(order)
    errors = []
    for i in range(k):
        fold = order[i::k]
        train = [j for j in order if j not in fold]
        w = fit(x[train], y[train], degree, lam)
        errors.append(np.mean((predict(w, x[fold]) - y[fold]) ** 2))
    return float(np.mean(errors))


x, y = make_data(1)
print(len(x), round(cv_mse(x, y, 3, 10**-3.5), 3))
# 30 0.137
print(round(float(np.mean((y - np.sin(3 * x) - 0.5 * x) ** 2)), 3))
# 0.124
for d in (3, 6, 9, 12, 15):
    print(d, [round(cv_mse(x, y, d, 10.0**e), 3) for e in (-6, -4, -2, 0)])
    # 3 [0.137, 0.137, 0.139, 0.745]
    # 6 [0.192, 0.192, 0.183, 0.747]
    # 9 [0.341, 0.297, 0.214, 0.756]
    # 12 [0.648, 0.786, 0.223, 0.753]
    # 15 [4.486, 1.755, 0.267, 0.759]
lattice = {(d, e / 2): cv_mse(x, y, d, 10.0 ** (e / 2)) for d in DEGREES for e in range(-12, 3)}
best = min(lattice, key=lattice.get)
print(len(lattice), best, round(lattice[best], 3))
# 210 (3, -3.5) 0.137
print(sorted({round(lattice[(3, e / 2)], 3) for e in range(-12, -6)}))
# [0.137]
```

次数ごとに、$\log_{10}\lambda$ を $-6, -4, -2, 0$ と変えた評価値を表にします。

| 次数 $d$ | $-6$ | $-4$ | $-2$ | $0$ |
|---:|---:|---:|---:|---:|
| 3 | 0.137 | 0.137 | 0.139 | 0.745 |
| 6 | 0.192 | 0.192 | 0.183 | 0.747 |
| 9 | 0.341 | 0.297 | 0.214 | 0.756 |
| 12 | 0.648 | 0.786 | 0.223 | 0.753 |
| 15 | 4.486 | 1.755 | 0.267 | 0.759 |

次数が高く $\lambda$ が小さいと、曲線が学習用の点に合わせすぎます。次数15、$\log_{10}\lambda=-6$ の誤差は4.486です。$\lambda$ を1にすると罰則が強すぎて、どの次数でも0.75前後に張りつきます。次数3では、罰則がほとんど効かない範囲（$\log_{10}\lambda\le-3.5$）で、誤差は0.137のまま平らです。210点の格子は、次数14種類と、$\log_{10}\lambda$ を0.5刻みにした15種類です。この格子の最良は、次数3、$\log_{10}\lambda=-3.5$ の0.137です。

手で確かめられる量が二つあります。一つ目は分割の大きさです。30点を5組に分けると、検証用が6点、学習用が24点です。次数15の係数は16個で、学習用の点数より少なくなります。二つ目はノイズの大きさです。この30点に実際に載ったノイズの二乗平均は0.124で、期待値の0.16より小さい値でした。評価値0.137が0.16を下回るのは、このためです。

### 30点の例・同じ設定を測り直すと値が変わる

3つの設定を、分割の乱数を0から99まで変えて100回測ります。データは同じで、変わるのは分割だけです。

```python
cands = [(3, -3.5), (4, -2.0), (7, -3.0)]  # (次数, log10 λ)
V = {c: [cv_mse(x, y, c[0], 10.0 ** c[1], split_seed=s) for s in range(100)] for c in cands}
for c in cands:
    v = V[c]
    print(c, round(v[0], 3), round(st.mean(v), 3), round(st.stdev(v), 3), round(min(v), 3), round(max(v), 3))
    # (3, -3.5) 0.137 0.155 0.014 0.13 0.203
    # (4, -2.0) 0.162 0.164 0.015 0.133 0.212
    # (7, -3.0) 0.159 0.183 0.022 0.136 0.245
wins = {c: sum(min(cands, key=lambda k: V[k][s]) == c for s in range(100)) for c in cands}
print(wins)
# {(3, -3.5): 84, (4, -2.0): 13, (7, -3.0): 3}
for s in (0, 3):
    print(s, [(c, round(V[c][s], 3)) for c in sorted(cands, key=lambda k: V[k][s])])
    # 0 [((3, -3.5), 0.137), ((7, -3.0), 0.159), ((4, -2.0), 0.162)]
    # 3 [((7, -3.0), 0.136), ((3, -3.5), 0.144), ((4, -2.0), 0.151)]
```

| 設定（次数, $\log_{10}\lambda$） | 分割0 | 100通りの平均 | 標準偏差 | 最小 | 最大 |
|---|---:|---:|---:|---:|---:|
| (3, $-3.5$) | 0.137 | 0.155 | 0.014 | 0.130 | 0.203 |
| (4, $-2.0$) | 0.162 | 0.164 | 0.015 | 0.133 | 0.212 |
| (7, $-3.0$) | 0.159 | 0.183 | 0.022 | 0.136 | 0.245 |

同じ設定の評価値が、分割によって0.130から0.203まで動きます。標準偏差の0.014から0.022は、分割0での設定どうしの差と同じ大きさです。たとえば (3, $-3.5$) と (7, $-3.0$) の差は0.022です。100通りの分割で最良になった回数は、(3, $-3.5$) が84回、(4, $-2.0$) が13回、(7, $-3.0$) が3回です。分割3では (7, $-3.0$) の0.136が最良になり、分割0の順位が入れ替わります。

読み取れるのは、評価値の差が分割のばらつきと同じ大きさなら、その差で設定の優劣を決められないということです。この例のばらつきの源は分割だけです。実際の学習では、初期値や乱数でも値が変わります。

### 30点の例・同じ16回を格子とランダムに使う

評価16回を、次数 $\{2,6,11,15\}$ と $\log_{10}\lambda$ の4点（範囲の両端を含む等間隔）の格子と、ランダムに引いた16組で使います。ランダムは、次数を整数から一様に、$\log_{10}\lambda$ を範囲で一様に引きます。

```python
lo, hi = LOG_LAM


def random_config(rng):
    return rng.choice(DEGREES), 10.0 ** rng.uniform(lo, hi)  # log10 λ を一様に


def evaluate(cfgs):
    return [cv_mse(x, y, d, lam) for d, lam in cfgs]


def span(a, b, m):
    return [a + (b - a) * i / (m - 1) for i in range(m)]


grid_end = [(d, 10.0**e) for d in (2, 6, 11, 15) for e in span(lo, hi, 4)]
grid_mid = [(d, 10.0 ** (lo + (hi - lo) * (i + 0.5) / 4)) for d in (3, 7, 10, 14) for i in range(4)]
for name, g in (("端点", grid_end), ("中心", grid_mid)):
    v = evaluate(g)
    j = int(np.argmin(v))
    print(name, len(g), len({lam for _, lam in g}), len({d for d, _ in g}), round(v[j], 3), g[j][0], round(math.log10(g[j][1]), 2))
    # 端点 16 4 4 0.192 6 -3.67
    # 中心 16 4 4 0.137 3 -3.38
bests, n_lam, n_deg = [], [], []
for seed in range(200):
    rng = random.Random(seed)
    cfgs = [random_config(rng) for _ in range(16)]
    bests.append(min(evaluate(cfgs)))
    n_lam.append(len({lam for _, lam in cfgs}))
    n_deg.append(len({d for d, _ in cfgs}))
print(np.quantile(bests, [0.25, 0.5, 0.75]).round(3), round(min(bests), 3), round(max(bests), 3))
# [0.137 0.138 0.16 ] 0.137 0.192
print(set(n_lam), min(n_deg), round(st.mean(n_deg), 1), max(n_deg))
# {16} 7 9.6 13
ge, gm = (round(min(evaluate(g)), 3) for g in (grid_end, grid_mid))
print(sum(round(b, 3) <= ge for b in bests), sum(round(b, 3) <= gm for b in bests))
# 200 95
rng = random.Random(0)
cfgs = [random_config(rng) for _ in range(16)]
v = evaluate(cfgs)
j = int(np.argmin(v))
print(len({d for d, _ in cfgs}), round(v[j], 3), cfgs[j][0], round(math.log10(cfgs[j][1]), 2))
# 11 0.144 3 -1.67
```

| 探し方 | 評価回数 | $\lambda$ の種類 | 次数の種類 | 最良の誤差 |
|---|---:|---:|---:|---:|
| 格子（両端を含む） | 16 | 4 | 4 | 0.192（次数6、$\log_{10}\lambda=-3.67$） |
| 格子（各区間の中心） | 16 | 4 | 4 | 0.137（次数3、$\log_{10}\lambda=-3.38$） |
| ランダム（種0） | 16 | 16 | 11 | 0.144（次数3、$\log_{10}\lambda=-1.67$） |

ランダムを種0から199まで200回やり直しました。16点の最良の誤差は、第1四分位が0.137、中央値が0.138、第3四分位が0.160、最大が0.192です。$\lambda$ の種類は毎回16で、次数の種類は7から13（平均9.6）でした。最良が0.192以下だったのは200回中200回、0.137以下だったのは95回です。

この例では、次数も $\lambda$ も誤差に効くので、片方だけが重要とは言えません。ただし、もし片方しか効かない問題なら、格子は16回で4種類の値しか見ません。ランダムは、16種類の値を見ます。評価回数が同じでも、各設定について見る値の数が違うのが、両者の構造の差です。一方で、格子の最良は置き方で0.192にも0.137にもなりました。この結果は、1つのデータと1つの予算でのもので、どちらの探し方が優れているかを示すものではありません。

### 30点の例・探索空間を書き分ける

対数目盛り・整数・条件付きの設定をコードでどう書くかを確かめます。

```python
band = (-3.0, -1.0)  # 良い設定が多い log10 λ の帯
p_log = (band[1] - band[0]) / (hi - lo)
p_lin = (10 ** band[1] - 10 ** band[0]) / (10**hi - 10**lo)
print(round(p_log, 4), round(p_lin, 4), round(16 * p_log, 2), round(16 * p_lin, 2))
# 0.2857 0.0099 4.57 0.16


def random_config_linear(rng):
    return rng.choice(DEGREES), rng.uniform(10.0**lo, 10.0**hi)  # λ そのものを一様に


for name, sampler in (("対数", random_config), ("線形", random_config_linear)):
    in_band, best_, lowest = [], [], []
    for seed in range(200):
        rng = random.Random(seed)
        cfgs = [sampler(rng) for _ in range(16)]
        in_band.append(sum(band[0] <= math.log10(lam) <= band[1] for _, lam in cfgs))
        best_.append(min(evaluate(cfgs)))
        lowest.append(min(math.log10(lam) for _, lam in cfgs))
    print(name, st.mean(in_band), round(st.median(best_), 3), round(min(lowest), 2))
    # 対数 4.515 0.138 -6.0
    # 線形 0.13 0.5 -2.39


def to_degree(t):  # 連続値を整数の次数へ丸める
    return int(math.floor(t + 0.5))


print([to_degree(t) for t in (3.6, 4.0, 4.4)], cv_mse(x, y, to_degree(3.6), 1e-2) == cv_mse(x, y, to_degree(4.4), 1e-2))
# [4, 4, 4] True


def cv_cond(reg, d, lam):  # reg が "none" なら lam は使われない
    return cv_mse(x, y, d, lam if reg == "ridge" else 0.0)


print([round(cv_cond(r, 3, lam), 3) for r in ("none", "ridge") for lam in (1e-5, 1e1)])
# [0.137, 0.137, 0.137, 1.078]
flat = [(r, d, 10.0**e) for r in ("none", "ridge") for d in (2, 6, 11, 15) for e in span(lo, hi, 4)]
print(len(flat), len({round(cv_cond(*c), 12) for c in flat}))
# 32 20
```

- **対数目盛り**: 良い設定が多い帯を $\log_{10}\lambda\in[-3,-1]$ とします。範囲 $[-6,1]$ のうち帯の幅は7分の2です。$\log_{10}\lambda$ を一様に引くと、帯に入る確率は0.2857で、16回で平均4.57個が入ります。$\lambda$ そのものを $[10^{-6},10]$ で一様に引くと、帯の確率は $(0.1-0.001)/10=0.0099$ で、16回で0.16個しか入りません。200回の試行では、帯に入った数の平均が4.5個と0.13個、最良の誤差の中央値が0.138と0.500でした。最小の $\log_{10}\lambda$ は、対数の引き方で $-6.0$、線形の引き方で $-2.39$ です。線形に引くと、$10^{-2.39}$ より小さい $\lambda$ を一度も試せません。
- **整数**: 連続値の3.6、4.0、4.4は、丸めるとすべて次数4になり、評価値も一致します（`True`）。連続値で動かす方法に整数の設定を渡すと、評価値が平らな段になる区間ができます。
- **条件付き**: 罰則なし（`none`）では、$\lambda$ を $10^{-5}$ から $10$ に変えても評価値は0.137のままです。罰則あり（`ridge`）では、0.137から1.078に変わります。`none` と `ridge`、次数、$\lambda$ を独立な軸として全部の格子にすると、$2\times4\times4=32$ 回の評価で、異なる値は20個です。`none` 側は $\lambda$ が使われないので、次数が同じなら同じ値が4回ずつ出ます。この12回は、予算を無駄に使った重複です。

### 30点の例・選んだ設定の点数を、選択に使っていないデータで測る

次のコードは、200組の設定から最良を選び、その点数を、選ぶのに使っていない新しい5000点で測り直します。選び方は3通りです。30点の交差検証で選ぶ方法、別の30点をテストにして選ぶ方法、別の10点をテストにして選ぶ方法です。種1のデータ1つの結果と、種100から199の100個のデータの中央値を出します。

```python
x_new, y_new = make_data(999, 5000)  # 設定の選択に一度も使わない新しい5000点


def holdout(x, y, d, lam, xs, ys):
    return float(np.mean((predict(fit(x, y, d, lam), xs) - ys) ** 2))


def tune(seed, how, pool=200, n_sel=30):
    x, y = make_data(seed)
    rng = random.Random(seed + 5000)
    cfgs = [random_config(rng) for _ in range(pool)]
    if how == "cv":
        score = [cv_mse(x, y, d, lam) for d, lam in cfgs]
    else:  # 別の n_sel 点を「テスト」として設定の選択に使う
        xs, ys = make_data(seed + 7000, n_sel)
        score = [holdout(x, y, d, lam, xs, ys) for d, lam in cfgs]
    j = int(np.argmin(score))
    d, lam = cfgs[j]
    again = st.mean(cv_mse(x, y, d, lam, split_seed=s) for s in range(1, 21))
    return score[j], holdout(x, y, d, lam, x_new, y_new), again, (d, lam)


sel, fresh, again, (d, lam) = tune(1, "cv")
print(round(sel, 3), round(fresh, 3), round(again, 3), d, round(math.log10(lam), 2))
# 0.137 0.173 0.157 3 -3.55
w = fit(*make_data(1), d, lam)
t = np.linspace(-1, 1, 2001)
gap = float(np.mean((predict(w, t) - np.sin(3 * t) - 0.5 * t) ** 2))
noise = float(np.mean((y_new - np.sin(3 * x_new) - 0.5 * x_new) ** 2))
print(round(noise, 3), round(gap, 3))
# 0.159 0.015
sel, fresh, _, (d, lam) = tune(1, "test")
print(round(sel, 3), round(fresh, 3), d, round(math.log10(lam), 2))
# 0.218 0.178 7 -1.71
for how, n_sel in (("cv", 30), ("test", 30), ("test", 10)):
    R = [tune(s, how, n_sel=n_sel) for s in range(100, 200)]
    med = [round(st.median(r[i] for r in R), 3) for i in range(3)]
    print(how, n_sel, med, sum(r[1] > r[0] for r in R))
    # cv 30 [0.176, 0.199, 0.189] 72
    # test 30 [0.171, 0.19, 0.22] 61
    # test 10 [0.113, 0.197, 0.244] 82
```

`tune` は、選んだときの点数、新しい点での点数、別の20分割での平均、選んだ設定を返します。出力は次のとおり読みます。

- 1行目は、種1で交差検証が最良の設定（次数3、$\log_{10}\lambda=-3.55$）の結果です。選んだときの点数は0.137、新しい5000点では0.173、別の20分割の平均は0.157です。
- 2行目の0.159と0.015は、新しい点に載ったノイズの二乗平均と、選んだ曲線と真の曲線の差の二乗平均です。足すと0.174になり、0.173にほぼ一致します。0.173のうち、設定を選び直しても減らせない部分は0.159で、設定の良し悪しで動く部分は0.015です。
- 3行目は、別の30点で選んだ場合です。選んだときの点数0.218に対し、新しい点では0.178でした。
- 最後の3行は、100個のデータの中央値と、新しい点のほうが悪かったデータの数です。中央値は、選んだときの点数、新しい点での点数、別の20分割の平均の順です。

| 選び方 | 選んだときの点数 | 新しい5000点での点数 | 新しい点のほうが悪かったデータ |
|---|---:|---:|---:|
| 30点の交差検証 | 0.176 | 0.199 | 72 / 100 |
| 別の30点のテスト | 0.171 | 0.190 | 61 / 100 |
| 別の10点のテスト | 0.113 | 0.197 | 82 / 100 |

選んだときの点数は、どの選び方でも、新しい点での点数より小さい側にずれます。選ぶ点が少ないほど、このずれは大きくなります。

## つまずきやすい点

- **交差検証で最良だった点数を、新しいデータでの性能と読む**: 200組から交差検証で最良の設定（次数3、$\log_{10}\lambda=-3.55$）を選ぶと、点数は0.137です。選択に使っていない新しい5000点では0.173で、約0.036悪くなります。0.173は、ノイズの二乗平均0.159と、曲線の差の二乗平均0.015の和にほぼ一致します。100個のデータでは、選んだときの中央値が0.176、新しい点では0.199で、72個で悪くなりました。選ぶ過程で、たまたま良く測れた設定を拾うからです。最後の点数は、選択に使っていないデータで1回だけ測ります。
- **テストセットで設定を選び、同じ点数を報告する**: 別の30点をテストにして200組から選ぶと、100個のデータの中央値は、選んだときの0.171が新しい点では0.190です。テストが10点なら、0.113が0.197になり、100個中82個で悪くなります。種1の1回だけを見ると、0.218が新しい点で0.178になり、かえって良くなります。1回の結果では、甘くなるかどうかさえ分かりません。選ぶためのデータと、報告のためのデータは分けます。
- **同じ分割で選んだ点数を、そのまま信じる**: 選んだ設定を別の20分割で測り直すと、種1では0.137が0.157に、100個のデータの中央値では0.176が0.189になりました。同じ分割で選ぶと、その分割に有利な設定が残ります。分割を変えて測り直せば甘さは減りますが、新しいデータでの0.199までは戻りません。
- **評価値の差を、そのまま設定の優劣と読む**: (3, $-3.5$) の0.137と (7, $-3.0$) の0.159は、分割0では0.022の差です。分割3では順位が入れ替わり、0.144と0.136になります。100通りの分割で、標準偏差は0.014から0.022でした。差が標準偏差と同じ大きさなら、優劣として読みません。
- **同じ評価回数なら、格子もランダムも同じ情報量だと読む**: 評価16回の格子は $\lambda$ を4種類しか見ず、ランダムは16種類を見ます。ただし、これは「ランダムが勝つ」という意味ではありません。格子の最良は、置き方で0.192にも0.137にもなりました。
- **$\lambda$ を、そのまま一様に引く**: 良い帯の $\log_{10}\lambda\in[-3,-1]$ に入った設定は、16回あたり、線形の引き方で平均0.13個、対数の引き方で4.5個でした。最良の誤差の中央値は0.500と0.138です。桁で効く設定は、桁を一様に引きます。
- **条件付きの設定を、全部の組合せの格子にする**: `none` 側で $\lambda$ を4通りに振ると、同じ値が重なります。32回の評価のうち、異なる値は20個でした。使われない設定は、探索空間から外します。

## 課題から定式化する

「モデルの設定を決めたい」という課題だけでは、まだこの型とは決まりません。次の4つを順に確かめます。

1. **何を決めるか**: 次数（整数）と $\lambda$（対数目盛りの連続値）を決めます。罰則の種類のように選択肢があれば、それによって使われる設定が変わる条件付きの構造になります。
2. **評価1回は何をするか**: 設定を決めて学習し、学習に使っていないデータで誤差を測ります。この例の1回は係数を求める計算5回で、実際のモデルなら数時間かかります。分割や乱数で値が変わるなら、その大きさを先に測ります。
3. **どのずれを減らすか**: 学習用の誤差ではなく、検証損失（5分割の交差検証の平均二乗誤差）を減らします。選んだ後の点数は、選択に使っていないデータで測ります。
4. **何を守り、何を予算とするか**: 設定の範囲の上下限と、評価の回数（16回）が条件です。並列で評価できるかも、探し方に効きます。

探索範囲に整数や対数目盛りが含まれ、評価が学習と検証の組で、勾配が得られない設定を選ぶとき、この記事の型になります。

## 困りごとから関連する問題へ

実際の課題で、次の症状が出たら、対応する記事へ進めます。

- 評価1回が数時間かかり、試せる回数が数十回しかない → [非常に高価な低次元評価](#/formulations/PA014)と、[評価費と予算](#/learn/concept.evaluation-cost)
- 同じ設定でも、測るたびに値が変わる → [noiseを含むblack-box](#/formulations/PA013)
- 設定が数十個あり、探索が広がりすぎる → [高次元black-box](#/formulations/PA015)
- 学習が発散して値が返らない設定が出る → [失敗・NaNを伴うsimulation](#/formulations/PA016)
- 内側の学習の式まで含めて、二段の問題として書きたい → [bilevel optimization](#/formulations/PA046)
- 設定が正則化の強さ1つだけで、係数がちょうど0になるかも見たい → [L1正則化つき回帰](#/formulations/PA035)

### HPOと関連する問題の関係

- [bilevel optimization](#/formulations/PA046): HPOは、その特別な場合です。内側（学習）の解を $w^{*}(\theta)$ として、外側（検証損失の最小化）へ代入した形で、標準形の2つの式がそれです。外側から内側の式の構造を使えるかは、条件しだいです。この例のリッジ回帰は、内側が閉じた式で解けますが、次数という整数の設定は微分できません。内側が反復計算の学習なら、外側は内側を見えない箱として扱うことが多くなります。
- [非常に高価な低次元評価](#/formulations/PA014): 検証損失を、1回が高価なblack-box評価として扱うと、HPOはこの型へ書き直せます。条件は、評価回数が数十回、設定が低次元で、値のばらつきが小さいことです。次元が高い、ばらつきが大きい、失敗が混ざるときは、前の症状の記事へ進みます。
- [noiseを含むblack-box](#/formulations/PA013): 形が似ていますが、ばらつきの源が違います。この例の源は、データの分割です。分割を固定すれば値は決まりますが、固定した分割に有利な設定を選ぶ危険が残ります。
- [L1正則化つき回帰](#/formulations/PA035): 罰則の強さ $\lambda$ を、この記事と同じ交差検証で選ぶ場面が多い型です。$\lambda$ が1つなら、HPOの最も小さい形です。

## 数値計算の方法を選ぶ

どの方法も、使う情報と得られる保証が違います。探索空間の形、評価回数、並列度、学習の途中の成績が取れるかで分けて考えます。次の表は順位ではなく、条件ごとの入口です。

| 系統 | 使う情報 | 向く条件・避ける条件 |
|---|---|---|
| [Random Search](#/learn/random-search) | 履歴を使わない | 実装が単純で、並列にしやすく、他の方法と比べる基準になります。次元が高く有望な領域が小さいと、被覆は保証されません |
| [TPE](#/learn/tpe) | 良かった設定と残りの分布の比 | 整数、カテゴリ、条件付きの設定が混ざる探索空間で候補になります。履歴が極端に少ないときは、探索がランダムに近くなります |
| [SMAC](#/learn/smac) | ランダムフォレストによる予測 | カテゴリや条件付きの設定が多いとき、木で分岐を表せます。評価回数が少ない、連続変数中心の低次元なら、ガウス過程も候補です |
| [ベイズ最適化](#/learn/bayesian-optimization) | 観測から作る代理モデルの予測と不確実性 | 連続変数が中心で、低次元、評価が数十回のときに向きます。条件付きやカテゴリが多いと、連続値のカーネルが合いません |
| [Hyperband / ASHA](#/learn/hyperband-asha) | 学習の途中の成績 | エポックや標本数を段階的に増やせ、途中の成績が最終の成績と相関するときに向きます。相関がなければ、系統的な偏りを作ります |
| [Population Based Training](#/learn/pbt) | 並走する学習の途中成績と状態 | 学習を続けながら設定を変えるとき（学習率の予定など）に向きます。得られるのは設定の予定を含む学習の結果で、固定の設定ではありません |

各ライブラリ（Optuna、SMAC3、Ray Tuneなど）の既定のsamplerや打切り器は、そのライブラリの選択です。この記事の推奨でも、一般的な順位でもありません。

次のコードは、途中の成績で絞る方法を、この30点の例で確かめます。低い忠実度として、先頭の15点だけで交差検証を測ります。16組のうち上位4組だけを、30点の評価へ進めます。

```python
from scipy.stats import spearmanr


def halve(seed, n_cfg=16, frac=0.5, keep=4):
    x, y = make_data(seed)
    rng = random.Random(seed + 9000)
    cfgs = [random_config(rng) for _ in range(n_cfg)]
    m = int(len(x) * frac)  # 先頭の15点だけで測る（低い忠実度）
    low = [cv_mse(x[:m], y[:m], d, lam) for d, lam in cfgs]
    full = [cv_mse(x, y, d, lam) for d, lam in cfgs]
    kept = set(np.argsort(low)[:keep].tolist())
    return spearmanr(low, full)[0], int(np.argmin(full)) in kept


rho, ok = halve(1)
print(round(float(rho), 3), ok)
# 0.838 True
R = [halve(s) for s in range(100, 200)]
print(round(float(np.median([r[0] for r in R])), 3), round(float(min(r[0] for r in R)), 3), sum(r[1] for r in R))
# 0.687 -0.256 66
print(16 * 0.5 + 4, 16)
# 12.0 16
```

種1では、半分の点で測った順位と30点で測った順位の Spearman の順位相関が0.838でした。30点で最良の設定は、残る4組に入りました。種100から199の100個のデータでは、順位相関の中央値が0.687、最小が $-0.256$ で、最良の設定が残ったのは66個です。34個では、最良の設定が途中で落ちました。

費用は、30点の評価1回を1とします。16組を半分の点で測る費用が8、残り4組を30点で測る費用が4で、合計12です。16組すべてを30点で測る費用16より少なくなります。ただし、この費用は点数に比例するという仮定の計算です。この比較は、1つのモデルと1つの切り方での値で、途中の成績が最終の成績を予測できるかは、問題ごとに先に確かめます。
