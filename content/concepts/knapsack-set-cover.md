ナップサック問題と集合被覆問題は、品目や集合を「選ぶ・選ばない」の0か1で決める定式化です。ナップサック問題は容量の上限のもとで価値を最大にし、集合被覆問題は全部を覆う条件のもとで費用を最小にします。

## 30秒でつかむ

容量8の袋へ、4品目から何を入れるか決めます。重さあたりの価値が高いものを順に入れると12。ところが、ある品目をあえて外すと13になります。なぜ「お得な順」なのに最良ではないのでしょうか。

品物は半分に切れず、入れるか入れないかです。先に入れた小さな品物が、後で価値の高い組合せを妨げることがあります。この記事では同じ4品目で、貪欲法、整数の最適解、分数を許した上界を比べます。最後に、守る条件を「容量以下」から「すべてを覆う」へ変えた集合被覆を見ます。

- **決めるもの**: 品目ごとの「入れる（1）・入れない（0）」
- **良くしたいもの**: 選んだ品目の価値の合計
- **守ること**: 選んだ品目の重さ（費用）の合計が、容量（予算）以下

向きを逆にした型が集合被覆問題です。すべての地区を、いずれかの拠点の担当範囲に入れなければなりません。守るべき条件は「全部を覆う」で、良くしたいのは選ぶ拠点の費用の少なさです。
容量の上限を守る問題と、覆い残しをなくす問題は、同じ0-1の決定で書けます。

## 標準形を読む

ナップサック問題は、価値の合計を、重さの上限のもとで最大にする問題です。

$$
\max_{x\in\{0,1\}^n}\; v^\top x \quad \text{s.t.}\quad w^\top x\le W
$$

| 記号 | 意味 |
|---|---|
| $x_i$ | 品目 $i$ を入れるとき1、入れないとき0 |
| $v_i$ | 品目 $i$ の価値。事例では便益スコアや期待効果 |
| $w_i$ | 品目 $i$ の重さ。事例では費用 |
| $W$ | 容量。事例では予算の上限 |

集合被覆問題は、選ぶ集合の費用の合計を、要素の覆い残しなしで最小にする問題です。

$$
\min_{y\in\{0,1\}^m}\; c^\top y \quad \text{s.t.}\quad \sum_{j:\,i\in S_j} y_j\ge 1\;\;(i=1,\dots,n)
$$

$y_j$ は集合 $S_j$ を選ぶとき1です。要素 $i$ ごとに1本の制約があり、$i$ を含む集合のうち少なくとも1つを選ぶことを求めます。
ナップサック問題は「上限」の制約を1本だけ持ち、集合被覆問題は「下限」の制約を要素の数だけ持ちます。

どちらも $x\in\{0,1\}^n$ の整数条件が主役です。この条件があるため、混合整数線形計画の特別な場合として扱えます。

## 小さな例

動的計画法の記事と同じ、容量8のリュックに4品目を入れる問題です。

| 品目 | A | B | C | D |
|---|---:|---:|---:|---:|
| 重さ $w$ | 4 | 3 | 5 | 2 |
| 価値 $v$ | 8 | 5 | 6 | 4 |

入る組み合わせは限られているので、手で全部数えられます。

| 選ぶ品目 | 重さの合計 | 価値の合計 |
|---|---:|---:|
| A, B | 7 | 13 |
| A, D | 6 | 12 |
| B, C | 8 | 11 |
| C, D | 7 | 10 |
| B, D | 5 | 9 |

A と C は重さが9で入らず、1品だけなら価値は最大でも8です。3品以上の組み合わせは、すべて重さが8を超えます。
最適解は A と B で、価値は $13$ です。使い残した容量は1です。

### 読み取り: 「お得な順」に詰めても最適とは限らない

価値÷重さの比は、品目ごとに次のとおりです。

| 品目 | A | B | C | D |
|---|---:|---:|---:|---:|
| 価値÷重さ | 2 | 約1.67 | 1.2 | 2 |

比の大きい順に、入るものを入れていきます。AとDは同率です。ここでは入力順のAを先にしますが、この例ではDを先にしても同じA+Dになります。A と D を選ぶと、価値は $12$ で、重さは6です。
次の B は重さ3ですが、残りの容量は2なので入りません。C も入りません。

最適解 $13$ は、比の高いDを外し、Bを入れた組み合わせです。この交換だけを計算すると、重さは $6-2+3=7$、価値は $12-4+5=13$。Dの比が高いことは、Aとの組合せでもDを残すべきだという証拠にはなりません。

最適解の余りは1です。一方、B+Cは重さ8で袋を使い切りますが、価値は11。ここで良くしたいのは価値の合計であり、使用容量の多さではありません。

### 上界で「どこまで良くなり得るか」を測る

0-1の条件を外し、$0\le x_i\le 1$ の連続量にすると、線形計画の緩和になります。
A と D を全部入れると、容量の残りは2です。この残りで B を $2/3$ だけ入れた $x=(1,\tfrac23,0,1)$ が答えです。
価値は $8+4+\tfrac23\cdot5\approx 15.33$ です。

![同じ容量8について貪欲A Dの価値12、最適A Bの価値13、容量を使い切るB Cの価値11、分数を許すA D Bの3分の2の上界46/3を並べる。棒の長さは重さ、右の数字は価値。](./media/knapsack-four-items-bound.svg "0–1可行解と連続緩和を区別する図。分数のBは現実に採用できる品物ではなく、上界を計算するための仮想的な分割です。")

図では棒の長さが重さ、右の数字が価値です。長い棒ほど良いと読まないでください。最下段の斜線のBだけは分数で、上3段と同じ採用候補ではありません。

どの0-1の解も、この値を超えられません。見つけた解が $13$ なら、最適値は $13$ と $15.33$ の間にあります。
ここでは全16通りを調べたので13が最適と分かります。13と $46/3$ という二つの数だけを知っている段階では、まだ最適性を証明できていません。価値が整数でも、14や15の可能性は残ります。分枝限定法は、この幅を詰めて最適性を証明します。この事例の緩和の答えは、B が分数のままなので、丸めるだけでは解になりません。

### 16通りを全部調べる基準計算

空の袋も含めて $2^4=16$ 通りあり、容量を守るのは10通りです。次の短いコードで、主例の最適値をソルバーと独立に確認できます。

```python
from itertools import product

weight = (4, 3, 5, 2)
value = (8, 5, 6, 4)
feasible = []
for bits in product((0, 1), repeat=4):
    w = sum(a * b for a, b in zip(weight, bits))
    v = sum(a * b for a, b in zip(value, bits))
    if w <= 8:
        feasible.append((v, w, bits))
best = max(feasible)
assert len(feasible) == 10
assert best == (13, 7, (1, 1, 0, 0))
print(best)  # 価値、重さ、A/B/C/Dの採否
```

各品目を増やすたびに組合せは2倍になります。全列挙はこの小例の正解照合には便利ですが、大きい問題への計算量の解決策ではありません。

### 事例との対応

公開事例『限られた予算で防災事業を選ぶ』は、同じ形です。費用が $4,3,2,3$、便益が $9,6,4,5$、予算が $7$ です。
全部を数えると、最適は事業 A と B です。便益は $15$ で、費用は $7$ です。
他の予算配分の事例は、ここに「地域ごとに少なくとも1件を選ぶ」のような条件が加わります。制約が複数の行に増え、純粋なナップサック問題より一般的な0-1整数計画になります。

### 集合被覆問題の小さな例

6つの地区 $1,\dots,6$ を、次の集合（拠点の担当範囲）で覆います。費用はどれも1で、選ぶ数を最小にします。

| 集合 | 覆う地区 |
|---|---|
| A | 1, 2, 3, 4 |
| B | 1, 2, 5 |
| C | 3, 4, 6 |
| D | 5 |
| E | 6 |

最も多くを覆うAから選ぶと、地区5と6が残ります。同じ被覆数なら表の順に選ぶと、BとCを足して3つになります。この例では同率候補のD/Eを選ぶ場合も、Aの後にもう2集合が必要です。
B と C だけで、1から6のすべてを覆えます。2つで足り、これが最小です。1集合で6地区全部を覆う候補は存在しないため、下界2と可行解2が一致します。

「新しく覆える数が最大の集合を順に選ぶ」貪欲法は、ここでは最適ではありません。ナップサック問題の貪欲法と同じく、先に得をした選択が後で響きます。

## 見分け方

次の言葉が出てきたら、ナップサック問題を疑います。

- 限られた予算・容量・時間で、どの案件・品目を採用するかを選ぶ
- 案件ごとに費用と便益が決まっていて、分割して実施できない
- 「入れる・入れない」「採用・見送り」の二択の集合が答え

次の言葉が出てきたら、集合被覆問題を疑います。

- すべての地区・顧客・要件を、どれかの拠点や手段で必ず満たす
- 満たすために選ぶ拠点や手段の数、または費用を減らしたい

別の型へ向かう兆候もあります。

- 同じ品目を複数個買える、台数や個数が答え → [混合整数線形計画](#/formulations/PA023)（整数変数）
- 品目を連続量で配分できる → [線形計画](#/learn/concept.linear-program)。0-1の条件が要らず、丸めの問題が消えます
- 「AならばB」「AとBは同時に選べない」のような論理条件が多い → [CP-SAT](#/learn/cp-sat)や混合整数計画
- 品目どうしの組み合わせで価値が変わる（相乗効果、重なり） → 目的に二次の項が入る別の定式化

## 近い定式化

- **混合整数線形計画**: ナップサック問題は、制約が1本の0-1整数計画です。制約を足し、連続変数を混ぜれば混合整数線形計画になります。
- **線形計画（LP緩和）**: 0-1の条件を $0\le x_i\le1$ にした問題です。最大化の問題では、この値が上界になります。ナップサック問題の緩和は、価値÷重さの大きい順に詰め、最後の1品を分数で入れる方法で解けます。前提は、価値が0以上で重さが正であることです。
- **集合被覆問題**: 制約が要素ごとに増える0-1整数計画です。最小化なので、LP緩和の値は下界になります。
- **動的計画法**: 重さと容量が整数なら、ナップサック問題を表を埋める方法で厳密に解けます。表の大きさは品目数×容量で、容量の数値が大きいと表も大きくなります。

## 解き方の系統

- **動的計画法**: 「$i$ 品目まで見て、容量が $a$」の部分問題を表に残します。整数の重さと小さい容量に向き、最適性を証明できます。制約が増えて部分問題に分けにくくなると、扱いにくくなります。
- **branch-and-cut**: 緩和で上界を求め、変数を0と1に分けて探索します。上界と暫定最良解の差（最適性ギャップ）が、最適性の残りの余地を示します。MILP ソルバーの標準的な方法です。
- **CP-SAT**: 線形制約を整数の係数で表し、論理条件と探索で解きます。「少なくとも1件」のような条件が多い事例で使いやすい方法です。
- **貪欲法・局所探索**: 速く良い解を作れます。ただし最適性は証明しません。上の例では、貪欲法は最適に届きませんでした。

次のコードは、全列挙で確かめた同じ主例についてLP緩和と整数解と貪欲法を並べます。[SciPyの公式説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)で、`milp`の整数指定、最小化形式、終了状態を確認できます。内部の解法はHiGHSです。

```python
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

names = "ABCD"
value = np.array([8, 5, 6, 4])
weight = np.array([4, 3, 5, 2])
capacity = 8


def solve(integer):
    return milp(
        c=-value,  # 最大化を最小化に直す
        constraints=LinearConstraint([weight], ub=capacity),
        integrality=np.ones(4) if integer else np.zeros(4),
        bounds=Bounds(0, 1),
    )


relaxed, exact = solve(False), solve(True)
assert relaxed.success and exact.success
print("LP relaxation:", relaxed.x.round(3), round(-relaxed.fun, 3))
print("integer:", exact.x.round(3), -exact.fun)

# 価値÷重さの大きい順に、入る品目を入れていく貪欲法
remaining, picked = capacity, []
for i in np.argsort(-value / weight, kind="stable"):
    if weight[i] <= remaining:
        remaining -= weight[i]
        picked.append(i)
print("greedy:", [names[i] for i in picked], value[picked].sum())
```

実行すると、次のように出ます。

```text
LP relaxation: [1.    0.667 0.    1.   ] 15.333
integer: [1. 1. 0. 0.] 13.0
greedy: ['A', 'D'] 12
```

手計算の結果と、1行ずつ照らして確かめます。LP緩和の $0.667$ は B の分数です。整数解は A と B を選び、貪欲法は $12$ で止まります。

集合被覆問題は、要素ごとの制約を行列にして渡します。

```python
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

sets = {"A": {1, 2, 3, 4}, "B": {1, 2, 5}, "C": {3, 4, 6}, "D": {5}, "E": {6}}
names = list(sets)
# 行が要素 1..6、列が集合。要素 i が集合 j に入っていれば 1
cover = np.array([[int(e in sets[n]) for n in names] for e in range(1, 7)])


def min_cover(matrix):
    return milp(
        c=np.ones(len(names)),  # 選ぶ集合の数を最小にする
        constraints=LinearConstraint(matrix, lb=1),  # どの要素も1回以上覆う
        integrality=np.ones(len(names)),
        bounds=Bounds(0, 1),
    )


result = min_cover(cover)
assert result.success
print("optimal:", [n for n, y in zip(names, result.x) if y > 0.5], result.fun)

# 新しく覆える要素が最も多い集合を、順に選ぶ貪欲法
uncovered, chosen = set(range(1, 7)), []
while uncovered:
    best = max(sets, key=lambda n: len(sets[n] & uncovered))
    chosen.append(best)
    uncovered -= sets[best]
print("greedy:", chosen)

# どの集合にも入らない要素を足すと、実行不可能になる
bad = min_cover(np.vstack([cover, np.zeros(len(names), dtype=int)]))
print("status:", bad.status, bad.success)
```

```text
optimal: ['B', 'C'] 2.0
greedy: ['A', 'B', 'C']
status: 2 False
```

最適は2つ、貪欲法は3つです。最後の行の `status` が2なら、実行不可能と判定されています。

## つまずきやすい点

- **貪欲法の結果を最適と読む**: 価値÷重さの順や、新しく覆える数の順で選ぶ方法は、速い代わりに最適性の根拠がありません。上の2つの例で、どちらも最適を外しました。厳密な答えが必要なら、最適性ギャップを出す方法か動的計画法で確かめます。
- **LP緩和の解を丸める**: 緩和の答え $x_2=0.667$ を四捨五入して B を入れると、A と B と D で重さが9になり、容量8を超えます。丸めは実行可能性を保証しません。
- **重さが小数のまま**: 容量を表の添字にする通常の動的計画法は、整数の重さと容量を使います。CP-SATの線形制約も整数係数で書きます。$3.5$ のような重さは、容量と同じ単位変換で整数へそろえます。丸めると容量の境界で別の問題になるので、精度を先に決めます。価値まで常に整数でなければならない、という意味ではありません。
- **集合被覆問題で覆えない要素がある**: どの集合にも入らない要素があると、実行可能な解が存在しません。上のコードのように `status` を確かめ、データの入力漏れを疑います。
- **制約の向きの取り違え**: ナップサック問題は上限（$\le$）、集合被覆問題は下限（$\ge$）です。逆に書くと、全部を選ぶか何も選ばないかが答えになり、問題が意味を失います。

## まとめて確認する

- A+Dの12は、条件を守る良い候補。ただし貪欲法というだけでは最適とは言えない
- A+Bの13は、この4品目を全列挙した最適解。容量1を残す
- 分数を許す $46/3$ は上界。0–1解として採用せず、丸めた後の重さも必ず再計算する
- 集合被覆のB+Cは2集合。1集合で覆えないという下界が、最適性の証拠になる
