変数の定義域は、最適化で何を動かせるかを決め、使える定式化・ソルバー・保証の範囲を最初に絞る分類です。

## 同じ式なら、答えも同じになるか

製品AとBを作り、利益を大きくする小さな生産問題を考えます。Aの量を $x_1$、Bの量を $x_2$ とします。Aは1単位あたり利益5、Bは利益4です。使える資源には二つの上限があります。

$$
\max\;5x_1+4x_2
\quad\text{s.t.}\quad
6x_1+4x_2\le24,\qquad x_1+2x_2\le6,\qquad x_1,x_2\ge0.
$$

第1制約は、Aが6、Bが4使う資源の総量を24以下に抑えます。第2制約は、Aが1、Bが2使う別の資源を6以下に抑えます。ここまででは「1.5単位のBを作ってよいか」が決まっていません。**最後に変数の定義域を指定して、初めて意思決定が定まります。**

- 液体のように分割できる量なら、$x\in\mathbb R_{\ge0}^2$。連続値を選べます。
- 完成品の個数なら、$x\in\mathbb Z_{\ge0}^2$。整数しか選べません。
- 各製品を1単位だけ採用するかなら、$x\in\{0,1\}^2$。0か1しか選べません。

最後の設定は「各種類を高々1単位」という追加の制限を含みます。整数問題を別のデータ型で実装しただけではなく、意思決定の意味そのものを変えています。

![同じ二つの資源制約について、連続可行領域、13個の整数可行点、4個の二値可行点を並べた図。最良点は順に(3,1.5)、(4,0)、(1,1)。](./media/variable-domain-comparison.svg "線と軸は同じです。青い面または青い点が選べる候補、橙の星が各定義域の最良点です。整数パネルの赤い×は丸めで生じた不可行点です。")

図は左から右へ、「候補として残る点」を読んでください。連続問題の青い領域に入る点でも、整数問題では格子点でなければ選べません。二値問題ではさらに四つの点だけが残ります。

| 何を選ぶか | 最良点 $(x_1,x_2)$ | 利益 |
|---|---:|---:|
| 分割できる連続量 | $(3,1.5)$ | 21 |
| 整数個 | $(4,0)$ | 20 |
| 各種類の0/1採否 | $(1,1)$ | 9 |

連続解 $(3,1.5)$ では二つの資源を使い切ります。この値が上限になることは、制約の第1式を $3/4$ 倍、第2式を $1/2$ 倍して足すと分かります。

$$
5x_1+4x_2\le \tfrac34\times24+\tfrac12\times6=21.
$$

整数解はこの21を超えられません。ただし21を達成する点が整数であるとは限らないので、連続問題の最良点をそのまま返すことはできません。

### 丸めると何を失うか

$1.5$ を2へ丸めた $(3,2)$ は、第1資源を $26>24$、第2資源を $7>6$ 使用します。**二つの制約を両方とも破ります。** 1へ切り下げた $(3,1)$ は可行ですが、利益19です。整数の最良点 $(4,0)$ の利益20には届きません。

この例はすべての係数が正なので切り下げが可行性を保ちますが、一般の問題には等式、最低生産量、負の係数もあります。切り下げなら常に安全、という規則にもできません。丸め後には元の制約と目的を必ず計算し直します。

### 図の点を自分で数える

この小例なら、整数候補をすべて調べられます。非負条件と資源制約から $x_1\le4$、$x_2\le3$ なので、調べる範囲に抜けはありません。コードは連続解をLPで、整数と二値の答えを全列挙で求めます。

```python
from itertools import product
import numpy as np
from scipy.optimize import linprog

A = np.array([[6., 4.], [1., 2.]])
b = np.array([24., 6.])
profit = np.array([5., 4.])

def best(points):
    feasible = [np.array(x) for x in points if np.all(A @ x <= b)]
    return max(feasible, key=lambda x: profit @ x)

lp = linprog(-profit, A_ub=A, b_ub=b, bounds=(0, None), method="highs")
assert lp.success
integer = best(product(range(5), range(4)))
binary = best(product(range(2), repeat=2))
print("continuous:", lp.x, -lp.fun)
print("integer:", integer, profit @ integer)
print("binary:", binary, profit @ binary)
print("rounding excess:", A @ [3, 2] - b)
```

出力は順に $(3,1.5),21$、$(4,0),20$、$(1,1),9$。最後の超過量は $(2,1)$ です。ここで全列挙できるのは候補が少ないためです。数千個の二値変数に同じ方法を広げると候補数が爆発するので、[混合整数線形計画](#/learn/concept.mixed-integer-linear-program)で緩和と探索を組み合わせます。

## まず「何を選ぶか」を言葉にする

最適化でいう変数は、Pythonの`float`や`int`の型だけではありません。設計長さは連続値です。製品の採否は二値、訪問順は順列です。制御入力の時系列なら軌道が変数です。ソルバー選択の前に、**解として返したい対象がどの集合に属するか**を明示します。

生産例のように定義域を変える場合だけでなく、符号化の方法にも注意が必要です。たとえば「3種類から1つを選ぶ」問題を考えます。整数`0, 1, 2`として連続最適化器へ渡すと、選択の意味が曖昧になります。カテゴリ選択またはワンホット形式の二値を使い、制約を伴う離散問題として表す方が意味を保ちやすくなります。

| 定義域 | 典型例 | 最初に確認すること |
| --- | --- | --- |
| 連続変数 | 寸法、濃度、温度 | 上下限、尺度、微分の有無 |
| 整数変数 / 二値 | 台数、採否、オン／オフ | 線形緩和の強さ、論理制約、許容する最適性ギャップ |
| カテゴリ / 順序付きカテゴリ | 材料種、モデル種、段階 | 順序や距離を仮定してよいか |
| 順列 / グラフ / 集合 | 順路、接続、選抜 | 専用のグラフ・マッチング・経路選択構造がないか |
| 単体 / 行列 / 多様体 | 配合比、共分散、回転 | 集合を保つ射影・パラメータ化・レトラクションがあるか |
| 軌道 / 関数 | 制御列、温度分布 | 時間離散化、動力学、連続時間での妥当性 |

## 定義域はソルバー名より先に効く

連続変数で滑らかな目的と勾配があるなら、[滑らかな局所最適化](#/learn/family.smooth-local)のような勾配法を検討できます。一方、二値や整数を連続変数として解いて丸めるだけでは不十分です。丸め後の解が制約を満たすとは限らず、最適性ギャップの解釈も失われます。離散性が本質なら、[離散・組合せ最適化](#/learn/family.discrete-structure)の定式化から考えます。

定義域が特殊な集合である場合も同様です。確率の比率は単に非負な実数の並びではなく、合計1の単体です。回転行列や低ランク行列は、成分ごとの上下限だけでは本来の集合を保てません。

制約へ罰則を足す方法もあります。射影／変数変換／[多様体最適化](#/learn/family.manifold)のように集合を直接扱う方法もあります。各方法の数値条件と実行可能性を比較します。

## 連続緩和は便利だが、元の問題ではない

整数・二値問題の連続緩和の大域最適値は、最小化では下界、最大化では上界を与えます。連続緩和とその解は、初期解の構築、感度解析、branch-and-boundの部分問題としても役立つことがあります。ただし、緩和解の`x = 0.37`は「0か1を選ぶ」という元の意思決定そのものではありません。丸めや整数化の後には、目的値・制約違反・最適性証明を改めて評価します。

同じ注意は軌道にもあります。時間を粗く離散化した制約を満たしても、連続時間の途中で安全制約を満たす保証には直結しません。必要ならメッシュ細分化、区間内検証、または連続時間の制約を扱う定式化を追加します。

::: warning
「変数が数値で表せる」ことと、「連続最適化として扱ってよい」ことは別です。カテゴリ／順列／論理／行列構造を安易に連続値へ符号化すると、ソルバーが動いても解の意味を壊すことがあります。
:::

## 診断するときの最小チェック

解法を比較する前に、次を記録しておくと切替理由を追えます。

- 各変数の定義域、単位、上下限、許容精度
- 整数・カテゴリの符号化と、無効な組合せを除く制約
- 連続緩和を使う場合は、丸め・修正後に再評価した可行性と目的値
- 軌道なら、時間刻み、制御の保持方法、区間内制約の確認方法
- 特殊集合なら、射影・パラメータ化・レトラクションのどれで集合を保つか

次に、定義域以外の3点を並べます。

- 目的の形が滑らかか
- 制約が何か
- 1回の評価にどれだけの予算を使えるか

定義域だけで万能なソルバーは決まりませんが、定義域と矛盾する選択は早い段階で除外できます。
