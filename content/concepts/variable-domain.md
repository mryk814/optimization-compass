変数の定義域は、最適化で何を動かせるかを決め、使える定式化・ソルバー・保証の範囲を最初に絞る分類です。

## 同じ式なら、答えも同じになるか

製品AとBを作り、利益を大きくする小さな生産問題を考えます。Aの量を $x_1$、Bの量を $x_2$ とします。Aは1単位あたり利益5、Bは利益4です。使える資源には二つの上限があります。

$$
\max\;5x_1+4x_2
\quad\text{s.t.}\quad
6x_1+4x_2\le24,\qquad x_1+2x_2\le6,\qquad x_1,x_2\ge0.
$$

第1制約は、Aが6、Bが4使う資源の総量を24以下に抑えます。第2制約は、Aが1、Bが2使う別の資源を6以下に抑えます。ここまででは「1.5単位のBを作ってよいか」が決まっていません。最後に変数の定義域を指定して、初めて意思決定が定まります。

- 液体のように分割できる量なら、$x\in\mathbb R_{\ge0}^2$。連続値を選べます。
- 完成品の個数なら、$x\in\mathbb Z_{\ge0}^2$。整数しか選べません。
- 各製品を1単位だけ採用するかなら、$x\in\{0,1\}^2$。0か1しか選べません。

0か1は整数の特別な場合ではなく、各製品を高々1単位に限る別の問題です。決める内容そのものが変わります。

まず、操作欄の「製品Aの量 x₁ の定義域」で「整数」を選び、続けて「製品Bの量 x₂ の定義域」でも「整数」を選んでください。

::: explorable variable-domain-switch
青緑の面・線分・点が、その定義域で選べる計画です。灰色の線と点は、両方連続のときの最適解 $(3,1.5)$ と利益21で、どの定義域でも薄く残ります。点線の多角形は、整数条件を外して連続に戻した緩和の領域です。星が選んだ定義域の最適解、ひし形が緩和の最適解で、二つが一致するときのひし形は星を囲む輪郭だけになります。橙の線が等利益線で、定義域を切り替えると新しい最適解まで動きます。0か1を選ぶと、$x\le1$ の太い青緑の線が現れ、緩和の領域がそこで切られます。パネル「九通りの一覧」は、利益を数字で、緩和との差（ギャップ）をマスの橙の濃さで示します。この図は変数2個、資源制約2本の例だけを扱います。変数が増えたときの探索の大変さは読み取れません。
:::

1. 両方「連続」から両方「整数」へ切り替えます。面が13個の点に変わり、橙の線が灰色の線から離れて星の $(4,0)$ まで動きます。利益は21から20に下がり、ひし形と星の間に「ギャップ 1.00」が出ます。
2. 続けて「丸めてみる」にチェックを入れます。ひし形から赤い×が現れ、多角形の外の $(3,2)$ に「丸め（不可）」と出ます。図の「丸め（不可）」の下に「資源1を2超過・資源2を1超過」と書かれ、表のあとの文も同じ超過量を伝えます。三角の「切り下げ」$(3,1)$ は領域の内側ですが、利益19で星の20に届きません。
3. 両方「0か1」にします。点が4個になり、緩和の領域は $x_1,x_2\le1$ の正方形に切られます。星を囲むひし形の輪郭が現れて、ギャップは0になります。利益9は灰色の点の21から大きく下がります。
4. 製品Aだけ「整数」、製品Bは「連続」にします。面が縦の線分5本になり、星が灰色の点に重なります。ひし形は星を囲む輪郭になり、点線の等利益線が消えます。利益は21、ギャップは0です。次に製品Aを「連続」に戻し、製品Bだけを「整数」にします。面が横の線分4本になり、星が $(10/3,1)$ へ移ります。利益は $62/3\approx20.67$ で、ひし形が $(3,1.5)$ に残り、ギャップは $1/3$ です。
5. 製品Aを「0か1」、製品Bを「連続」にします。ギャップは0で、ひし形の輪郭が星を囲みますが、利益は15で灰色の21より下です。ギャップが0でも、連続のときの21と同じとは限りません。緩和の領域が $x_1\le1$ で先に狭められているためです。

九通りの最適値を、変数ごとに並べると次のとおりです。パネル「九通りの一覧」の数字と同じ値です。ギャップは「緩和の最適値 − 最適値」で、緩和は整数条件を外し、0か1の変数を0以上1以下にした連続問題です。

| $x_1$ | $x_2$ | 最適解 | 利益 | ギャップ |
|---|---|---|---:|---:|
| 連続 | 連続 | $(3,1.5)$ | 21 | 0 |
| 連続 | 整数 | $(10/3,1)$ | 20.67 | 0.33 |
| 連続 | 0か1 | $(10/3,1)$ | 20.67 | 0 |
| 整数 | 連続 | $(3,1.5)$ | 21 | 0 |
| 整数 | 整数 | $(4,0)$ | 20 | 1 |
| 整数 | 0か1 | $(4,0)$ | 20 | 0.67 |
| 0か1 | 連続 | $(1,2.5)$ | 15 | 0 |
| 0か1 | 整数 | $(1,2)$ | 13 | 2 |
| 0か1 | 0か1 | $(1,1)$ | 9 | 0 |

連続解 $(3,1.5)$ では二つの資源を使い切ります。この値が上限になることは、制約の第1式を $3/4$ 倍、第2式を $1/2$ 倍して足すと分かります。

$$
5x_1+4x_2\le \tfrac34\times24+\tfrac12\times6=21.
$$

整数解はこの21を超えられません。ただし21を達成する点が整数であるとは限らないので、連続問題の最良点をそのまま返すことはできません。

### 丸めると何を失うか

$1.5$ を2へ丸めた $(3,2)$ は、第1資源を $26>24$、第2資源を $7>6$ 使用します。二つの制約を両方とも破り、式の上の利益23は実行できません。1へ切り下げた $(3,1)$ は可行ですが、利益19です。整数の最良点 $(4,0)$ の利益20には届きません。この三つの点を、「丸めてみる」が図に並べます。

この例ではすべての係数が正なので、切り下げが可行性を保ちます。一般の問題には、等式や最低生産量や負の係数もあります。切り下げなら常に安全という規則にはできません。丸めた後は、元の制約と目的を必ず計算し直します。

### 図の点を自分で数える

この小例なら、整数候補をすべて調べられます。非負条件と資源制約から $x_1\le4$、$x_2\le3$ なので、調べる範囲に抜けはありません。コードは連続解をLPで、整数と二値の答えを全列挙で求め、丸めた二点も評価します。

```python
from itertools import product
import numpy as np
from scipy.optimize import linprog

A = np.array([[6., 4.], [1., 2.]])
b = np.array([24., 6.])
profit = np.array([5., 4.])

def best(points):
    feasible = [np.array(x) for x in points if np.all(A @ x <= b)]
    return max(feasible, key=lambda x: profit @ x)

lp = linprog(-profit, A_ub=A, b_ub=b, bounds=(0, None), method="highs")
assert lp.success
integer = best(product(range(5), range(4)))
binary = best(product(range(2), repeat=2))
print("continuous:", lp.x, -lp.fun)                  # continuous: [3.  1.5] 21.0
print("integer:", integer, profit @ integer)         # integer: [4 0] 20.0
print("binary:", binary, profit @ binary)            # binary: [1 1] 9.0
print("rounding excess:", A @ [3, 2] - b)            # rounding excess: [2. 1.]
floor = np.array([3, 1])
print("floor:", A @ floor - b, profit @ floor)      # floor: [-2. -1.] 19.0
```

連続解は $(3,1.5)$ で利益21、整数は $(4,0)$ で20、二値は $(1,1)$ で9です。丸めた $(3,2)$ の超過量は $(2,1)$ で、切り下げた $(3,1)$ は資源に $(2,1)$ ずつ余裕があり、利益19です。ここで全列挙できるのは候補が少ないためです。数千個の二値変数に同じ方法を広げると候補数が爆発するので、[混合整数線形計画](#/learn/concept.mixed-integer-linear-program)で緩和と探索を組み合わせます。

## まず「何を選ぶか」を言葉にする

最適化でいう変数は、Pythonの`float`や`int`の型だけではありません。設計長さは連続値です。製品の採否は二値、訪問順は順列です。制御入力の時系列なら軌道が変数です。ソルバー選択の前に、**解として返したい対象がどの集合に属するか**を明示します。

生産例のように定義域を変える場合だけでなく、符号化の方法にも注意が必要です。たとえば「3種類から1つを選ぶ」問題を考えます。整数`0, 1, 2`として連続最適化器へ渡すと、選択の意味が曖昧になります。カテゴリ選択またはワンホット形式の二値を使い、制約を伴う離散問題として表す方が意味を保ちやすくなります。

| 定義域 | 典型例 | 最初に確認すること |
| --- | --- | --- |
| 連続変数 | 寸法、濃度、温度 | 上下限、尺度、微分の有無 |
| 整数・二値 | 台数、採否、オンかオフか | 緩和の最適値との差、論理条件 |
| カテゴリ / 順序付きカテゴリ | 材料種、モデル種、段階 | 順序や距離を仮定してよいか |
| 順列 / グラフ / 集合 | 順路、接続、選抜 | 専用のグラフ・マッチング・経路選択構造がないか |
| 単体 / 行列 / 多様体 | 配合比、共分散、回転 | 集合を保つ射影・パラメータ化・レトラクションがあるか |
| 軌道 / 関数 | 制御列、温度分布 | 時間離散化、動力学、連続時間での妥当性 |

## 定義域はソルバー名より先に効く

連続変数で滑らかな目的と勾配があるなら、[滑らかな局所最適化](#/learn/family.smooth-local)のような勾配法を検討できます。二値や整数の変数を連続として解いて丸めるだけでは足りません。生産の例では、丸めた $(3,2)$ が二つの資源を超えました。離散性が本質なら、[離散・組合せ最適化](#/learn/family.discrete-structure)の定式化から考えます。

定義域が特殊な集合の場合も同様です。確率の比率は単に非負な実数の並びではなく、合計1の単体です。回転行列や低ランク行列は、成分ごとの上下限だけでは本来の集合を保てません。

集合を保つ方法は複数あります。制約へ罰則を足す方法、射影や変数変換、[多様体最適化](#/learn/family.manifold)のように集合を直接扱う方法があります。たとえば合計1の配合比では、罰則を足すと合計がずれた解が返ることがあります。射影や変数変換なら、返る点はいつも合計1です。

## 連続緩和は便利だが、元の問題ではない

整数・二値問題の連続緩和の大域最適値は、最小化では下界、最大化では上界です。この例では、緩和の最適値21が整数の最適値20の上界になっています。緩和の解は、探索の出発点や感度の見積もりに使えます。branch-and-boundの部分問題にも使われます。

ただし、緩和解の`x = 0.37`は「0か1を選ぶ」という元の意思決定そのものではありません。丸めや整数化の後には、目的値と制約違反と最適性証明を改めて評価します。

::: warning
「変数が数値で表せる」ことと、「連続最適化として扱ってよい」ことは別です。カテゴリ／順列／論理／行列構造を安易に連続値へ符号化すると、ソルバーが動いても解の意味を壊すことがあります。
:::

## 診断するときの最小チェック

解法を比較する前に、次を記録しておくと切替理由を追えます。

- 各変数の定義域、単位、上下限、許容精度（例: AもBも個数なので整数で、資源から $x_1\le4$、$x_2\le3$）
- 整数・カテゴリの符号化と、無効な組合せを除く制約（例: 採否の変数には $x\le1$ の上限を明示する）
- 連続緩和を使う場合は、丸め・修正後に再評価した可行性と目的値（例: $(3,2)$ は資源1を2超過する）
- 軌道なら、時間刻み、制御の保持方法、区間内制約の確認方法
- 特殊集合なら、射影・パラメータ化・レトラクションのどれで集合を保つか

定義域のほかに、目的の滑らかさと制約の種類と1回の評価に使える予算も、解法の選択を絞ります。定義域だけで万能なソルバーは決まりませんが、定義域と矛盾する選択は早い段階で除外できます。

## 出典と再現条件

変数を連続・整数として指定するAPI、上下限、最小化の符号の約束は [SciPy 1.17.0の `linprog` 公式文書](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.optimize.linprog.html)で確認できます。本稿の実行環境はNumPy 2.3.5、SciPy 1.17.0です。

生産の数値例と図は本稿の教材用です。整数・二値の答えは全候補の列挙、連続解の値は非負の重み付き制約による上限21と照合しました。別の問題でも同じ解法が速いという性能比較ではありません。
