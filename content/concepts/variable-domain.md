変数の定義域は、最適化で何を動かせるかを決め、使える定式化・ソルバー・保証の範囲を最初に絞る分類です。

## まず「何を選ぶか」を言葉にする

最適化でいう変数は、Pythonの`float`や`int`の型だけではありません。設計長さは連続値です。製品の採否は二値、訪問順は順列です。制御入力の時系列なら軌道が変数です。ソルバー選択の前に、**解として返したい対象がどの集合に属するか**を明示します。

同じ実装でも、表現を変えると別の問題になります。たとえば「3種類から1つを選ぶ」問題を考えます。整数`0, 1, 2`として連続最適化器へ渡すと、選択の意味が曖昧になります。カテゴリ選択またはワンホット形式の二値を使い、制約を伴う離散問題として表す方が意味を保ちやすくなります。

| 定義域 | 典型例 | 最初に確認すること |
| --- | --- | --- |
| 連続変数 | 寸法、濃度、温度 | 上下限、尺度、微分の有無 |
| 整数変数 / 二値 | 台数、採否、オン／オフ | 線形緩和の強さ、論理制約、許容する最適性ギャップ |
| カテゴリ / 順序付きカテゴリ | 材料種、モデル種、段階 | 順序や距離を仮定してよいか |
| 順列 / グラフ / 集合 | 順路、接続、選抜 | 専用のグラフ・マッチング・経路選択構造がないか |
| 単体 / 行列 / 多様体 | 配合比、共分散、回転 | 集合を保つ射影・パラメータ化・レトラクションがあるか |
| 軌道 / 関数 | 制御列、温度分布 | 時間離散化、動力学、連続時間での妥当性 |

## 定義域はソルバー名より先に効く

連続変数で滑らかな目的と勾配があるなら、[滑らかな局所最適化](#/learn/family.smooth-local)のような勾配法を検討できます。一方、二値や整数を連続変数として解いて丸めるだけでは不十分です。丸め後の解が制約を満たすとは限らず、最適性ギャップの解釈も失われます。離散性が本質なら、[離散・組合せ最適化](#/learn/family.discrete-structure)の定式化から考えます。

定義域が特殊な集合である場合も同様です。確率の比率は単に非負な実数の並びではなく、合計1の単体です。回転行列や低ランク行列は、成分ごとの上下限だけでは本来の集合を保てません。

制約へ罰則を足す方法もあります。射影／変数変換／[多様体最適化](#/learn/family.manifold)のように集合を直接扱う方法もあります。各方法の数値条件と実行可能性を比較します。

## 連続緩和は便利だが、元の問題ではない

整数・二値問題の連続緩和は、下界／初期解／感度解析／branch-and-boundの部分問題として役立つことがあります。ただし、緩和解の`x = 0.37`は「0か1を選ぶ」という元の意思決定そのものではありません。丸めや整数化の後には、目的値・制約違反・最適性証明を改めて評価します。

同じ注意は軌道にもあります。時間を粗く離散化した制約を満たしても、連続時間の途中で安全制約を満たす保証には直結しません。必要ならメッシュ細分化、区間内検証、または連続時間の制約を扱う定式化を追加します。

::: warning
「変数が数値で表せる」ことと、「連続最適化として扱ってよい」ことは別です。カテゴリ／順列／論理／行列構造を安易に連続値へ符号化すると、ソルバーが動いても解の意味を壊すことがあります。
:::

## 診断するときの最小チェック

解法を比較する前に、次を記録しておくと切替理由を追えます。

- 各変数の定義域、単位、上下限、許容精度
- 整数・カテゴリの符号化と、無効な組合せを除く制約
- 連続緩和を使う場合は、丸め・修正後に再評価した可行性と目的値
- 軌道なら、時間刻み、制御の保持方法、区間内制約の確認方法
- 特殊集合なら、射影・パラメータ化・レトラクションのどれで集合を保つか

次に、定義域以外の3点を並べます。

- 目的の形が滑らかか
- 制約が何か
- 1回の評価にどれだけの予算を使えるか

定義域だけで万能なソルバーは決まりませんが、定義域と矛盾する選択は早い段階で除外できます。
