双対可行性（双対実行可能性）を保ったまま、実行不能な基底を直し、LPの基底を効率よく再最適化する単体法の変種です。

## 30秒でつかむ

二つの製品の生産量を決めるLPを解き、$(x_1,x_2)=(3,1.5)$、利益21を得たとします。そこへ「製品2は1まで」という条件が加わります。前の点は使えませんが、前に求めた基底と目的の係数は、すべて捨てる必要があるでしょうか。

双対単体法は、追加条件のせいで負になった余りを、基底の交換で修復します。本例では交換は1回。新しい解は $(10/3,1)$、利益 $62/3$ です。利益が下がるのは、許される範囲を狭めたからであり、計算の失敗ではありません。

最初から計画を立て直す代わりに、値段の付け方を保ったまま、破れた条件だけを直していきます。これが双対単体法です。

- **見るもの**: 基底変数の値のうち、負になっているもの（実行不能な行）
- **動かすもの**: 基底。負の行の変数を外し、被約費用の符号を崩さない変数を入れる
- **前進の判断**: 負の値がなくなれば最適で止まる。直せる列がなければ、その問題は実行不能

主単体法は「常に実行可能で、目的値を改善する」手法でした。双対単体法は向きが逆で、「常に最適性の条件を満たし、実行可能性を回復する」手法です。

## 一手の意味

### まず最大化の符号規約を固定する

最大化 $\max c^\top x$、$Ax=b$、$x\ge0$ を考えます。基底とは、等式を満たすために解く変数の組です。残りの非基底変数を0に置き、基底行列 $B$ を使って $x_B=B^{-1}b$ を求めます。この値に負があれば、その**基底に対応する点**は主問題で実行不能です。基底という語そのものに実行可能という意味はありません。

本稿は表を次の形で書きます。

$$
x_B+\alpha x_N=\bar b,\qquad
z+\rho^\top x_N=z_0,\qquad
\rho=c_B^\top B^{-1}A_N-c_N^\top.
$$

つまり $z=z_0-\rho^\top x_N$ です。$\rho\ge0$ なら、非基底変数を増やしても $z_0$ より大きな目的値にはなりません。これが本稿の双対可行な符号です。よく使われる被約費用 $r=c_N^\top-c_B^\top B^{-1}A_N$ とは $\rho=-r$ の関係で、最大化の標準的な条件 $r\le0$ と同じ内容です。以後「被約費用」と書く数は、この目的行の $\rho$ です。

この上界の解釈は、途中の基底点が可行であることを主張しません。負の基本変数が残る間は、$z_0$ を採用可能な計画の利益と取り違えないでください。

### 出る行を決めてから、入る列を選ぶ

一手は、値が負の基底変数を一つ選んで外し、代わりに入る変数を比の最小値で選ぶ操作です。
比の最小値で選ぶことで、すべての被約費用を0以上に保ったまま、負の値を持つ行を直せます。

| | 主単体法 | 双対単体法 |
|---|---|---|
| 常に保つもの | 実行可能性（基底変数が0以上） | 双対可行性（被約費用が0以上） |
| 直していくもの | 目的値 | 実行可能性 |
| 先に選ぶもの | 入る変数（被約費用が負） | 出る変数（値が負の基底変数） |
| 後で選ぶもの | 出る変数（比の最小値） | 入る変数（比の最小値） |
| 止まる条件 | 被約費用がすべて0以上 | 基底変数がすべて0以上 |

出る行を $r$ とします。その行の非基底変数の係数を $\alpha_{rj}$、上の規約の被約費用を $\rho_j$ とすると、入る変数は次で選びます。

$$
j^\star=\arg\min_{j:\,\alpha_{rj}<0}\;\frac{\rho_j}{-\alpha_{rj}}
$$

負の値を持つ行を直すには、その行で係数が負の変数を増やすしかありません。係数が負の変数だけが候補になるのは、そのためです。
最小の比を選ぶと、ピボット（pivot）の後も被約費用が0以上のまま残ります。
候補が一つもない行があれば、その行の式は満たせないと分かり、問題は実行不能です。

最適性の条件を保つので、途中の目的値は最適値の界になります。最大化なら、目的値は最適値より大きい側から下がってきます。

## 小さな例

[混合整数線形計画](#/learn/concept.mixed-integer-linear-program)の小さな例を使います。

$$
\max\; 5x_1+4x_2 \quad \text{s.t.}\quad 6x_1+4x_2\le 24,\;\; x_1+2x_2\le 6,\;\; x\ge 0
$$

整数条件を外したLP（緩和）の最適解は $(3,\,1.5)$ で、目的値は $21$ です。
余り変数を $s_1,s_2$ とすると、最適な基底は $\{x_1,x_2\}$ で、表の式は次のとおりです。

$$
x_1+\tfrac14 s_1-\tfrac12 s_2=3,\qquad x_2-\tfrac18 s_1+\tfrac34 s_2=\tfrac32
$$

目的行は

$$z+\tfrac34s_1+\tfrac12s_2=21$$

です。被約費用 $\rho$ は $s_1$ が $3/4$、$s_2$ が $1/2$ で、どちらも0以上です。この基底は最適性の条件を満たしています。

ここで、分枝限定法が $x_2$ を分ける場面を考えます。一方の枝の条件は $x_2\le1$ です。
新しい余り変数 $t$ を使って $x_2+t=1$ と書き、基底に入っている $x_2$ を上の式で置き換えると、新しい行が得られます。

$$
t+\tfrac18 s_1-\tfrac34 s_2=-\tfrac12
$$

基底変数 $t$ の値が $-1/2$ で負です。前の最適解 $(3,\,1.5)$ が、新しい条件 $x_2\le1$ を破っていることを表しています。被約費用は変わらないので、双対可行性は保たれています。

- **出る変数**: 値が負の $t$
- **入る変数の候補**: この行で係数が負なのは $s_2$（$-3/4$）だけ。比は $(1/2)\div(3/4)=2/3$
- **結果**: $s_2$ が入ります。$x_1=10/3$、$x_2=1$ で、目的値は $62/3\approx20.67$ です。負の値は消え、被約費用も $5/6,\,2/3$ で0以上です

### 表の一行を実際に割る

新しい行を $-3/4$ で割ると、入る $s_2$ の係数が1になります。

$$
s_2-\tfrac16s_1-\tfrac43t=\tfrac23.
$$

この式で他の行から $s_2$ を消すと、基底は $\{x_1,x_2,s_2\}$ に変わります。

$$
\begin{aligned}
x_1+\tfrac16s_1-\tfrac23t&=\tfrac{10}{3},\\
x_2+t&=1,\\
s_2-\tfrac16s_1-\tfrac43t&=\tfrac23,\\
z+\tfrac56s_1+\tfrac23t&=\tfrac{62}{3}.
\end{aligned}
$$

非基底の $s_1=t=0$ を置くと、基本変数は $10/3,1,2/3$ で全部非負です。目的行の係数も非負なので、これより大きい利益は得られません。主可行性と双対可行性の両方が揃いました。

![追加前の可行領域とx2が1以下の新領域、旧頂点3 1.5と修復後10/3 1。右表は負のtが基底を出てs2が入り、目的行の非負係数を保つ一回の交換を示す。](./media/dual-simplex-one-pivot.svg "有理数の一回ピボットと同じ数値を描画。ソルバーの実行時間や一般的な反復回数を比較する図ではありません。")

図の橙の点は新しい横線より上にあり、追加後には使えません。右表の $t=-1/2$ は、その同じ違反を代数で表しています。点を線の下へ動かすことと、基底の負の値をなくすことを対応させて読んでください。

### 元の式からも最適性を証明する

追加後の3制約に、順に $5/6,0,2/3$ を掛けて足します。係数は非負なので不等号の向きは変わりません。

$$
\tfrac56(6x_1+4x_2)+0(x_1+2x_2)+\tfrac23 x_2
\le \tfrac56\cdot24+\tfrac23\cdot1.
$$

左辺はちょうど $5x_1+4x_2$、右辺は $62/3$ です。したがってすべての可行解の利益は $62/3$ 以下で、見つけた点がその値に達します。この非負の係数の組が双対解です。表の数字を信用するだけでなく、元の制約へ戻して検算できます。

一回のピボットで最適な基底に戻りました。頂点は $(3,\,1.5)$ から $(10/3,\,1)$ へ動き、目的値は $21$ から $20.67$ へ下がっています。

各部分問題で、それぞれ親の最適基底から始めて、ほかの枝も一回ずつのピボットで再最適化できます。

| 追加した条件 | 負になった値 | 入る変数（比） | 再最適化後の頂点 | 目的値 |
|---|---:|---|---|---:|
| $x_2\le1$（根から） | $-1/2$ | $s_2$（$2/3$） | $(10/3,\,1)$ | $20.67$ |
| $x_2\ge2$（根から） | $-1/2$ | $s_1$（$6$） | $(2,\,2)$ | $18$ |
| $x_1\le3$（ $x_2\le1$ の枝から） | $-1/3$ | $s_1$（$5$） | $(3,\,1)$ | $19$ |
| $x_1\ge4$（ $x_2\le1$ の枝から） | $-2/3$ | $t$（$1$） | $(4,\,0)$ | $20$ |

四つの部分問題のどれも、最初から解き直さず、親の基底から一回のピボットで最適解に着きました。
[分枝限定法](#/learn/branch-and-bound)の探索木の各探索点（部分問題）を、この形で再最適化しています。

## 向く条件・避ける条件

双対単体法が自然なのは、直前の最適な基底が実行不能になる場面です。

- MILPの各探索点（部分問題）でLP緩和を再最適化する
- 既存のLPへ制約やカットを追加する
- 変数の上下限（界）を変更する
- パラメータやシナリオを変えたあとに再最適化する
- 前処理後に得られた基底を使う
- 疎な大規模LP

利用者がアルゴリズムを直接選ばなくても、LP・MIPソルバーが内部で自動的に選ぶ場合があります。

向いている条件は次のとおりです。

- LPの構造が明示されている
- 基底のウォームスタートが有効
- 制約を追加したあとの再最適化
- 係数のモデルを厳密に解く（ブラックボックス探索ではない）

避ける、または切り替える場面は次のとおりです。

- 非線形・非凸な関係を無理にLPへ直している。[非線形内点法](#/learn/interior-point-nlp)など別の手法を検討します。
- 係数の尺度が極端。まず単位を揃えます。
- 密で巨大なLP。[主双対障壁法](#/learn/barrier-lp-qp)が向く場合があります。
- ブラックボックスの目的関数。LPの前提が成り立ちません。
- LPの解だけで整数条件が満たされたと誤解している。整数性は[分枝限定法](#/learn/branch-and-bound)や[branch-and-cut](#/learn/branch-and-cut)で扱います。

## Python

小さな例の一回のピボットを、分数のまま再現します。根の最適な表から始め、`x2 <= 1` の行を足して、負の値を持つ行を直します。

```python
from fractions import Fraction as F

from scipy.optimize import linprog

names = ["x1", "x2", "s1", "s2", "t"]
# 根の最適な表（最大化 5 x1 + 4 x2）。基底は x1, x2。右端は右辺、最後の行は被約費用と目的値
rows = [
    [F(1), F(0), F(1, 4), F(-1, 2), F(0), F(3)],
    [F(0), F(1), F(-1, 8), F(3, 4), F(0), F(3, 2)],
]
cost = [F(0), F(0), F(3, 4), F(1, 2), F(0), F(21)]
basis = [0, 1]

# 条件 x2 <= 1 を足す。x2 + t = 1 から、基底に入っている x2 を消して行にする
new = [F(0), F(1), F(0), F(0), F(1), F(1)]
new = [a - new[1] * b for a, b in zip(new, rows[1])]
rows.append(new)
basis.append(4)

while any(row[-1] < 0 for row in rows):
    r = min(range(len(rows)), key=lambda i: rows[i][-1])  # 最も負の行が出る
    candidates = [j for j in range(5) if rows[r][j] < 0]  # 負の係数の列だけが入れる
    if not candidates:
        raise SystemExit("この部分問題は実行不能")
    j = min(candidates, key=lambda j: cost[j] / -rows[r][j])  # 被約費用を崩さない比
    print("出る:", names[basis[r]], "値", rows[r][-1], "入る:", names[j])
    pivot = rows[r][j]
    rows[r] = [v / pivot for v in rows[r]]
    for i in range(len(rows)):
        if i != r:
            rows[i] = [a - rows[i][j] * b for a, b in zip(rows[i], rows[r])]
    cost = [a - cost[j] * b for a, b in zip(cost, rows[r])]
    basis[r] = j

solution = {names[b]: rows[i][-1] for i, b in enumerate(basis)}
print("x1 =", solution["x1"], " x2 =", solution["x2"], " 目的値 =", cost[-1])

check = linprog([-5, -4], A_ub=[[6, 4], [1, 2]], b_ub=[24, 6],
                bounds=[(0, None), (0, 1)], method="highs-ds")
print(check.x, -check.fun)
```

```text
出る: t 値 -1/2 入る: s2
x1 = 10/3  x2 = 1  目的値 = 62/3
[3.33333333 1.        ] 20.666666666666668
```

最後の二行は、`x2` の上限を1にして `highs-ds` で最初から解き直した独立確認です。SciPyへ手計算の基底を渡していないため、この呼出しはウォームスタート実験ではありません。手計算と同じ $(10/3,\,1)$ が得られます。
[`highs-ds` の公式リファレンス](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs-ds.html)では、HiGHSの双対改訂単体法を指定します。実装バージョン・前処理・尺度の調整・許容誤差は診断値として記録します。

## 診断値

- 実行可能性の残差（主問題の実行可能性の残差）
- 双対の実行可能性の残差（双対問題の実行可能性の残差）
- 目的値
- 基底の状態
- 単体法の反復数
- 退化とピボットの停滞
- 前処理で減った変数・制約の数
- 状態。実行不能か非有界か
- 数値の警告

判断の目安は次のとおりです。
基底変数の負の値が許容誤差の範囲でなくなれば、最適で止まります。
反復数が増えても目的値が動かなければ、退化による停滞を疑います。

LPの `infeasible` と `unbounded` は別の状態です。モデルの誤り・単位・上下限・符号を確認し、ソルバーの終了状態を単に「失敗」とまとめません。

::: note
単体法の反復数を内点法の反復数と直接比較しません。また、本例の1回のピボットだけからウォームスタートが常に速いとも結論しません。一反復の計算内容・分解（行列分解）・基底解への変換・ウォームスタートの有無が異なります。
:::

## 失敗・切替の兆候

| 症状 | 考えられる原因 | 対処 |
|---|---|---|
| 目的値が動かないままピボットが続く | 退化による停滞。複数の基底が同じ頂点を表している | 巡回防止、価格付け、摂動（perturbation）の設定を確認する。実装依存なので設定を記録する |
| 入る変数の候補が一つもない行が出る | 追加した条件が他の制約と両立しない（実行不能） | 条件・単位・符号を見直す。MILPの探索点なら、その枝を打ち切る |
| 係数の尺度が桁違いで数値警告が出る | 単位の不揃い | 単位を揃えて尺度を調整する |
| 密で巨大なLPで、分解が重くなる | 単体の一反復あたりの仕事量が大きい | [主双対障壁法](#/learn/barrier-lp-qp)を試す |
| LPの解が整数にならない | 整数条件はLPの中にない | 整数性は[分枝限定法](#/learn/branch-and-bound)側で扱う |

## コラム: 退化とピボットの停滞

複数の基底が同じ頂点を表す退化では、ピボットしても目的値が変わらないことがあります。
巡回防止、価格付け、摂動などの対処は実装依存です。ソルバーの設定として記録しておくと、再現しやすくなります。

## 一つ確認してから次へ

目的行を通常の被約費用 $r=-\rho$ で書き直すと、根では $r_{s_1}=-3/4,r_{s_2}=-1/2$、修復後では $r_{s_1}=-5/6,r_t=-2/3$ です。数字の符号が変わっても、最大化の双対可行性は同じです。

最後の点 $x_1=10/3$ は整数ではありません。双対単体法が証明したのは、この枝の**LP緩和**の最適性です。生産量が整数でなければならない場合、分枝限定側の仕事はまだ残っています。
