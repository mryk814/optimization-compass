排出を30以下にしたい。その範囲で最も安い生産計画は何でしょうか。ε制約法では、この「30以下」を制約として固定し、費用だけを最小化します。上限を24へ下げたら、別の単目的問題をもう一度解きます。

ここでは同じ需要18・二つの生産技術を使い、上限36、30、24、18、12を順に比べます。最後の12で解がないことも、有効な結果です。重みの交換率より、許せる排出量を直接指定したいときに向く方法です。

## 30秒でつかむ

二目的をどちらも最小化するとき、$f_1$ を主目的、$f_2$ を許容条件へ移します。

$$\min_{x\in X} f_1(x)\qquad\text{subject to}\quad f_2(x)\le\epsilon.$$

- **固定するもの**: 元の需要や変数の範囲、主目的、目的の単位
- **動かすもの**: $\epsilon$。閾値ごとに可行集合が変わる
- **読むもの**: 得られた計画と二つの目的値、実行不能かどうか、部分問題をどこまで厳密に解いたか

$\epsilon$ は目的間の交換率ではなく許容上限です。選択した解では、排出が上限ぴったりになるとは限りません。また、上限を等間隔に変えても、別々の解が等間隔に得られるとは限りません。

## 小さな例を定式化する

技術XとYを、それぞれ何単位動かすか決めます。決定変数を整数 $x,y$ とし、今回の列挙範囲は $0\le x,y\le10$ です。

| 技術 | 1単位の生産量 | 費用 | 排出 |
|---|---:|---:|---:|
| X | 3 | 8 | 6 |
| Y | 2 | 7 | 2 |

需要は18以上。費用と排出を同時に小さくしたいので、まず排出を制約側へ置きます。

$$
\begin{aligned}
\min_{x,y}\quad &8x+7y\\
\text{subject to}\quad &3x+2y\ge18,\\
&6x+2y\le\epsilon,\\
&x,y\in\{0,1,\dots,10\}.
\end{aligned}
$$

この範囲の121計画のうち、需要を満たすのは88計画です。「88」は排出制約まで守る数ではなく、閾値を決める前の需要可行計画の数です。過剰生産を禁止していないので、$3x+2y=18$ だけを調べるのでは足りません。

### 一手を追う：上限36から30へ

排出上限36では $(x,y)=(6,0)$ が使えます。生産18、費用48、排出36です。上限を30にすると、この計画は費用が安くても失格になります。

Xを2単位減らし、Yを3単位足した $(4,3)$ を試します。生産は $3\cdot4+2\cdot3=18$ のまま、費用は $8\cdot4+7\cdot3=53$、排出は $6\cdot4+2\cdot3=30$。排出を6減らす代わりに費用が5増えました。

これは一つの可行計画です。さらに安い計画がないかは、全列挙か下界で別に確かめます。

### 元の式から費用の下界を作る

生産量を $q=3x+2y$、排出を $e=6x+2y$ と置くと、費用は正確に

$$8x+7y=\frac{13}{3}q-\frac56e$$

です。$q\ge18$、$e\le\epsilon$ なので

$$8x+7y\ge78-\frac56\epsilon.$$

$\epsilon=30$ なら下界は53。いま作った $(4,3)$ の費用53と一致するため、この閾値の部分問題では最適です。下の36、24、18でも、それぞれ48、58、63の下界を達成します。

| 排出上限 $\epsilon$ | X | Y | 生産 | 費用 | 排出 | 結論 |
|---:|---:|---:|---:|---:|---:|---|
| 36 | 6 | 0 | 18 | 48 | 36 | 最適 |
| 30 | 4 | 3 | 18 | 53 | 30 | 最適 |
| 24 | 2 | 6 | 18 | 58 | 24 | 最適 |
| 18 | 0 | 9 | 18 | 63 | 18 | 最適 |
| 12 | — | — | — | — | — | 実行不能 |

上限12の実行不能も式で分かります。排出は $6x+2y=(3x+2y)+3x\ge18$ なので、需要18を満たす限り18未満へ下げられません。ソルバーがたまたま計画を見つけなかった、という意味ではありません。

新しい図は、横軸が排出そのものではなく**許容上限**です。たとえば $\epsilon=29.9$ では $(4,3)$ が使えず、最適は $(2,6)$、排出24、費用58へ飛びます。排出には5.9の余裕が残ります。図の白丸はその区間に含まれない端、塗りつぶした点は含まれる端です。

$\epsilon$ を少し変えても同じ解が続く区間と、一気に入れ替わる境界があります。これを同じ問題の最適化反復の停滞とは読みません。毎回、違う可行集合を持つ問題を解いています。

## Pythonで同じ88計画を調べる

以下は既存の整数列挙を使います。主目的の費用が同じなら排出の小さい計画を先にし、さらに同じならX、Yの順で決めます。この辞書式の規則は、出力の再現性だけでなく、費用同値で排出だけ悪い点を選ばないためにも必要です。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Plan:
    x_count: int
    y_count: int
    output: int
    cost: int
    emissions: int


def enumerate_plans(demand: int = 18) -> list[Plan]:
    plans = []
    for x_count in range(11):
        for y_count in range(11):
            output = 3 * x_count + 2 * y_count
            if output < demand:
                continue
            plans.append(
                Plan(
                    x_count=x_count,
                    y_count=y_count,
                    output=output,
                    cost=8 * x_count + 7 * y_count,
                    emissions=6 * x_count + 2 * y_count,
                )
            )
    return plans


def solve_for_epsilon(
    plans: list[Plan],
    epsilon: int,
) -> Plan | None:
    eligible = [plan for plan in plans if plan.emissions <= epsilon]
    if not eligible:
        return None
    return min(
        eligible,
        key=lambda plan: (plan.cost, plan.emissions, plan.x_count, plan.y_count),
    )


plans = enumerate_plans()
for epsilon in (36, 30, 24, 18, 12):
    solution = solve_for_epsilon(plans, epsilon)
    if solution is None:
        print(f"epsilon={epsilon}: infeasible")
        continue
    print(
        f"epsilon={epsilon}: X={solution.x_count}, Y={solution.y_count}, "
        f"cost={solution.cost}, emissions={solution.emissions}"
    )
```

```text
epsilon=36: X=6, Y=0, cost=48, emissions=36
epsilon=30: X=4, Y=3, cost=53, emissions=30
epsilon=24: X=2, Y=6, cost=58, emissions=24
epsilon=18: X=0, Y=9, cost=63, emissions=18
epsilon=12: infeasible
```

このコードと表は同じデータです。全列挙なので、`None` はこの有限範囲に可行計画がないことを意味します。検証では同じ整数モデルをSciPyのMILPでも解き、4つの最適費用と12の実行不能を照合しました。大きな問題では列挙を内部ソルバーへ置き換えますが、そこで時間制限に達した `UNKNOWN` と、証明された実行不能を混同しません。

## Pareto最適性には同点の扱いも必要

$\epsilon$ 制約の主目的を大域的に解いただけでは、一般には弱Pareto最適性までしか保証されません。費用が同じ解が複数あると、排出の悪い方も費用最小だからです。

二目的なら、最小費用を確定した後、その費用の解の中で排出を最小にすれば、Pareto最適なものを選べます。本コードの `(cost, emissions, ...)` はこれを有限列挙で行っています。ある点がこの選択を支配すると仮定すると、費用が低ければ最初の最小化に矛盾し、費用が同じで排出が低ければ二段目に矛盾するためです。

逆に、あるPareto点 $x^*$ の他目的値をそのまま閾値に設定すれば、その点は主目的最小化の最適解になります。それより主目的が良い可行点があれば $x^*$ を支配してしまうからです。この性質には凸性は要りません。ただし、適切な閾値を選び、各部分問題を大域的に解くことが前提です。有限個の粗い閾値だけで全フロントを得られるという保証ではありません。

閾値の生成、重複計算、弱Pareto点を避ける二段階求解は、[Laumanns・Thiele・Zitzlerの原論文](https://drops.dagstuhl.de/entities/document/10.4230/DagSemProc.04461.6)でも扱われています。ここではその適応アルゴリズムを実装したのではなく、固定5閾値で原理を確認しています。

## 非凸な場合にできることと、この例の限界

[重み付き和](#/learn/weighted-sum)では、どの重みでも選べない非支持Pareto点があります。ε制約法は可行集合を閾値で切るため、そのような点も選び得ます。[多目的定式化の金具の例](#/learn/concept.multiobjective-optimization)では、重さ $t\le0.5$ のもとでたわみ $1-t^2$ を最小にすると $t=0.5$。重み付き和が逃す前線の途中の点 $(0.5,0.75)$ を取れます。これは本稿の生産例とは別の反例です。

重要なのは、**本稿の4生産計画は非支持点の実演ではない**ことです。4点は費用と排出の空間で同一直線上にあり、すべて

$$\text{費用}+\frac56\,\text{排出}=78$$

を満たします。この重みでは4点とも最適な支持点です。重み付き和ソルバーが一つしか返さないことと、どの重みでも最適になれないことを区別します。整数変数があるだけで、必ず非支持点があるわけではありません。

## 閾値の選び方と停止の読み方

排出の単位を1000倍にしたら、同じ許容条件を表す $\epsilon$ も1000倍にします。片方だけ変えると、別の条件になります。重み付き和のように二つの異なる単位を足しませんが、閾値をどの単位・精度・間隔で指定したかは必要です。

- **まず範囲を決める**: 各目的だけを最適化した解などから、現実的な閾値範囲を調べる。本例は排出18未満が不可能
- **重複をまとめる**: 本例の25、26、27はすべて同じ計画。細かい格子の数を、そのまま得た解の数にしない
- **実行不能を残す**: その閾値が不可能と証明されたのか、予算内に解が見つからなかっただけかを記録する
- **部分問題の保証を引き継ぐ**: 局所解やギャップ付きの解なら、得たPareto集合にもその限界が残る
- **多数目的では領域を絞る**: 閾値の組合せが増えるため、必要な妥協領域へ集中する。広い探索なら[NSGA-III](#/learn/nsga-iii)などとも比べる

比較では、元モデル、目的の単位、閾値の集合、内部ソルバーの許容誤差と計算予算を揃えます。閾値ごとの可行性、元の目的値、重複数、最良界、総計算時間を記録すれば、どの領域をどこまで確かめたか説明できます。
