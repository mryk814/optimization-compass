TPE（Tree-structured Parzen Estimator）は、観測済みの設定を目的値の良い群と残りの群に分け、両者の密度を比べて次の設定を提案する方法です。ここで大きな密度比は、**実測済みの良さではなく、次に測る場所の優先度**です。同じ5観測を図、数値、Pythonで追います。

## 30秒でつかむ

成功した試作品によく現れ、残りの試作品にはあまり現れない設定を探すイメージです。目的関数 $f(x)$ の曲面を直接当てはめる代わりに、良い結果に対応する設定の分布と、残りの分布を作ります。

- 入力するもの：設定、目的値、試行の状態を含む履歴
- 作るもの：良い群の密度 $l(x)$ と残りの密度 $g(x)$
- 提案に使うもの：密度比 $l(x)/g(x)$

[ベイズ最適化](#/learn/bayesian-optimization)と同じく履歴を活用する逐次探索ですが、モデル化の向きが異なります。

## 一手の意味

### なぜ比を比べるのか

TPEは、閾値より良い結果が出たときの設定分布を $l$、それ以外を $g$ として、期待改善に基づく候補の順位へつなげます。この考え方の一次資料は[Bergstraらの原論文](https://proceedings.neurips.cc/paper/2011/hash/86e8f7ab32cfd12577bc2619bc635690-Abstract.html)です。

直感的には、良い群でも残りの群でもよく現れる場所は、良い結果に特有ではありません。良い群で高い密度を持ちながら、残りでは低い場所を優先するために比を使います。ただし履歴が少ないと、分母の小ささだけが目立つなど推定が不安定になります。

## 小さな例

### 5観測を二つの群へ分ける

1変数の教材として $f(x)=(x-1)^2$ の5点を観測したとします。

| 設定 $x$ | 観測した目的値 | 群 |
|---:|---:|---|
| −1.0 | 4.00 | 残り |
| 0.0 | 1.00 | 残り |
| 0.8 | 0.04 | 良い |
| 1.2 | 0.04 | 良い |
| 3.0 | 4.00 | 残り |

小さい値が良い最小化です。説明用の閾値 $y^*=0.5$ で分けると、良い群は $\{0.8,1.2\}$、残りは $\{-1,0,3\}$ です。良い群の割合は $\gamma=2/5=0.4$。この閾値は教材用に固定したもので、Optunaの既定の群分けを再現していません。

![同じ5点を目的値で群分けし、固定帯域の二つの密度と密度比を作る。次の比較候補0、1、2では1が最大となり、その後の実測値0を左に白抜きで示す。](./media/tpe-five-observations.svg "色付き5点は提案前の情報です。白抜きの点は提案後の実測で、最初の密度を作る材料には含みません。")

左の色付き5点が提案前に持っていた情報です。白抜きの点 $x=1$ は、提案してから新たに測った結果であり、最初の密度を作る材料には含めていません。

### 小さな山を重ねて密度を作る

各観測位置の周囲に、標準偏差 $h=0.5$ のガウス密度を置き、群内で平均します。

$$
K_h(x-a)=\frac{1}{h\sqrt{2\pi}}
\exp\left(-\frac{(x-a)^2}{2h^2}\right),
$$

$$
l(x)=\frac12\sum_{a\in\{0.8,1.2\}}K_h(x-a),\qquad
g(x)=\frac13\sum_{a\in\{-1,0,3\}}K_h(x-a).
$$

両方とも実数全体で積分すると1になります。良い群が2点、残りが3点であるため、それぞれ2と3で割る必要があります。単に山の和を取ると群の件数まで密度に混ざります。

図中央では良い群の密度が1付近に集まり、残りの密度は−1、0、3付近で高くなっています。

### 次の3候補を比較する

候補を $x\in\{0,1,2\}$ の3点に限って、密度を計算します。

| 候補 $x$ | 正規化した $l(x)$ | 正規化した $g(x)$ | 比 $l/g$ |
|---:|---:|---:|---:|
| 0 | 0.133315 | 0.301956 | 0.441507 |
| 1 | 0.736540 | 0.036172 | 20.361931 |
| 2 | 0.133315 | 0.036083 | 3.694666 |

3候補では $x=1$ の比が最大です。元記事の「密度相当値」では共通係数 $1/(0.5\sqrt{2\pi})$ を省略していました。係数を含めた表でも比は同じで、たとえば $x=1$ の未正規化値は $l=0.923116$、$g=0.045335$ です。

ここで $l/g=20.36$ は成功確率20.36でも、目的値が20倍良くなるという意味でもありません。二つの条件付き密度の比です。また、図右の曲線は1と2の間でもっと高くなります。**この3候補の中で1が最良**という結果を、連続空間全体で密度比を最大にした結果と混同しないでください。

今回は提案後に $f(1)=0$ と測れ、最良値が0.04から0へ改善しました。一方、同じ図の $x=1.45$ では密度比が約85.14とさらに大きいのに、実測すると $f(1.45)=0.2025$ で、既存最良値0.04より悪くなります。この同じ小例でも、密度比の大きさが目的値の良さを保証しないことを確かめられます。

## 向く条件・避ける条件

### 向く条件と診断

ハイパーパラメータ探索や、連続・整数・カテゴリ・条件付きパラメータが混ざる問題で候補になります。履歴が極端に少ない、目的の評価方法が途中で変わる、失敗試行の記録が欠けると、密度比較の前提が弱くなります。

## Python

### Pythonで同じ密度比を計算する

NumPy 2.3.5、SciPy 1.17.0で実行しました。これは固定帯域Gaussian KDEの教材コードであり、OptunaのTPE実装ではありません。

```python
import numpy as np
from scipy.special import logsumexp


def log_density(x, observations, bandwidth=0.5):
    x = np.atleast_1d(x)
    z = -0.5 * ((x[:, None] - observations[None, :]) / bandwidth)**2
    return (logsumexp(z, axis=1) - np.log(len(observations))
            - np.log(bandwidth * np.sqrt(2 * np.pi)))


good = np.array([0.8, 1.2])
bad = np.array([-1.0, 0.0, 3.0])
candidates = np.array([0.0, 1.0, 2.0])
log_l = log_density(candidates, good)
log_g = log_density(candidates, bad)
log_ratio = log_l - log_g
chosen = candidates[np.argmax(log_ratio)]
print(np.exp(log_l), np.exp(log_g), np.exp(log_ratio))
print(chosen, (chosen - 1)**2)
# ratio ≈ [0.44150666, 20.36193105, 3.69466561]
# chosen=1.0, new observed value=0.0
```

小さな密度を直接割る代わりに対数差を使っています。検証では、離れた $x=100$ で両密度が浮動小数点上の0になり、単純な比が $0/0$ になることを確認しました。対数比は約−704.474535と有限です。順位を付けるだけなら最後に指数を取る必要もありません。

今回の密度は実数全体で正規化しており、箱の端で切り詰めた密度ではありません。有界探索空間へ移すときは、端の扱いや事前分布まで同じと見なさないでください。

### Optunaを使うときの違い

[OptunaのTPESampler公式文書](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html)には、初期のランダム試行数、候補サンプル数、多変量モデル、条件付き探索空間、並列試行に関わる設定があります。固定帯域の5点教材とは、群分け、帯域、事前成分、候補生成などが異なります。

同じ目的関数をOptunaで試す最小例は次です。**今回の環境にはOptunaがないため、このブロックは未実行です。結果値や提案列は記載しません。**

```python
import optuna


def objective(trial):
    x = trial.suggest_float("x", -2.0, 4.0)
    return (x - 1.0)**2


sampler = optuna.samplers.TPESampler(seed=7, n_startup_trials=10)
study = optuna.create_study(direction="minimize", sampler=sampler)
study.optimize(objective, n_trials=40)
print(study.best_value, study.best_params)
```

この新しい40試行が、図の5観測から始まるわけではありません。既存履歴を使う実務では、設定の名前、対数尺度、範囲、カテゴリ、条件付きの有効範囲、試行状態を保存して、同じ意味の観測だけを比較します。

`Tree-structured`は、ある設定によって別のパラメータが有効になる条件付き空間に由来します。決定木を必ずモデルとして使うという意味ではありません。

## 診断値

### 向く条件と診断

- 良い群が少ない：初期試行と学習に使える予算を確認します。

### 向く条件と診断

比較は同じ試行予算と停止条件で、無作為探索も基準にします。この5点の成功例から一般性能や大域最適性は主張できません。

## 失敗・切替の兆候

### 向く条件と診断

- 同じ領域へ偏り続ける：空間設計、帯域や事前成分、独立・多変量の設定を見ます。
- 多数並列で似た提案が増える：未完了試行を扱う設定と並列数を確認します。
- 低次元連続空間で予測の不確実性を読みたい：GPを用いるベイズ最適化とも比較します。
- 中間の学習成績が得られる：途中打切りの方法と提案器の役割を分けて検討します。
