複数目的のトレードオフを単一目的への変換または集団で探索し、単一の最適解ではなくパレート解集合の近似を得るための多目的最適化手法を条件に応じて選び分ける入口です。

## 30秒でつかむ

この手法群の気持ちは、**「1つの最適解」を求めるのではなく、目的間のトレードオフを表すパレートフロントを近似すること、またはその代表点を得ること**です。ある解が他のどの解にも支配されないとき、その解はパレート最適候補として扱われます。

- 見ているもの: 複数目的の値、解同士の支配関係
- 動かすもの: 単一ソルバーへの重みや単一目的への変換、または集団全体の分布
- 前進の判断: パレートフロントの近似がどれだけ広く、均等に覆われているか
- 主な弱点: 目的の尺度や評価指標への依存、目的数が増えると探索・可視化が難しくなること

「多目的手法が単一目的への変換より常に優れている」という順位ではありません。事前の選好情報の有無と、目的数、フロント全体の品質評価の手間を交換しています。

## まず確認すること

| 確認項目 | 選択への影響 |
|---|---|
| 意思決定者の選好が事前にあるか | あるなら重みや制約閾値を決めて単一目的への変換で単目的ソルバーを使える |
| 目的数が2〜3か、それ以上（多数目的）か | 目的数が増えるほど集団系の設計とフロント品質評価が難しくなる |
| 各目的の尺度や単位 | 尺度が揃っていないと重み付き和の重みが意味を持ちにくい |
| 単目的ソルバーの評価コスト | 高価なら単一目的への変換の反復回数を抑える設計が必要 |
| フロント全体を評価する指標 | ハイパーボリュームなどで探索範囲の広がりを測る前提を作れるか |

複数目的を根拠なく1つの評価値へ潰すと、トレードオフの構造そのものが見えなくなります。まず「単一の効用が実は明確にある」のか「トレードオフ自体が成果物」なのかを確認します。

## 条件付きの選び分け

| 役割 | 手法 | 優先しやすい条件 | 切り替えを考える条件 |
|---|---|---|---|
| 選好を重みとして固定 | [重み付き和単一目的への変換](#/learn/weighted-sum) | 目的間の相対重要度が決まっており、単目的ソルバーを繰り返し使いたい | パレートフロントが非凸な部分を持ち、重み変化で捉えられない解がある |
| 1目的を制約へ移す | [ε制約法](#/learn/epsilon-constraint) | 主目的が明確で、他の目的を許容上限・下限として扱いたい | 閾値の候補が多く、反復ごとの単目的求解コストが大きい |
| 2〜3目的でフロントを近似 | [NSGA-II（multi-objective）](#/learn/multi-objective) | 事前の選好がなく、2〜3目的のフロントを集団で近似したい | 目的数が増えて混雑度距離による多様性維持が弱くなる |
| 多数目的でフロントを近似 | [NSGA-III](#/learn/nsga-iii) | 目的数が多く、参照方向でフロントの広がりを維持したい | 参照方向の設計が問題の形状に合わない |
| 分解によるフロント近似 | [MOEA/D](#/learn/moead) | 多数の重みや参照方向で部分問題に分解して近い候補同士を共有したい | 部分問題間の近傍構造が問題に合わず収束が偏る |

これは一般性能順位付けではありません。同じ問題例、目的数、評価予算、乱数シードで比較します。

## うまくいったサインと切替サイン

うまく進んでいるときは、次の観測が揃います。

- ハイパーボリュームが評価回数とともに改善し、停滞しない
- 解間の間隔やε指標が極端な偏りを示さない
- 実行可能な候補の割合が十分に保たれる（制約がある場合）
- 得られた解集合が意思決定に使える程度に多様である

切替サイン:

- パレート探索範囲の広がりが不足し、フロントの一部しか得られない → 集団の大きさや単一目的への変換の重み・閾値の刻みを見直す
- 解が両極端に偏り、トレードオフ候補として使えない → 重み付き和の非凸フロント限界を疑い、集団系へ切り替える
- 目的数が増えて混雑度距離ベースの多様性維持が効かない → NSGA-IIIやMOEA/Dへ切り替える
- 実は単一効用が明確だと分かった → 多目的として扱う必要がなくなり、単目的ソルバーに戻す

## 小さな比較の型

実装比較では目的数、評価予算、フロント品質の指標を揃えて記録します。

```python
experiment = {
    "problem_instance": "same-biobjective-problem",
    "num_objectives": 2,
    "evaluation_budget": 10000,
    "seeds": [0, 1, 2],
    "quality_metric": "hypervolume",
    "methods": ["weighted-sum", "nsga2", "moead"],
}

assert experiment["num_objectives"] >= 2
```

## コラム: ハイパーボリュームは何を測っているのか

ハイパーボリュームは、得られた解集合と基準点との間に囲まれる領域の体積として計算される指標で、フロント全体の「広さ」と「良さ」を同時に反映します。単一の解の目的値だけを見ても、フロント全体がどれだけ多様な選択肢を提供しているかは分かりません。ハイパーボリュームや解間の間隔、ε指標のような指標は、1つの解ではなく解集合全体の品質を評価するために使います。

ただし、これらの指標は基準点の取り方や尺度の正規化に依存します。目的間で尺度が大きく異なる場合、正規化を誤ると指標が実際のトレードオフ構造を正しく反映しません。
