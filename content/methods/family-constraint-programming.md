変数の候補範囲の伝播、学習、探索を用いて論理・組合せ制約の可行性と最適化を扱う手法群の入口です。

## 30秒でつかむ

この手法群の気持ちは、**変数が取り得る値の範囲（候補範囲）を制約から論理的に削り、削り切れなかった部分だけ分岐して探すこと**です。

- 見ているもの: 各変数の候補範囲、制約の伝播結果、衝突（矛盾）
- 動かすもの: 候補範囲の縮小と、分岐による探索木の分割
- 前進の判断: 候補範囲が縮む、矛盾の原因が学習節として再利用できる、実行可能解が見つかる
- 主な弱点: 伝播が弱い制約表現では爆発しやすい、連続・滑らかな構造の利用は弱い

「CP-SATが常に最良」という順位ではありません。可否・組合せ構造・論理制約が主役の問題で、伝播の強さと探索・学習の仕組みが噛み合うかを条件で判断します。

## まず確認すること

| 確認項目 | 選択への影響 |
|---|---|
| 変数の候補範囲 | 有限候補範囲か、Boolean/整数へ意味のある符号化ができるか |
| 制約の種類 | 論理・大域制約が中心か、線形整数構造が強いか |
| 最適化か充足か | 目的関数の有無、界反復で十分な規模か |
| 証明の必要性 | 実行可能性・実行不能性の証明そのものが成果物か |
| 整数化の妥当性 | 実数精度を整数・真偽値の尺度へ落として意味が保たれるか |

論理・スケジューリング・資源制約が中心ならこの手法群を第一候補にしますが、整数線形構造（線形目的関数と線形不等式）が強い問題は、MILP系のBranch-and-Cutのような手法とも比較する価値があります。

## 条件付きの選び分け

| 役割 | 手法 | 優先しやすい条件 | 切り替えを考える条件 |
|---|---|---|---|
| 伝播・学習・探索を統合した既定候補 | [CP-SAT](#/learn/cp-sat) | 論理・スケジューリング・割当制約が中心で、最適化と証明の両方が欲しい | 整数線形構造が強く、専用MILP ソルバーの方が緩和が強い |
| 候補範囲縮小の仕組みを学ぶ入口 | [制約プログラミング探索](#/learn/cp-search) | 大域制約で問題を書きたい、伝播と分岐の関係を理解したい | 大規模化して自作の伝播では収束しない |
| 真偽値充足可能性そのものが焦点 | [CDCL SAT](#/learn/cdcl-sat) | 論理制約中心で、可否そのものやUNSAT証明が目的 | 最適化そのものが目的で、目的関数を直接扱いたい |
| 整数線形構造が強い場合の代替 | Branch and Cut | 線形目的関数と線形不等式が中心で、強い連続緩和が使える | 論理・スケジューリング制約が支配的でLP緩和が弱い |

これは一般性能順位付けではありません。同じモデル、時間上限、計算機環境、乱数シード、並列ワーカー数で比較します。

## うまくいったサインと切替サイン

うまく進んでいるときは、探索が進むほど手がかりが増えます。

- 候補範囲が分岐のたびに目に見えて縮む
- 衝突・分岐あたりの伝播が多く、探索木が浅い
- 学習節（CDCL/CP-SATの内部）が同種の衝突を再発させない
- 最良界と暫定解のギャップが縮む

切替サイン:

- 衝突・節点数が増え続けて収束しない → 伝播・分岐戦略・モデル表現を見直す
- 候補範囲が縮まらない → 大域制約の選び方や符号化を見直す
- 整数尺度が過大 → 単位・離散化を見直す、またはMILP系へ切り替える
- 本質的に連続・滑らかな構造が支配的 → NLP/QP系の手法群へ

## 小さな比較の型

比較では解の品質だけでなく、時間上限・乱数シード・並列ワーカー数を揃えます。

```python
experiment = {
    "problem_instance": "same-finite-domain-model",
    "domain_representation": "boolean-or-integer",
    "time_limit_seconds": 60,
    "random_seed": 7,
    "worker_count": 1,
    "methods": ["cp-sat", "cp-search", "cdcl-sat"],
}

assert experiment["time_limit_seconds"] > 0
```

## コラム: 可否判定と最適化はどう繋がるか

SATやCPの探索は、もともと「制約をすべて満たせるか」という可否判定として発展しました。最適化は、見つけた解より良い値を要求する界制約を追加してSAT/CPを繰り返し呼ぶことで扱えます。CP-SATのような実装は、この反復と線形緩和やカットを内部で統合しており、単純な繰り返し呼び出しより効率的です。MaxSATのように、制約の一部を重み付きで緩めて最適化そのものを目的関数化する拡張もあります。
