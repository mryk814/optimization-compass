MILPを分枝限定法で探索しながら、カットで連続緩和を締め、暫定解と界のギャップを詰めて最適性を証明する厳密な探索法です。

## 30秒でつかむ

この手法の気持ちは、整数解を残したまま不要な枝を切り、見るべき探索だけに集中することです。

整数解をすべて残すカットで連続緩和を締めると、改善できない枝を早く除けます。
それでも残る枝だけを探索し、暫定解と最良の界のギャップを詰めます。

- **見るもの**: LP緩和の解・分数になっている変数・暫定解・最良の界・ギャップ
- **動かすもの**: 探索木、各節点の緩和、追加するカット
- **前進の判断**: 暫定解と最良の界のギャップが、設定した許容値へ近づくこと

## 一手の意味

一手は、節点の緩和を解いて、分数の解を切り落とす不等式（カット）を足す操作です。解き直しても分数の解が残れば、分枝します。

整数条件を外したLP緩和は、整数の実行可能解より良すぎる分数の解を返すことがあります。
カットは、次の二つを満たす不等式です。

- すべての整数実行可能解を残す
- いまの分数の解を除外する

カットを足すとLP緩和が締まり、界が下がります（最大化なら上界が下がります）。切り落とされた分数の解に代わって、次のLP解が返ります。
カットを足したあとのLPは、直前の最適な基底が実行不能になる形です。そのため、[双対単体法](#/learn/dual-simplex)で解き直すのが自然です。

Branch-and-Cutは、次の六つを統合した、現代的なMILPソルバーの中心的な枠組みです。

1. 前処理
2. LP緩和
3. カットの生成（分離）
4. 実行可能解を探すヒューリスティクス（主問題のヒューリスティクス）
5. 分枝
6. 節点の枝刈り

### 界とギャップをどう読むか

- **暫定解**: いま見つかっている最良の整数実行可能解
- **最良の界（最良界 / 双対の界）**: 未探索の領域から得られる可能性の限界
- **ギャップ**: 暫定解と界の差

最小化では、最良の界が暫定解を下から追います。ギャップが許容値以下になれば、設定した許容値のもとでの最適性を主張できます。

::: warning
ソルバーが`optimal`と返す場合でも、整数の許容誤差と実行可能性の許容誤差を確認します。
相対ギャップと絶対ギャップも含め、数学的な完全一致ではなく、数値の許容値付きの判定です。
:::

## 小さな例

[混合整数線形計画](#/learn/concept.mixed-integer-linear-program)の小さな例を使います。[分枝限定法](#/learn/branch-and-bound)では、この問題に五つの緩和を解きました。

$$
\max\; 5x_1+4x_2 \quad \text{s.t.}\quad 6x_1+4x_2\le 24,\;\; x_1+2x_2\le 6,\;\; x_1,x_2\in\mathbb{Z}_{\ge 0}
$$

根のLP緩和の解は $(3,\,1.5)$ で、上界は $21$ です。$x_2$ が分数です。ここで分枝する代わりに、カットを探します。

二本の制約を、$1/4$ 倍と $1/2$ 倍して足します。

$$
\tfrac14(6x_1+4x_2)+\tfrac12(x_1+2x_2)\le \tfrac14\cdot24+\tfrac12\cdot6
\;\Longrightarrow\; 2x_1+2x_2\le 9
$$

$x_1+x_2\le 4.5$ です。$x_1$ と $x_2$ は整数なので、和 $x_1+x_2$ も整数です。整数が $4.5$ 以下なら $4$ 以下です。したがって、次のカットが得られます。

$$
x_1+x_2\le 4
$$

整数の実行可能点は全部で13個あり、どれもこのカットを満たします（下のPythonで確かめます）。一方、根の解 $(3,\,1.5)$ は $3+1.5=4.5>4$ なので、除外されます。

| 段階 | LP緩和の解 | 上界 | 状態 |
|---|---|---:|---|
| カットなし（根） | $(3,\;1.5)$ | $21$ | $x_2$ が分数 |
| カット $x_1+x_2\le4$ を足した後 | $(4,\;0)$ | $20$ | 整数解。暫定解 $20$ と上界 $20$ が一致し、ギャップは0 |

一つのカットで、根のLP緩和の解が整数になり、最適性の証明まで終わりました。分枝は一回も必要ありません。
この例では、分枝限定法が五つの緩和を解いたのに対し、カットは一つ足すだけで済みました。カットが緩和を締める効果が分かります。

この例は小さいから一つのカットで終わります。実際のソルバーは、カットの生成と再最適化を何回か繰り返し（カット生成の繰り返し）、それでも分数の解が残れば分枝します。
どのカットをどれだけ足すかは、ソルバーとバージョンに依存します。

## 向く条件・避ける条件

Branch-and-Cutの性能は、アルゴリズムの設定値だけでなく、定式化に強く依存します。まず次を確認します。

- Big-Mが必要以上に大きくないか
- 対称性がないか
- 変数の上下限（界）が十分に締まっているか
- 強い定式化や有効不等式があるか
- 前処理で固定できる変数があるか
- 初期の暫定解をウォームスタートとして与えられるか
- 係数の桁が極端でないか

向いているのは、線形緩和が強いMILPです。
避ける、または切り替える場面は次のとおりです。

- 論理関係・真偽値との対応付け・スケジューリングの大域制約が中心。[CP-SAT](#/learn/cp-sat)が自然に表現できる場合があります。
- 専用のフロー・マッチング・DP・CPの構造がある。専用法へ戻ります。

CP-SATとMILPのどちらが良いかは、同じ現実問題でも、定式化によって変わります。

## Python

小さな例のカットを、LPで確かめます。カットを足す前後で、LP緩和の解と上界がどう変わるかを見ます。

```python
from scipy.optimize import linprog

c = [-5, -4]  # 最大化 5 x1 + 4 x2 を最小化に直す
a_ub, b_ub = [[6, 4], [1, 2]], [24, 6]


def solve(a, b):
    result = linprog(c, A_ub=a, b_ub=b, bounds=[(0, None)] * 2, method="highs")
    return (result.x.round(3) + 0.0).tolist(), round(-result.fun, 3)


print("緩和", solve(a_ub, b_ub))

# cut  x1 + x2 <= 4  は、次の丸めで作れる:
# (1/4) * (6 x1 + 4 x2 <= 24) + (1/2) * (x1 + 2 x2 <= 6)  ->  2 x1 + 2 x2 <= 9
# x1 + x2 は整数なので、右辺 4.5 を切り下げて  x1 + x2 <= 4
points = [(i, j) for i in range(5) for j in range(4) if 6 * i + 4 * j <= 24 and i + 2 * j <= 6]
print("整数実行可能点の数", len(points), " すべて cut を満たす", all(i + j <= 4 for i, j in points))
print("cut 後", solve(a_ub + [[1, 1]], b_ub + [4]))
```

```text
緩和 ([3.0, 1.5], 21.0)
整数実行可能点の数 13  すべて cut を満たす True
cut 後 ([4.0, 0.0], 20.0)
```

### MILPをソルバーへ渡す

次の例では、カットや分枝を手で実装せず、HiGHSにモデルを渡します。

```python
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

values = np.array([8.0, 5.0, 6.0, 4.0])
weights = np.array([4.0, 3.0, 5.0, 2.0])

result = milp(
    c=-values,
    integrality=np.ones(len(values)),
    bounds=Bounds(np.zeros(len(values)), np.ones(len(values))),
    constraints=LinearConstraint(weights, -np.inf, 8.0),
    options={"time_limit": 30.0, "mip_rel_gap": 1e-6},
)

print(result.success, result.x, -result.fun, result.message)
```

```text
True [1. 1. 0. 0.] 13.0 Optimization terminated successfully. (HiGHS Status 7: Optimal)
```

実装がどのカットの種類を有効にするか、どのヒューリスティクスを使うかは、ソルバーとバージョンに依存します。

## 診断値

- 根の緩和のギャップ
- 暫定解・最良の界・相対ギャップ
- 探索した節点数
- LPの反復数
- カットの数と、カットの効き目
- 最初の実行可能解が見つかるまでの時間
- メモリ
- 前処理で減った変数・制約の数
- 停止した理由（termination reason）

判断の目安は次のとおりです。
根の緩和のギャップが大きいまま残るなら、カットが効いていないか、定式化が弱いと疑います。
カットを足して根の界がどこまで下がったかを、探索の前後で比べます。

## 失敗・切替の兆候

| 症状 | 考えられる原因 | 対処 |
|---|---|---|
| 根のギャップが大きいまま | 定式化が弱い。カットが効かない | Big-Mや上下限を見直す。有効不等式を足す |
| 節点の数が指数的に増える | 界が弱い。対称性が大きい | 定式化を締める。対称性を崩す制約を足す |
| 暫定解が長時間見つからない | 実行可能解を作る手がかりが弱い | 初期の暫定解を与える。ヒューリスティクスを使う |
| メモリが探索木で増大する | 節点の増えすぎ | 探索の順序を見直す。定式化を見直す |
| Big-Mによる数値警告が出る | Big-Mが大きすぎる | 根拠のある最小の値に取り直す |
| 同等の解を繰り返し探索している | 対称性 | 順序を付ける制約で崩す |
| 専用のフロー・マッチング・DP・CPの構造を無視している | 構造の見落とし | 専用法や[CP-SAT](#/learn/cp-sat)へ切り替える |
