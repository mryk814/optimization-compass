Multi-startは、出発点を変えて局所最適化を繰り返し、得られた候補の中から良いものを選ぶ戦略です。実装は単純ですが、結果の読み方には注意が必要です。**局所求解が25本とも成功しても、大域最適解に届かない**例を追います。

## 30秒でつかむ

地形の違う場所から下り始め、到着した谷底を比較します。一つの初期点からの探索に偏らないための外側の仕組みで、内側にはBFGSや微分不要法などを使えます。

- 見るもの：初期点、局所求解の終了点、目的値、停止理由
- 増やすもの：独立の初期点と局所求解の本数
- 判断するもの：最良値だけでなく、異なる谷へ到達したか、評価予算をいくら使ったか

内側の局所法が持つ仮定や限界は残ります。Multi-startを付けただけで、局所法の失敗や大域最適性の証明が解決するわけではありません。

## 一手は局所求解を一本追加すること

初期点 $x_0^{(j)}$ に局所求解 $L$ を適用して

$$
x^{(j)}=L(x_0^{(j)}),\qquad
b_j=\min\{b_{j-1},f(x^{(j)})\}
$$

と最良値を更新します。制約があるなら、まず可行性を確認してから比較します。局所求解が失敗した点を参考候補として保存する場合も、正常終了した点と分けて記録します。

各求解は独立に実行できるので並列化できます。ただし、壁時計時間が短くなっても目的関数の総評価数が減ったことにはなりません。同じ谷へ着いた実行も費用に含めます。

## Rastrigin関数で25本を走らせる

2変数Rastrigin関数を使います。

$$
f(x_1,x_2)=20+\sum_{i=1}^2\left(x_i^2-10\cos(2\pi x_i)\right).
$$

各項を $x_i^2+10(1-\cos(2\pi x_i))$ と書けば非負なので、原点の値0が大域最小です。波状に並ぶ他の谷へ下りてしまうかを確認できます。

初期点は `np.random.default_rng(7)` で $[-5.12,5.12]^2$ から一様に25点生成します。各点から同じBFGSを実行し、到達点間のユークリッド距離が $10^{-3}$ 未満なら同じ到達点と数えます。

ここで箱は**初期点を抽出する範囲**です。今回のBFGSには上下限を渡しておらず、局所探索の移動を箱に制限していません。箱内に必ず留まる問題なら、たとえばL-BFGS-Bへ上下限を渡すなど、内側の求解も変更します。

| 求解 | 初期点 | 到達点 | 目的値 | 目的評価数 |
|---|---|---|---:|---:|
| 1 | $(1.2810,4.0675)$ | $(0.9950,3.9798)$ | 16.9142 | 30 |
| 2 | $(2.8230,-2.8139)$ | $(2.9849,-2.9849)$ | 17.9092 | 42 |
| 3 | $(-2.0463,3.8252)$ | $(-1.9899,3.9798)$ | 19.8991 | 30 |

3本目までの最良値は1本目の16.9142のままです。「別の谷を見つけた」と「最良値を更新した」は違います。

![25個の初期点とBFGSによる到達点、累積目的評価数に対する最良値、到達点ごとの重複本数。原点は未到達。](./media/multi-start-basins.svg "矢印は初期点と終了点の対応で、BFGSの内部経路ではありません。25回の求解でも原点には到達していません。")

左の矢印は初期点と終了点の対応であり、BFGSの内部経路ではありません。中央の緑線は局所求解が終わるたびの最良値、灰色の点は各求解の終了値です。

SciPy 1.17.0、NumPy 2.3.5での結果は次の通りです。

- 局所求解25本すべてが`success=True`
- 23個の異なる到達点。うち21個は1本だけが到達し、2個には各2本が到達
- 目的関数の総評価数は882回
- 最良値は約0.994959。原点の値0には未到達

23という数は、この標本化と局所ソルバーと重複許容差で見つかった到達点の数です。関数にある谷の総数や、探索空間の網羅率を意味しません。

## Pythonで初期点と停止を記録する

```python
import numpy as np
from scipy.optimize import minimize


def rastrigin(x):
    return float(10 * len(x) + np.sum(x**2 - 10 * np.cos(2 * np.pi * x)))


rng = np.random.default_rng(7)
seen, records = [], []
best_f, best_x, total_nfev = np.inf, None, 0

for run in range(25):
    x0 = rng.uniform(-5.12, 5.12, size=2)
    result = minimize(rastrigin, x0, method="BFGS")
    total_nfev += result.nfev
    duplicate = any(np.linalg.norm(result.x - old) < 1e-3 for old in seen)
    if not duplicate:
        seen.append(result.x.copy())
    if result.success and result.fun < best_f:
        best_x, best_f = result.x.copy(), float(result.fun)
    records.append((x0, result.x.copy(), result.fun,
                    result.success, result.message, result.nfev))

print(best_x, best_f)
print(len(seen), 25 - len(seen), total_nfev)
# distinct=23, duplicates=2, total_nfev=882
```

このコードでは`jac`を指定していません。[SciPyのBFGS文書](https://docs.scipy.org/doc/scipy-1.17.0/reference/optimize.minimize-bfgs.html)にあるように、勾配は関数の有限差分で近似されます。その追加呼び出しも`nfev`へ含まれます。「ユーザーが勾配を渡していない」と「勾配モデルを使わない手法」は同じ意味ではありません。

再現には乱数種だけでなく、初期点配列、目的関数の実装、NumPyとSciPyの版、局所停止条件を残します。浮動小数点計算の違いで、非凸関数では到達先が変わることもあります。

## 何本増やせば十分なのか

仮に、固定した初期点分布と局所法で「欲しい谷へ着く確率」が $p$ と分かり、各実行が独立なら、$k$ 本で一度も着かない確率は $(1-p)^k$ です。しかし未知の関数では通常 $p$ が分かりません。今回の25本未到達から、次の25本で必ず届くとも、決して届かないともいえません。

初期点を増やす以外に、ラテン超方格などの空間充填的な配置、既知の良い候補の追加、局所ソルバーの尺度調整を検討できます。配置を変えると到達確率も変わるため、単に本数だけを比較しないようにします。

同じ到達点への再訪は完全に無意味ではありません。再現性や吸引域の広さについて手掛かりになります。ただし、それだけで未発見の谷がない証拠にはならず、新しい候補を増やす目的では費用に見合わない場合もあります。

## 向く条件と切替の目安

一回の局所求解が比較的安く、初期点依存が強い問題や、独立実行を並列化できる場合に扱いやすい戦略です。一評価が高価なら「25本」という設定だけでなく、局所求解が使う総評価予算を先に決めます。

- 重複ばかり増える：初期点の配置や探索範囲を見直します。
- 局所求解が失敗する：内側の停止理由、尺度、勾配近似を調べます。
- 多くの谷は見つかるが改善しない：予算の打切り基準と、別の探索方法を比較します。
- 高次元で少数初期点しか置けない：低次元の図と同じ網羅感を期待しません。
- 有界低次元で別の探索構造が欲しい：[SHGO](#/learn/shgo)や[DIRECT](#/learn/direct-global)も、その仮定と保証範囲を確認して比較します。
