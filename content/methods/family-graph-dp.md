問題が既知のグラフ・DP構造に一致するかを確認し、一致するなら汎用最適化より先に専用法を検討するための入口です。

## 30秒でつかむ

この手法群の気持ちは、**問題が最短路、フロー、マッチング、段階的なDP構造のいずれかに一致するなら、汎用の最適化ソルバーへ持ち込む前に、その構造を直接利用する専用法をまず確認すること**です。

- 見ているもの: 節点、辺、状態、段階、最適部分構造の有無
- 動かすもの: 経路、フロー、マッチング、DPの状態遷移
- 前進の判断: 距離や費用の確定、フローの改善、状態の縮約、部分問題の再利用
- 主な弱点: 構造が崩れると適用不能、状態空間の爆発

これは一般性能順位付けではありません。専用法が使える構造を持つ問題では、汎用最適化より高速かつ強い保証が得られる場合が多いという役割の違いを示します。

## まず確認すること

| 確認項目 | 選択への影響 |
|---|---|
| 最適部分構造の有無 | 部分問題の最適解を組み合わせて全体の最適解が作れるか |
| 状態空間の大きさ | DPの状態が現実的なメモリに収まるか |
| 追加の制約の有無 | 構造を壊す追加制約（複数の資源、時間窓、論理条件など）がないか |
| グラフ表現への対応 | 問題を節点・辺やフローネットワークとして素直に表現できるか |
| 必要な保証 | 厳密解・多項式時間の保証が必要か、早い可行解でよいか |

これらを確認した結果、構造が崩れている、または状態空間が巨大すぎると分かった場合は、MILP・CP-SATなど汎用の離散最適化へ進みます。判断の入口は[離散・組合せ最適化の選び分け](#/learn/family.discrete-structure)にまとめています。

## 条件付きの選び分け

| 役割 | 手法 | 優先しやすい条件 | 切り替えを考える条件 |
|---|---|---|---|
| 段階的な部分問題の再利用 | [動的計画法](#/learn/dynamic-programming) | 最適部分構造があり、状態を小さく定義できる | 状態数・メモリが爆発する |
| 最短路の専用探索 | [Dijkstra / A*](#/learn/dijkstra-astar) | 最短路、非負辺、過大評価しないヒューリスティクスが使える | 追加の制約が増え専用構造が崩れる |
| 二部マッチングの専用解法 | [Hungarian Algorithm](#/learn/hungarian-algorithm) | 割当問題が二部完全マッチングとして表現できる | 追加の制約で完全マッチングの前提が崩れる |
| フローネットワークの専用単体法 | [Network Simplex法](#/learn/network-simplex) | 最小費用流のネットワーク構造（節点・枝接続行列）を保っている | 追加の制約で専用構造が崩れる |
| 早い良質可行解が必要な大規模問題 | [組合せ局所探索](#/learn/local-search-combinatorial) | 大規模な経路選択・スケジューリング、証明より運用解を優先 | 大域最適性の証明やギャップの保証が必須になる |

同じ問題規模でも、構造を保ったまま解けるか、追加の制約で崩れているかによって適した手法は変わります。

## うまくいったサインと切替サイン

うまく専用構造を利用できているときは、次のような値が安定して観測できます。

- 状態・辺・ラベルの数が問題規模に対して現実的な範囲に収まっている
- メモリ使用量が想定内で推移している
- 最適性条件（最短路の確定、フローの被約費用条件、マッチングの完全性など）が満たされている

切替サイン:

- 状態数や節点・辺数が指数的またはメモリ上限を超えて増大する
- 追加の制約が増え、専用構造（ネットワーク、二部マッチング、Bellman再帰）の前提が崩れる
- 厳密な保証よりも早い可行解が優先される状況に変わる、またはその逆
- 専用法の実装や近傍設計が問題の複雑さに対して過度に手間がかかる

## 小さな比較の型

専用法を選ぶ前に、問題の構造と必要な成果物を記録します。

```python
problem_brief = {
    "graph_structure": ["shortest_path", "min_cost_flow", "bipartite_matching"],
    "optimal_substructure": True,
    "state_dimension_estimate": "small",
    "side_constraints_present": False,
    "required_output": "exact-optimal-with-guarantee",
    "candidate_methods": [
        "dynamic-programming",
        "dijkstra-astar",
        "network-simplex",
    ],
}

assert problem_brief["state_dimension_estimate"] in {"small", "moderate", "large"}
```

## コラム: 専用法と汎用最適化は競合しない

グラフ専用法やDPは、問題が持つ構造をそのまま利用するため、同じ問題を汎用のLP/MILPへ変換して解くよりも高速で、保証も明確になりやすい手法です。しかし、これは専用法が汎用最適化より常に優れているという意味ではありません。専用法は、想定した構造（ネットワーク、二部マッチング、Bellman再帰など）から外れた瞬間に前提が崩れ、適用できなくなります。

実務では、まず問題の構造を確認し、専用法が使える範囲を見極めたうえで、追加の制約が加わった部分だけを汎用ソルバーで扱う、という組み合わせもよく使われます。構造を壊さない範囲で専用法を使い、壊れた部分だけ汎用化するという判断が、この手法群全体の軸になります。
