Adamの適応的な更新と重み減衰を分離する学習最適化器です。勾配による更新とパラメータを縮める正則化を、別の操作として扱います。

## 30秒でつかむ

Adamでは座標ごとに過去の勾配の大きさを見て、更新量を調整します。そこへ「大きな重みを小さくしたい」という目的を加えるとき、二つの方法があります。損失にL2罰則を足してから勾配を適応化する方法と、データの勾配を適応化したあとで重みを直接縮める方法です。

AdamWは後者です。どこを通って縮小の力が伝わるかが変わるため、同じ係数でも更新は一致しません。

- 見るもの: 確率勾配、一次モーメントと二次モーメント、学習率
- 動かすもの: パラメータ、モーメントの状態、重み減衰
- 前進の判断: 学習だけでなく検証指標の改善

AdamWは「Adamより常に良い」という順位ではありません。学習の設定の中で正則化をどう定義するかを明確にする選択です。

## 一手の意味

一次・二次モーメントの偏りを補正した量を $\hat m_k,\hat v_k$ とすると、勾配に応じた更新と重み減衰を足して一歩を決めます。

$$
x_{k+1}=x_k-\eta_k\frac{\hat m_k}{\sqrt{\hat v_k}+\varepsilon}-\eta_k\lambda x_k
$$

### 仕組み

Adamのモーメント推定から適応的な勾配による更新を作り、その一歩とは別にパラメータを縮めます。概念的には次の二つを分けます。

1. 勾配情報による更新
2. 重み減衰によるパラメータ縮小

実際の式と偏り補正はフレームワーク実装で確認します。微小定数 $\varepsilon$ とパラメータ群の定義も確認します。特に「L2罰則を損失へ加える」ことと「分離した重み減衰」は同じ操作ではありません。


### 状態を更新する順序

$t=1$ から更新を数え、$m_0=v_0=0$ とします。減衰を含めないデータ損失の勾配 $g_t=\nabla f(x_{t-1})$ から

$$
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\qquad
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
$$

を作り、$\hat m_t=m_t/(1-\beta_1^t)$、$\hat v_t=v_t/(1-\beta_2^t)$ と補正します。二乗・平方根・割り算は成分ごとの演算です。最後に

$$
x_t=(1-\eta_t\lambda)x_{t-1}
-\eta_t\frac{\hat m_t}{\sqrt{\hat v_t}+\varepsilon}
$$

とします。減衰が参照するのは更新前の $x_{t-1}$ です。適応的な更新を済ませた値全体へあとから $(1-\eta_t\lambda)$ を掛けると、勾配ステップまで縮める別の式になります。ここではこの順序と、$\varepsilon$ を平方根の外へ足す定義に固定します。

## 小さな例

$f(x)=(x-1)^2$ を $x_0=2$ から解きます。
学習率は $0.1$、重み減衰は $0.1$、モーメント係数は $0.9,0.999$ です。
Python節の式を実行すると、次の値になります。

| 更新 | 勾配による移動量 | 重み減衰による縮小量 | 更新後の $x$ | $f(x)$ |
|---|---:|---:|---:|---:|
| 1 | 0.100000 | 0.020000 | 1.880000 | 0.774400 |
| 2 | 0.099465 | 0.018800 | 1.761735 | 0.580241 |
| 3 | 0.098462 | 0.017617 | 1.645656 | 0.416872 |

勾配による移動量と重み減衰量は、同じ更新の中でも異なる値です。
これは更新式の確認であり、検証データでの性能比較ではありません。


### L2罰則を混ぜたAdamと、最初の一手を比べる

L2側は損失を $f(x)+\tfrac{\lambda}{2}x^2$ と定義します。この $1/2$ を付ける約束なら、追加される勾配は $\lambda x$ です。初期点2、$\lambda=0.1$ では、データの勾配2へ0.2が加わります。両方式の初期状態は $m=v=0$、学習率0.1です。

| 初回の計算 | Adam + L2 | AdamW |
|---|---:|---:|
| モーメントへ入る勾配 | 2.2 | 2.0 |
| 補正後 $\hat m_1$ | 2.2 | 2.0 |
| 補正後 $\hat v_1$ | 4.84 | 4.0 |
| 適応的なステップ | 約0.1 | 約0.1 |
| 別経路の縮小 | なし | 0.02 |
| 更新後 | 約1.90 | 約1.88 |

初回は $\hat m_1=g$、$\hat v_1=g^2$ なので、$\varepsilon$ を無視できれば比は $g/|g|$ になります。L2で勾配を2から2.2へ増やしても、この正の初回では移動はほぼ0.1のままです。AdamWはそこに0.02の縮小を別に足します。2回目以降は履歴も違ってくるので、単に最後の式で係数を付け替えるだけでは同じ軌跡になりません。

![Adam+L2では罰則の勾配もモーメントへ入る。AdamWではデータ勾配だけをモーメントへ入れ、重み減衰を別経路で加える。右は本文の3更新の寄与。](./media/adamw-decoupled-step.svg)

この違いが、[Loshchilov・HutterのAdamW論文](https://arxiv.org/abs/1711.05101)の中心です。通常の、モーメンタムを使わないSGDならL2勾配を足す操作と重みを縮める操作は同じ式にできますが、Adamの適応的な尺度と履歴の中へ入れると一致しません。表は仕組みの比較で、どちらの検証損失が小さくなるかの実験ではありません。

### 「分離した」あとも学習率との積は効く

本稿の定義では一回の縮小率は $1-\eta_t\lambda$ です。もしデータ勾配由来の更新がずっと0なら、$T$ 回の倍率は $\prod_{t=1}^T(1-\eta_t\lambda)$。この例の0.99を100回掛けると約0.3660になります。同じ `weight_decay` でも、学習率の予定や総更新数を変えれば総縮小量も変わります。

「分離」は減衰がモーメントへ混ざらないという意味で、学習率と減衰を互いに無関係に設定できるという意味ではありません。また純粋な縮小になるのは $0\le\eta_t\lambda\le1$ の場合です。積が1を超えれば符号反転を含むため、単なる正則化の強化として読みません。

## 向く条件・避ける条件

### まず確認すること

| 項目 | 確認内容 |
|---|---|
| 目的 | ミニバッチ勾配を利用する学習問題か |
| 正則化 | 重み減衰をパラメータ縮小として扱いたいか |
| パラメータ群 | バイアスや正規化層のパラメータへ減衰を適用するか |
| 予定 | 学習率と重み減衰をどう時間変化させるか |
| メモリ | 一次・二次モーメントを保持できるか |
| 評価 | 検証指標と早期停止があるか |

小規模な決定的な凸問題や高精度解が必要な問題では、L-BFGSや専用ソルバーも比較します。

- **向く**: ニューラルネットワークなど高次元確率的な学習
- **向く**: 座標ごとに勾配の尺度が違う学習問題。ただし疎テンソルの直接サポートは実装ごとに確認する
- **向く**: Adam系を使いつつ重み減衰を明示したい
- **向く**: フレームワークのパラメータ群で適用範囲を管理できる
- **避ける**: 最適化器の状態を保存するメモリが厳しい
- **避ける**: 検証なしで学習損失だけを最小化する
- **避ける**: 減衰対象を理解せず全パラメータへ同じ設定を適用
- **切り替える**: 厳密な最適性ギャップや大域証明が必要

## Python

一次元の更新式を、標準ライブラリだけで実行します。
実モデルの学習では、フレームワークのモーメント定義とパラメータ群を確認します。

```python
import math

x, m, v = 2.0, 0.0, 0.0
for k in range(1, 4):
    g = 2.0 * (x - 1.0)
    m = 0.9 * m + 0.1 * g
    v = 0.999 * v + 0.001 * g * g
    gradient_step = 0.1 * (m / (1.0 - 0.9**k)) / (
        math.sqrt(v / (1.0 - 0.999**k)) + 1e-8
    )
    decay = 0.1 * 0.1 * x
    x -= gradient_step + decay
    print(k, round(gradient_step, 6), round(decay, 6),
          round(x, 6), round((x - 1.0)**2, 6))
```

```text
1 0.1 0.02 1.88 0.7744
2 0.099465 0.0188 1.761735 0.580241
3 0.098462 0.017617 1.645656 0.416872
```

実務では乱数種とデータ分割を記録します。学習率の予定・パラメータ群・フレームワークの版も残します。
`torch.optim.AdamW`を使う場合も、勾配を計算してから更新し、重み減衰の適用対象を決めます。


L2側の初回も同じ定義で確認できます。

```python
import math

x0, eta, lam, eps = 2.0, 0.1, 0.1, 1e-8
g_data = 2.0 * (x0 - 1.0)
g_l2 = g_data + lam * x0
# 初回の補正後モーメントは g と g^2
adam_l2 = x0 - eta * g_l2 / (math.sqrt(g_l2*g_l2) + eps)
adamw = (1.0 - eta * lam) * x0 - eta * g_data / (abs(g_data) + eps)
print(round(adam_l2, 6), round(adamw, 6))
# 1.9 1.88
```

### フレームワークへ移す前の確認

ここでは式の参照先を [PyTorch 2.8のAdamW公式文書](https://docs.pytorch.org/docs/2.8/generated/torch.optim.AdamW.html)に固定しています。掲載Pythonは標準ライブラリによる式の検算で、PyTorchの学習実験ではありません。実務では使用する版の式と次を確認します。

- `Adam` の `weight_decay` と `AdamW` の同名引数を、名前だけで同じ更新だと解釈しない
- 重み・バイアス・正規化層など、どのパラメータ群に何の係数を使うかを明示する
- 損失にL2罰則を既に足していないかを確認する。二重に入れれば別の正則化になる
- 中断再開ではモデルだけでなくモーメント、更新番号、学習率の予定も復元する

勾配評価は一反復1回で、状態はパラメータごとの一次・二次モーメント2本を持ちます。実装の一時領域や混合精度用の状態は別です。検証データで評価する処理は更新そのものには含まれません。固定乱数は再現性のためで、汎化性能の差を主張するときは同じデータ分割と評価予算で複数試行のばらつきも記録します。

## 診断値

- 学習 / 検証損失
- 主要な検証指標
- 学習率と重み減衰
- 更新量のノルムとパラメータのノルム
- 勾配のクリッピング率
- 乱数種間のばらつき
- 最大メモリと処理量

学習損失だけ下がり検証が悪化する場合、最適化器の停止条件とモデル汎化性能を分けて考えます。

- 恐れていること: 学習率と減衰の混同、過学習、最適化器の状態を保存するメモリ

## 失敗・切替の兆候

### うまくいったサインと切替サイン

- 学習は改善し検証が悪化 → 減衰、データ、早期停止を見直す
- パラメータのノルムが急減 → 減衰が強すぎる可能性
- 最適化器の状態がメモリを圧迫 → SGD系や状態の分割保存を検討
- 初期改善後に停滞 → 予定、SGD+モーメンタム、L-BFGSを比較
- NaNや発散 → 学習率、混合精度、勾配の尺度調整を確認

### コラム: 最適化器だけを比較しない

AdamWの結果は、学習率の予定や準備期間と組み合わさって決まります。バッチサイズ・正規化・データ拡張・勾配のクリッピングも影響します。最適化器名だけを変えた比較と、各最適化器向けに学習の設定を調整した比較を区別します。
