二部グラフの完全マッチングとして表せる割当問題を、専用構造を使って多項式時間で厳密に解くアルゴリズムです。

## 30秒でつかむ

座席表の各行と各列から一つずつ選び、全員の組合せを最小費用に整えます。

- 見るもの: 費用行列のゼロと部分割当
- 動かすもの: 行と列の値、割当
- 前進の判断: ゼロの位置で一対一の完全割当ができること

## 一手の意味

行と列から定数を引いても、完全割当の費用差は変わりません。

$$
\tilde c_{ij}=c_{ij}-u_i-v_j,\qquad
\sum_i c_{i,\pi(i)}=\sum_i\tilde c_{i,\pi(i)}+\sum_i u_i+\sum_j v_j
$$

どの完全割当でも各行と各列を一度ずつ使うからです。

### 割当問題をどう表すか

$n$人の作業者と$n$個の仕事があり、作業者$i$を仕事$j$に割り当てる費用が$c_{ij}$で与えられているとします。
Hungarian アルゴリズムでは、各作業者にちょうど1つの仕事を割り当てます。
各仕事にも、ちょうど1人だけを割り当てます。
この完全マッチングの中から、費用の合計が最小のものを求めます。
汎用のMILPやLPにこの問題を投げても解けます。
割当問題の構造（二部グラフの完全マッチング）だけを使う専用アルゴリズムは、同じ最適解を汎用ソルバーより高速に、かつ組合せ的な保証つきで返します。
「問題の構造を知っていれば専用アルゴリズムを選ぶ」という判断の代表例です。

青緑の3セルが、作業者と仕事を一対一に結ぶ費用5のマッチングです。

### 費用行列をどう簡約するか

簡約では、費用の相対関係を保ちながら0の候補を増やします。

1. 各行から、その行の最小値を引きます。
2. 続けて各列から、その列の最小値を引きます。
3. 0の位置だけで完全マッチングを作れるか確認します。

完全マッチングを作れない場合は、0を覆う最小本数の直線を引きます。
覆われていない部分を調整し、新しい0を増やしてから再判定します。

行・列簡約は、LPの双対変数（ポテンシャルまたはラベル）を更新する操作に対応します。
ここでは「簡約のたびに実行可能な双対解が改善される」という関係を押さえます。
双対理論の詳細を追わなくても、0だけで完全マッチングを作れるかを停止判断に使えます。

## 小さな例

Python節の費用行列を簡約します。
各行の最小値 $(1,0,2)$ を引きます。
行は順に $(3,0,2)$／$(2,0,5)$／$(1,0,0)$ となります。
さらに各列の最小値 $(1,0,0)$ を引きます。
各行は $(2,0,2)$／$(1,0,5)$／$(0,0,0)$ です。

まだゼロだけでは完全割当を作れません。
第3行と第2列でゼロを覆い、未被覆の最小値1を調整します。
行列は $(1,0,1)$、$(0,0,4)$、$(0,1,0)$ となります。
ここで仕事を $(1,0,2)$ と割り当てると、各行と各列を一度ずつ使えます。

元の行列での合計は $1+2+2=5$ です。
全6通りの割当費用も実行で検査し、最小が5であることを確認します。

## 向く条件・避ける条件

### 向いている条件

- 割当が二部グラフの完全マッチングとして表現できる
- 費用行列が事前に確定している、または容易に構築できる
- 追加制約（作業者ごとの人数上限など）がない、または後で緩和・分割できる
- 厳密な最適解と多項式時間の保証が必要

### 避ける／切り替える条件

複数の仕事をまとめて1人が担当する場合や、特定の組み合わせを禁止する場合は、追加の追加制約が必要です。
このとき二部完全マッチングという構造が崩れ、Hungarian アルゴリズムの前提が成り立たなくなります。
一部の作業者や仕事を未割当のまま許す場合も、素朴には適用できません。
こうした場合はMILPやCP-SATへ戻り、追加制約を明示的な制約式として表現します。

## Python

```python
import numpy as np
from scipy.optimize import linear_sum_assignment


def build_cost_matrix() -> np.ndarray:
    return np.array(
        [
            [4.0, 1.0, 3.0],
            [2.0, 0.0, 5.0],
            [3.0, 2.0, 2.0],
        ]
    )


cost = build_cost_matrix()
row_indices, col_indices = linear_sum_assignment(cost)
total_cost = float(cost[row_indices, col_indices].sum())

print(row_indices, col_indices, total_cost)
```

`row_indices`と`col_indices`は同じ長さの配列で、`row_indices[k]`が`col_indices[k]`へ割り当てられたことを表します。
最大化問題として使う場合や矩形行列を扱う場合の挙動は、利用バージョンの[公式リファレンス](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html)で確認します。

## 診断値

- 状態（探索中に扱う部分マッチング・ラベルの状態数）
- 辺（費用行列が表す二部グラフの辺数）
- ラベル（簡約中に維持するポテンシャル/ラベルの値）
- メモリ（費用行列と補助構造が使うメモリ量）
- 最適性条件（0だけで完全マッチングが作れているかどうか）

## 失敗・切替の兆候

- 追加の追加制約で二部完全マッチングという前提が崩れている
- 割当が完全マッチングでなく、一部が未割当のままでよい設定になっている
- 状態や作業者・仕事の数が非常に大きく、費用行列の構築自体が重い
- 費用が負の閉路や不正な前提（対称性の誤仮定など）を含んでいる

::: note
専用アルゴリズムは、対象の問題が想定した構造から外れた瞬間に保証を失います。
追加制約を足したくなったら、MILPなど汎用の定式化に戻ることを検討します。
:::
