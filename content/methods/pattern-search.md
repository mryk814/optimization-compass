現在点の周囲へ配置方向の近傍調査点を配置し、改善の有無に応じて一歩の大きさを拡大・縮小する微分不要局所探索法です。

## 30秒でつかむ

暗い部屋で、前後左右の足場を試しながら低い方へ進む感覚です。

- **見るもの**：現在点と近傍候補の目的値
- **動かすもの**：採用点と近傍を調べる間隔
- **前進の判断**：候補が改善するか、非改善時に間隔を縮められるか

## 一手の意味

### 近傍調査の考え方

現在点 $x_k$、一歩の大きさ $\Delta_k$、方向集合 $D_k$ に対し、

$$
x_k+\Delta_k d,\quad d\in D_k
$$

を評価します。改善点があれば現在の採用点を更新し、なければ$\Delta_k$を縮小します。

座標方向 $\{\pm e_i\}$ は単純な配置ですが、正に張る方向集合を使う理論的変種や、探索段階を加える実装もあります。

### 全候補を調べるか、最初の改善で打ち切るか

- 全候補の近傍調査: 全候補を評価して最良点を選ぶ
- 最初の改善で打ち切る: 最初の改善で残りを省略

最初の改善で打ち切れば評価数を減らせますが、方向順序に依存します。
並列評価では全候補を調べる方が自然な場合があります。

## 小さな例

1変数 $f(x)=(x-1)^2$ を初期点0から調べます。
左右の候補をすべて評価し、改善時に間隔を2倍、非改善時に半分へ変える骨格を実行しました。

| 調査 | 間隔 | 候補 | 採用点 | 目的値 |
|---|---:|---|---:|---:|
| 1回目 | 1.0 | $1,-1$ | 1 | 0 |
| 2回目 | 2.0 | $3,-1$ | 1 | 0 |
| 3回目 | 1.0 | $2,0$ | 1 | 0 |

1回目で目的値は1から0へ下がります。
その後は点を動かさず、間隔を縮めます。
間隔が小さくなることと、最良値が改善することは別です。
Python例の2変数問題では、改善時の倍率を1.2にしています。

## 向く条件・避ける条件

### 向いている条件

- 低〜中次元のブラックボックス
- 微分がない、信用できない
- 軽い非滑らかさ
- 近傍調査点を並列評価できる
- 局所停留性の目安が欲しい

### 避ける／切り替える条件

- 高次元で近傍調査点数が予算を圧迫
- 評価が極端に高価
- 雑音で改善判定が揺れる
- 変数尺度が悪い
- ブラックボックス制約を単純なペナルティだけで扱う
- 離散 / カテゴリ定義域を無理に連続方向へ埋め込む

[MADS](#/learn/mads)は近傍調査方向と格子をより一般化し、ブラックボックス制約を扱う実装もあります。

::: warning
同じ「配置探索」でも探索段階、近傍の方向集合、最初の改善で打ち切る規則、格子の更新、制約処理が異なります。実装と設定を明記します。
:::

## Python

```python
import numpy as np


def objective(x: np.ndarray) -> float:
    return float((1.0 - x[0]) ** 2 + 20.0 * (x[1] - x[0] ** 2) ** 2)


x = np.array([-1.2, 1.0])
step = 0.5
minimum_step = 1e-6
directions = np.vstack((np.eye(2), -np.eye(2)))

while step > minimum_step:
    candidates = [x + step * direction for direction in directions]
    values = [objective(candidate) for candidate in candidates]
    best_index = int(np.argmin(values))
    if values[best_index] < objective(x):
        x = candidates[best_index]
        step = min(step * 1.2, 1.0)
    else:
        step *= 0.5

print(x, objective(x), step)
```

これは全候補を評価する教育用の座標方向探索です。正式な配置-探索 / 一般化された配置-探索の方向条件や停止理論をすべて実装してはいません。

## 診断値

- 現在の採用点目的関数
- 一歩 / 格子の間隔
- 成功した / 改善しなかった近傍調査数
- 近傍を調べる方向別の成功率
- 評価回数
- 並列一括評価大きさ
- 上下限到達率
- 制約違反
- 停止理由

一歩が小さいだけで大域最適解は保証されません。雑音の大きさより小さな一歩を続けても改善判定が不安定になります。

## 失敗・切替の兆候

- 間隔だけが縮み、改善判定が揺れる → 評価の雑音と反復評価を確認します。
- 候補の評価数が大きい → 次元と方向数、並列評価の費用を確認します。
- 制約違反が減らない → [MADS](#/learn/mads)などの制約処理を検討します。
- 初期点によって別の谷へ止まる → [Multi-start](#/learn/multi-start)と比較します。
