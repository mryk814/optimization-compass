現在点の周囲を数方向に試し、良い点があれば移り、なければ探索幅を縮めます。Pattern Searchの一手を読むときは、**点が動いたか**と**次にどの幅で調べるか**を別々に見るのが出発点です。

## 30秒でつかむ

暗い部屋で前後左右の足場を試すように、関数値だけで近傍を調べます。この近傍調査をpollと呼びます。

- 見るもの：現在点と候補点の目的値
- 動かすもの：採用点と調査幅
- 一回の判断：改善点へ移るか、点を保って幅を縮めるか

このページは、2変数の同じ関数、同じ4方向、同じ幅更新を図・表・Pythonで追います。正式なGPSやMADSの全構成を実装するページではありません。

## 一手の意味

現在点を $x_k$、幅を $\Delta_k$、方向集合を $D$ とすると、候補は

$$
x_k+\Delta_k d,\qquad d\in D
$$

です。ここでは $D=\{e_1,e_2,-e_1,-e_2\}$ の順で4点すべてを評価し、最良候補が現在点より厳密に良ければ採用します。成功時は幅を1.2倍、上限1.0とし、非改善時は半分にします。現在点の目的値は保存するので、各調査に必要な追加評価は4回です。

「最初に見つかった改善点」で打ち切る方式なら、最初の調査で結果が変わります。本例の $+e_1$ は改善するものの、$+e_2$ はさらに良いからです。全候補方式は追加評価を使う代わりに、その調査内の最良点を選びます。並列に4点を評価できても、目的関数の評価費用が4回分であることは変わりません。

## 同じ点に留まる2回を読む

目的関数と初期状態を固定します。

$$
f(x_1,x_2)=(1-x_1)^2+20(x_2-x_1^2)^2,\qquad
x_0=(-1.2,1.0),\quad\Delta_0=0.5.
$$

初期値は8.712です。曲がった谷を持つため、座標方向だけの一歩が必ず谷に沿うとは限りません。

![同一の二変数関数で最初の3回のpollを比較。1回目は上方向を採用し、2回目と3回目は現在点を保って幅だけを縮める。](./media/pattern-search-poll.svg "同じ関数の最初の3回のpollです。緑は採用候補、茶色は不採用候補、濃い青は調査開始点です。")

図中の数字は候補の目的値です。緑は採用候補、茶色は不採用候補、濃い青は調査開始点です。薄い曲線は同じ目的関数の等高線で、ソルバーへ勾配を与えているわけではありません。

| 調査 | 調査開始点 | 幅 | $+e_1$ | $+e_2$ | $-e_1$ | $-e_2$ | 判断 |
|---|---|---:|---:|---:|---:|---:|---|
| 1 | $(-1.2,1.0)$ | 0.50 | 8.092 | 4.912 | 78.732 | 22.512 | $(-1.2,1.5)$を採用 |
| 2 | $(-1.2,1.5)$ | 0.60 | 28.552 | 13.552 | 68.392 | 10.672 | 全候補が4.912より悪い |
| 3 | $(-1.2,1.5)$ | 0.30 | 13.132 | 7.432 | 17.500 | 5.992 | 全候補が4.912より悪い |

1回目は $8.712\to4.912$ と改善し、次の幅を $0.5\times1.2=0.6$ にします。2回目では一番良い候補さえ10.672なので、現在点を変えず $0.6/2=0.3$ へ縮めます。3回目も同じ理由で幅は0.15になります。

3回後の採用点は $(-1.2,1.5)$、値は4.912のままです。しかし次の調査位置は変わりました。**不採用の評価は、その幅では改善しないことを調べるための費用**です。初期点1回と候補12回の合計13評価を使いました。

なお、この関数は二乗の和なので $f\ge0$ であり、$(1,1)$ で0になります。この既知の答えとの比較でも、3回の調査で最適解に到達したとはいえません。

## Pythonで同じ3回を再現する

NumPy 2.3.5で実行しました。図の元データもこの更新と同じです。

```python
import numpy as np


def objective(x):
    return float((1 - x[0])**2 + 20 * (x[1] - x[0]**2)**2)


x = np.array([-1.2, 1.0])
step = 0.5
fx = objective(x)
nfev = 1
directions = np.array([[1, 0], [0, 1], [-1, 0], [0, -1]])

for poll in range(1, 4):
    candidates = x + step * directions
    values = np.array([objective(point) for point in candidates])
    nfev += len(values)
    best = int(values.argmin())
    improved = values[best] < fx
    if improved:
        x, fx = candidates[best].copy(), float(values[best])
        step = min(1.2 * step, 1.0)
    else:
        step *= 0.5
    print(poll, x, round(fx, 3), round(step, 3), nfev)
# 1 [-1.2  1.5] 4.912 0.6 5
# 2 [-1.2  1.5] 4.912 0.3 9
# 3 [-1.2  1.5] 4.912 0.15 13
```

これは3回で止める教育用の座標方向探索です。実務の停止条件にするには、最小幅だけでなく評価上限、非有限値の処理、許す制約違反も定めます。雑音がある場合には、厳密な大小比較をそのまま使うと偶然の改善へ動いてしまいます。

## 小さな幅が保証してくれる範囲

方向集合 $\{\pm e_i\}$ は空間を正に張ります。ただし、それだけで任意の更新則に収束定理が付くわけではありません。理論は関数の性質、方向・格子・幅の更新、受理規則などの仮定を組み合わせます。[Torczonの原論文](https://epubs.siam.org/doi/10.1137/S1052623493250780)は、この構造の下でPattern Searchの収束を論じています。

論文の「global convergence」は、通常、任意の出発点から停留性へ向かうという意味で読みます。多峰関数の大域最小値を必ず得る、という意味とは区別します。この教材の1.2倍更新に、別のアルゴリズムの定理をそのまま引用しません。

## 向く条件と診断

低〜中次元で関数値だけを使いたい場合や、近傍評価を並列にできる場合に候補になります。次元が $n$ なら今回の方向集合は $2n$ 点なので、評価が高価なほど一回のpollが重くなります。

- 採用値が止まり幅だけ縮む：雑音と変数尺度を確認します。縮小それ自体を改善と数えません。
- 同じ方向ばかり成功する：単位を揃えたうえで、谷に方向が合っているか考えます。
- 制約違反が残る：単純な罰則の追加で十分とは限りません。[MADS](#/learn/mads)などの制約処理を比較します。
- 初期点で別の谷へ止まる：[Multi-start](#/learn/multi-start)で初期点依存を調べます。

ログには採用値、幅、候補数、成功・非改善poll数、累積評価数、停止理由を残します。カテゴリ変数に連続の「前後左右」をそのまま当てはめるのも避けます。
