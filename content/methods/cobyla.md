COBYLAは、目的関数と制約の値から局所的な線形モデルを作り、そのモデルを使って次に試す点を選ぶ微分不要法です。重要なのは、**モデル上で制約を守る候補でも、実際の制約を破ることがある**という点です。円の内側で一番よい点を探す例から、このずれを読みます。

## 30秒でつかむ

周囲の数点を測り、目的関数と制約を一時的に平面で近似します。その近似を信用する範囲が信頼領域です。候補を本物の関数で評価すると、平面からのずれも分かります。

- 入力するもの：目的関数値、制約値、初期点、探索尺度
- 更新するもの：補間点、線形モデル、信頼領域、候補点
- 確認するもの：目的値と制約違反を別々に記録した結果

各評価点が常に実行可能とは限りません。定義域の外でシミュレータが壊れる問題では、単に「制約式を書いたから外側を評価しない」と考えないでください。

## 一つの円と一本の直線で考える

$$
\min_x f(x)=(x_1-1)^2+(x_2-2)^2
$$

$$
c_1(x)=1-x_1^2-x_2^2\ge0,\qquad
c_2(x)=x_1+x_2-0.5\ge0.
$$

円の内側、かつ直線の上側で、$(1,2)$ に最も近い点を探します。ここでは制約値は非負なら許され、負なら違反です。最大違反を

$$
v(x)=\max\{0,-c_1(x),-c_2(x)\}
$$

と定義すると、目的値と同じ表へ混ぜずに可行性を判断できます。

この問題には別に解析的な答えがあります。原点から $(1,2)$ の方向へ単位円上に進んだ

$$
x^*=\frac{(1,2)}{\sqrt5},\qquad f^*=(\sqrt5-1)^2\approx1.527864045
$$

です。$x_1^*+x_2^*>0.5$ なので直線の条件も満たします。この答えはソルバーの成否を検算するために使います。

## 線形モデルの一手を手で追う

まず仕組みだけを切り出します。以下は説明用に選んだ3補間点から作る小問題で、SciPyの内部ステップを復元したものではありません。中心を $\bar x=(0.2,0.8)$、変位を $s=x-\bar x$ とします。

| 補間点 | $f$ | 円の制約 $c_1$ |
|---|---:|---:|
| $(0.2,0.8)$ | 2.08 | 0.32 |
| $(0.4,0.8)$ | 1.80 | 0.20 |
| $(0.2,1.0)$ | 1.64 | −0.04 |

3点を通る線形モデルは

$$
m_f(s)=2.08-1.4s_1-2.2s_2,\qquad
m_c(s)=0.32-0.6s_1-1.8s_2
$$

です。たとえば第1成分の傾きは $(1.80-2.08)/0.2=-1.4$。勾配を呼び出さず、離れた点の値から傾きを得ています。

半径0.5の中で、この目的モデルを最小化し、線形化した円制約と直線制約を満たす候補を選びます。

$$
\min_s m_f(s)\quad\text{s.t.}\quad m_c(s)\ge0,\quad
\bar x_1+\bar x_2+s_1+s_2\ge0.5,\quad \|s\|_2\le0.5.
$$

ここで直線制約は最適候補に対して余裕があります。線形化した円境界と信頼領域の交点から得られる候補は、約 $(0.699876,0.811153)$ です。

| 候補で調べる量 | モデルによる予測 | 本物の関数での評価 |
|---|---:|---:|
| 目的値 | 1.355638 | 1.503433 |
| 円の制約値 | 0.000000 | −0.147794 |

線形モデルでは境界上ですが、本物の円からは外れています。目的値1.503433は解析的最適値より低く見えても、実行不可能なので解として採用できません。候補の評価には、目的改善だけでなく、近似のずれを知る役目があります。

実際のCOBYLAでは、制約と目的の釣り合い、補間配置の改善、半径の調整なども扱います。上の単純な可行モデル小問題だけを、そのままアルゴリズム全体と見なさないでください。

## SciPyで元の問題を解く

実実行は元記事と同じ初期点 $(0.2,0.4)$ を使います。説明用の中心 $(0.2,0.8)$ とは役割が違います。以下はSciPy 1.17.0、NumPy 2.3.5で実行しました。

```python
import numpy as np
from scipy.optimize import minimize


def objective(x):
    return float((x[0] - 1)**2 + (x[1] - 2)**2)


def inside_disk(x):
    return float(1 - np.dot(x, x))


def above_line(x):
    return float(x[0] + x[1] - 0.5)


result = minimize(
    objective, [0.2, 0.4], method="COBYLA",
    constraints=[
        {"type": "ineq", "fun": inside_disk},
        {"type": "ineq", "fun": above_line},
    ],
    options={"rhobeg": 0.5, "tol": 1e-7,
             "catol": 1e-8, "maxiter": 3000},
)
violation = max(0.0, -inside_disk(result.x), -above_line(result.x))
print(result.success, result.x, result.fun, violation, result.nfev)
# True [0.44718094 0.89444352] 1.5278640433462032
# violation ≈ 3.749e-9, nfev = 64
```

終了理由は信頼領域半径が下限へ達したことです。違反は指定許容差 $10^{-8}$ 以下でした。厳密な可行性ではなく許容差付きなので、目的値が理論上の最適値を約 $1.65\times10^{-9}$ 下回ることと矛盾しません。必要なら出力点を実際の制約式で再評価します。

図の右は目的関数を包んで全64評価を記録したものです。茶色は違反が $10^{-8}$ を超えた評価、緑の線はその許容差内に入った点の最良値です。callbackは呼ばれ方に実装依存性があり、同じ点が続いても全評価や内部の更新を表しているわけではありません。

## 設定をどう読むか

[SciPy 1.17.0の公式文書](https://docs.scipy.org/doc/scipy-1.17.0/reference/optimize.minimize-cobyla.html)では、`rhobeg`は初期の変数変化の尺度、`tol`は信頼領域の大きさの下限、`catol`は制約違反の絶対許容差です。`maxiter`はこの手法では目的関数評価回数の上限です。`tol=1e-7`を座標誤差や目的値誤差の厳密な保証と読まないでください。

同文書はSciPy 1.16.0でPRIMA由来のPython実装へ切り替えたことも明記しています。古い版の評価回数やcallback表を、版を示さず再利用しないことが大切です。

## 向く条件と切替の目安

微分を用意できない低〜中次元の連続問題で、一般不等式制約を局所的に扱いたいときの候補です。変数の単位が大きく違うと一つの半径の意味が崩れ、制約値の単位が違うと違反の比較も難しくなります。変数・制約を意味のある尺度へ揃えます。

- 候補が境界を行き来する：最大違反と可行評価割合を見ます。目的値だけで成功を判定しません。
- 半径だけ縮む：雑音、補間配置、尺度を確認します。
- 等式が厳密に必要：二つの不等式や許容帯への変換が許されるか確認し、等式を直接扱う手法とも比較します。
- 評価が極端に高価：補間のための追加評価を許せるか検討します。
- 初期点依存が大きい：異なる初期点で比較します。局所法の出力は大域最適性の証明ではありません。
