ランダムな大きな移動と局所最適化を交互に行い、一つの初期点では届きにくい複数の谷を渡り歩く確率的大域探索です。

## 30秒でつかむ

谷の底まで下りてから、別の登り口へ移る感覚です。
一つの谷に留まらず、新しい谷の底を探します。

- 見るもの: 各局所求解後の局所最小値、受理判定、これまでの最良値
- 動かすもの: 谷間のランダムな移動と局所ソルバーの初期点
- 前進の判断: より良い谷を発見できたか
- 恐れていること: 同じ谷への再訪、局所求解の過剰費用、一歩の大きさの不適合

有限予算で大域最適性を証明する手法ではありません。複数谷を探す実用的方策として扱います。

## 一手の意味

谷の底へ写す局所求解を $L$、ランダムな摂動を $\xi_k$ とします。
摂動した点から局所求解した候補を、受理判定へ渡します。

$$
y_k=L(x_k+\xi_k),\qquad
x_{k+1}=
\begin{cases}
y_k & \text{受理した場合},\\
x_k & \text{棄却した場合}.
\end{cases}
$$

基本サイクルは次です。

1. 現在点からランダムな摂動で候補初期点を作る
2. 候補から局所ソルバーを実行する
3. 得られた局所最小を、改善量と温度に基づき受理または棄却する
4. これまでの最良値を更新し、予算まで繰り返す

悪化する谷も一定確率で受け入れることで、局所的な閉じ込めを避けます。一歩の大きさと温度を記録します。
局所ソルバーと受理判定の設定も対応付けます。

## 小さな例

Python例と同じ2変数Rastrigin関数を使います。
初期点 $(2.5,-1.5)$、乱数シード 7、移動幅0.5を固定しました。
表は初期の局所求解と、その後の3回の候補です。

| 段階 | 局所求解後の点 | 目的値 | 受理 |
|---|---|---:|---|
| 初期 | $(1.9899,-0.9950)$ | 4.9748 | 採用 |
| 1回目 | $(1.9899,-1.9899)$ | 7.9597 | 棄却 |
| 2回目 | $(-2.9849,-0.9950)$ | 9.9496 | 棄却 |
| 3回目 | $(1.9899,0.0000)$ | 3.9798 | 受理 |

局所求解に成功しても、候補を受理するとは限りません。
3候補目で別の谷へ移り、最良値が改善しました。

## 向く条件・避ける条件

### まず確認すること

| 項目 | 確認内容 |
|---|---|
| 上下限 / 定義域 | ランダムな移動をどこまで許すか |
| 局所ソルバー | 各谷内を安定して解けるか |
| 評価費用 | 多数の局所求解を許容できるか |
| 多峰性 | 初期点ごとに異なる局所解が現れるか |
| 乱数シード | 複数実行で安定性を確認できるか |
| 制約 | ランダムな移動と局所求解で実行可能性をどう保つか |

一評価が高価なら、谷を飛ぶたびに局所求解する費用が重すぎる可能性があります。

### 向く条件・避ける条件

向きやすい条件:

- 低〜中次元の多峰性連続問題
- 局所ソルバーが比較的安価で有効
- 上下限や変数の表現を妥当に設定できる
- 証明より良い候補を複数実行で探したい

避ける条件:

- 高次元かつ一評価が高価
- 離散・カテゴリ変数を無理に連続摂動する
- 一般制約を無視したランダムな移動
- 大域証明や再現可能な単一実行結果が必要

## Python

```python
import numpy as np
from scipy.optimize import basinhopping


def objective(x: np.ndarray) -> float:
    return float(np.sum(x**2 - 10.0 * np.cos(2.0 * np.pi * x) + 10.0))


result = basinhopping(
    objective,
    x0=np.array([2.5, -1.5]),
    niter=50,
    stepsize=0.5,
    seed=7,
    minimizer_kwargs={"method": "BFGS"},
)
print(result.x, result.fun, result.message)
```

比較では`niter`だけでなく、局所ソルバーが使った目的関数 / 勾配評価も合計します。

## 診断値

- これまでの最良値と局所最小の分布
- 受理 / 棄却谷数
- 同じ谷への再訪率
- 局所求解ごとの評価数
- 一歩の大きさと温度
- 乱数シード間の成功率

## 失敗・切替の兆候

### うまくいったサインと切替サイン

- 同じ谷ばかり再訪 → 一歩の大きさや候補の作り方を調整
- 局所求解が予算の大半を消費 → 評価費用の少ない局所法か別大域探索へ
- 受理率がほぼ0または1 → 温度と尺度を見直す
- 高価評価で試行数が不足 → Bayesian Optimizationへ
- 低次元有界で決定論的探索が欲しい → DIRECTやSHGOへ

### コラム: 地形の変換

Basin Hoppingは、各点をそこから到達する局所最小へ写した「谷の地形」を探索していると考えられます。元の関数を直接ランダムな歩行するのとは異なります。
